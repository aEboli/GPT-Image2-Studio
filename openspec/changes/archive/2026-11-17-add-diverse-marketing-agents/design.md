## 决策

1. 随机单位是每套营销图片。一个 Agent 统筹该套各张图片；同套重试、局部修复、补图不切换 Agent。批量的 `count × copiesPerScheme` 套均独立规划。
2. 服务端维护 64 人随机牌池。抽取时优先避开近期流派，牌池耗尽才重新洗牌。相同输入指纹及非空变化种子复用有界保留的人设分配，防止请求重试变成新创作。新套使用独立种子。
3. 人设具有具体可执行的视觉维度。文本模型必须结合当前产品事实重新设计，品类专长是观察角度，不是强行移植道具或新功能。场景、构图、背景色、照明、排版共同区分作品；产品本身颜色和结构不随人设变化。
4. 把当前人设及近期设计摘要传入初次规划和局部修复。实际生图提示词追加本套视觉执行指令；纯白商品图和纯白渲染采用适配指令，用户锁定项原文保留，禁字图片不增加画布文字。
5. 批量内每套使用独立变化种子和冻结结果。暂停时保存当前未入队结果；入队后清除它，下一套重新规划。现有双规划并发、停止和已入队任务语义保留。
6. 计划保存 Agent ID、名字、流派、具体视觉规则及分配标识。旧冻结计划不自动添加人设；新契约升级但继续按原版本校验旧指纹。

## 验证

- 验证 64 人完整性、唯一性、一轮不重复、相邻流派回避、跨轮边界及稳定重试分配。
- 验证 `1×20` 与 `3×2` 每套独立规划，瞬时重试不换种子，暂停继续不重复入队、未入队结果复用。
- 模拟文本模型检查人设进出规划、局部修复与实际图片请求，以及冻结/保存兼容。
- 运行营销及队列回归、全量测试、浏览器公共库同步检查、语法检查、OpenSpec 严格校验和中文编码检查。
- 代码与模拟上游可验证人设及指令差异；真实视觉多样性仍须实际模型出图后人工比较，不以模拟回归冒充实测。
