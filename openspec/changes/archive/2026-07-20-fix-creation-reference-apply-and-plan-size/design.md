## Context

参考图分析响应需要经过类目匹配、商品名建议、角色覆盖和计划草稿刷新多个同步/异步步骤。任何步骤触发的重绘都不应让应用状态短暂回退为“未应用”。识别结果只是默认建议，但用途下拉框必须继续允许用户纠正模型判断。

冻结计划包含每个轮播、SKU 和信息图重构项的最终提示词。平台策略和参考覆盖会显著增加提示词长度，因此单一固定的小字节阈值不能代表计划项数量上限；仍需保留绝对上限，避免异常请求无限膨胀。

## Decisions

1. `applyCreationReferenceAnalysisRecommendations` 先完成所有内存字段写入，再将 `applied` 和折叠状态设为最终值，最后只做一次可见渲染；商品名输入事件触发的重绘也必须看到最终应用状态。
2. 参考图卡片始终渲染用途 `select`。自动识别只提供初始值，不写入 `roleLocked`；手动改动仍会使旧识别标记为过期，但当前角色 payload 立即生效。
3. 冻结计划快照绝对上限调整为 4 MiB，计划项数量上限仍为 64，保留 JSON、必填字段和平台约束校验。该范围可容纳现有 33 张计划，同时不会取消服务端边界。
4. 结果卡继续保存 `coverageSources` 和 `coverageSummary` 供记录/大图详情使用，但活动结果卡不直接挂载长文本节点。

## Verification

- 浏览器静态回归断言自动应用、可编辑用途下拉框和卡片不渲染长覆盖文本。
- 规划器回归构造 33 项且超过旧 750 KB 的冻结计划，确认提交解析通过；超过 4 MiB 仍被拒绝。
- 运行 Creation 定向测试、完整 `npm test`、public 镜像检查和 OpenSpec 严格校验。
