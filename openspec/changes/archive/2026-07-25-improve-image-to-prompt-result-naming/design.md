## Context

普通图片反推现在返回固定的 `subject`、`framing`、`scene`、`visual`、`avoid` 五组 JSON。为继续避免信息重复，不能为了 UI 名称重新在 JSON 中增加 `title`，但前端已有足够信息生成简短、可辨认的名称。

## Goals / Non-Goals

**Goals:**

- 让同一条结果在历史记录、提示词模板列表和模板名称输入框中显示一致的可读短标题。
- 用确定性规则组合主体、动作或道具、时间天气和环境信息。
- 兼容旧 `json.title`、旧自动模板和缺少结构化内容的记录。

**Non-Goals:**

- 不改变五组反推 JSON 的字段结构。
- 不发起额外模型请求，也不从文件名或缺失字段虚构画面信息。
- 不改写用户手动设置的非文件名模板名称。

## Decisions

### 1. 使用纯前端确定性名称生成器

名称生成器读取 `subject`、`scene`、`visual` 和 `framing.foreground_frame`，从明确文本中选择最多一个时间、一个天气、一个主要动作或道具、主体类型以及一至两个环境要素。组合结果去重并限制为 40 个 Unicode 字符。

该逻辑放在独立共享模块中，使浏览器集成与 Node 单元测试使用同一实现。替代方案是让模型额外返回标题，但会破坏已确认的五组结构并重新引入重复字段。

### 2. 名称采用稳定优先级

显示名称依次使用旧 `json.title`、五组 JSON 组合短标题、去图片扩展名的文件主名和固定兜底 `图片反推 JSON`。旧标题同样应用长度限制，但不重新解释或改写其语义。

### 3. 只迁移可识别的自动模板名称

读取模板时，仅当 ID 以 `prompt-agent-` 开头且当前名称以常见图片扩展名结尾，才使用模板中的 JSON 重新生成名称。用户自定义的非文件名名称保持原样；无法提取结构化内容时也只移除图片扩展名。

## Risks / Trade-offs

- [关键词覆盖不完整] -> 始终保留主体类型和无后缀文件主名回退，后续可按真实样例扩充有限词表。
- [同一词在多个字段出现] -> 组合前按包含关系去重，环境只保留少量代表性要素。
- [历史模板无法判断是否手动修改] -> 仅迁移自动模板 ID 下仍明显带图片扩展名的名称，避免扩大改写范围。

## Migration Plan

1. 增加组合名称、标题优先、无后缀回退和自动模板迁移测试。
2. 接入历史记录、自动保存模板与模板读取归一化。
3. 运行项目测试、同步检查与 OpenSpec 严格验证。
4. 在现有 3602 页面刷新并检查真实历史记录与模板名称。
