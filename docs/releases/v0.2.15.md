# GPT-Image2-Studio v0.2.15

`v0.2.15` 将主应用版本从 `0.2.14` 更新到 `0.2.15`。

## 更新内容

### 路由模式的生图工具模型可选

- 官方 `image_generation` 工具的 `model` 字段现在接受三个当代模型：`gpt-image-2`、`gpt-image-2.5-sunburst`（精修更准、出图更慢）、`gpt-image-2.5-flare`（速度更快）。注意没有裸的 `gpt-image-2.5`，2.5 只有 sunburst 和 flare 两个变体。
- 此前路由模式的工具模型写死在 `lib/image-route-config.mjs` 里，参数区也固定渲染 `gpt-image-2`，界面上完全改不了。管道其实早就通了——`createResponsesRequestBody` 会把传入的 `imageModel` 写进 `tools[].model`，只是路由 A 永远只喂给它同一个常量。
- 配置区「Responses 模型」下方新增「生图工具模型」下拉框，提示词页参数区的「工具模型」跟随所选模型即时显示。
- 该项只提供下拉选项，不接受自定义填写：取值集合由官方文档给定，自由文本只会把上游必然拒绝的模型名送出去。旧配置、环境变量、被改过的 DOM 和伪造的请求字段一律在归一化时收敛为 `gpt-image-2`。
- 新增 `IMAGE_TOOL_MODEL` / `IMAGE_STUDIO_IMAGE_TOOL_MODEL` 环境变量。
- 图片编辑（含局部蒙版的 merge 与 sequential 两条策略）复用同一个 `imageModel`，因此随该配置一起改变。
- 清掉沿途写死 `gpt-image-2` 的记录点，它们此前会谎报一个没实际使用的模型：`public/app.js` 四处乐观展示记录、快速融图与图片编辑两个视图，以及 PPT 清单。`formatImageModelLabel` 补上两个 2.5 标签，否则 `gpt-image-2` 显示为「GPT Image 2.0」而 2.5 回落成裸 ID。

### 出图质量档可选，并按模型能力收敛

- GPT Image 2.5 把质量上限从 `high` 提到 `xhigh` 和 `max`，但仓库里质量既没有界面控件也没有归一化：服务端 9 处和客户端 6 处各自写 `config.defaults?.quality || "high"`，用户无处可改。
- 参数区把写死的「质量 High」换成下拉：`auto`、`low`、`medium`、`high`，以及只有 2.5 变体才提供的 `xhigh` 和 `max`。选项集合随工具模型变化，切换模型时重建。
- 质量改为随 `formData` 逐请求提交——此前 `buildGenerationFormData` 根本没发这个字段，服务端只能读配置默认值。服务端 9 处解析点全部按当次模型收敛；PPT 单页与补图条目各按自己的模型收敛，因为补图条目自带上游目标，模型可能与本次运行不同。
- 选着 `xhigh` / `max` 再把工具模型切回 `gpt-image-2` 时，质量降为 `high`，而不是发一个上游必然拒绝的请求。`mergeConfig` 在拿到归一化后的工具模型之后才收敛 `defaults.quality`，所以「只切模型、不动质量」也会把已保存的 `max` 降下来。
- 默认仍是 `high`（官方 API 默认为 `auto`），未改配置的用户出图行为不变。新增 `IMAGE_QUALITY` / `IMAGE_STUDIO_IMAGE_QUALITY` 环境变量。
- 关于「任意分辨率」：查证后不做。自定义 `WIDTHxHEIGHT` 在 `gpt-image-2` 上本来就支持，不是 2.5 的新能力，且现有 15 个比例的档位逐个验算都已满足官方约束。

### 浏览器本地保留可复用的 API 清单

- 配置区四个通道的接口地址和 API Key 此前都是单值输入框，只能存一份，「换一个 API」等于「覆盖掉上一个」。真正麻烦的不是找不到某把 Key，而是**地址和 Key 必须成对手动对齐**：填了新地址却忘了换 Key，请求会拿旧 Key 打新上游，报错通常只是 401 或 402，看不出是配错了对；而上一个 Key 保存时已被覆盖，界面上只剩掩码，无法找回。
- 四个通道（路由模式、直连生图、直连文本/视觉、模型协议通道）共用一份清单，因为用户常在多个通道复用同一个中转站。上限 20 条，超出丢弃最旧的。
- 下拉挂在**接口地址**上，不挂在 Key 上。选中一条即把该通道的接口地址、协议后缀和配套 Key 一起填好——Key 跟着 API 走，不单独挑。模型不动，仍需点「保存」生效。
- 一条记录的身份是「接口地址 + Key」：同一家同一把钥匙不因后缀不同占两条，同一家的第二把钥匙是另一条 API。缺地址或缺 Key 的组合不入清单，因为它无法整套切回来。
- 协议后缀只在当前通道确实提供该选项时才跟着换：路由模式存的 `responses` 不会把直连生图的 `images/generations` 顶成一个它不支持的值。
- 列表每行两行：上行接口地址，下行「后缀 · Key 掩码」，同一家的两把 Key 才分得清。每行带删除按钮，删除只从清单移除，不影响当前已保存的配置。
- 清单只存在浏览器本地 `localStorage`（键 `image-studio-api-endpoint-book-v1`，独立于浏览器私有配置）。`.local/config.json`、`.env` 与 `/api/config` 一个字节都不加，请求载荷与 FormData 不带该清单，桌面端与其他浏览器不共享。
- 明文 Key 不进 DOM：列表按索引回填，渲染只输出地址与掩码。掩码是既有的安全设计，本次不放开。
- Key 输入框留空仍表示沿用已保存 Key，保存后仍清空输入框并以掩码显示当前生效 Key。清单为空、损坏或本地存储不可用时按空清单处理，不影响配置读取与保存。

### 重调中国传统色配色

- 夜场从钢蓝 `#0f1423`（L\*6.5）抬到暗蓝 `#101f30`（L\*11.3），面层做成暗蓝→鸽蓝→青灰三级台阶。近黑底配亮字的晕光是「刺眼」的主因。
- 昼纸不再用近纯白：银白 `#f1f0ed` 作场、汉白玉 `#f8f4ed` 作面、雪白作起层。旧值场 L\*96.5 与面 L\*99.5 的落差只有 1.08:1，卡片等于没有边界。
- 五族点缀统一降彩度：石绿 C\*32→闪蓝 C\*16、蛙绿 C\*46→松霜绿 C\*20、淡灰绿 C\*35→尘灰 C\*26，填色对场的对比从 6.1–8.7:1 收到 6.1–6.8:1。昼色五支实测本来就够，未动。
- 描边补到可见：夜 `--border-strong` 对场从 1.59:1 提到 3.78:1，昼从 1.98:1 提到 3.42:1，控件轮廓一律过 WCAG UI 部件 3:1 下限；分隔线只作装饰。
- 修 `.filmstrip-selected-marker` 的浅底浅字：`#ffffff` 压在 `var(--accent)` 上对新点缀只有 1.8:1，改走 `--accent-fg`。
- `--seal` 苋菜红在夜面层只有 1.81:1，换朱红；`--muted` 换镍灰以在青灰起层上仍有 4.97:1。整表 34 个字面 hex 全部落在 526 色库内，唯一例外是采集器选中态的橙 `#ff8a1f`（跨主题导入规范，注释与测试都钉住，故保留）。

### 商品图采集扩展 1.1.33

- 采集器、采集窗和悬浮入口改为随页面一起载入并停留在同一隔离世界。点击入口时直接在当前页面打开已载入的采集窗，读取商品页也直接调用页面内采集器，不再等待浏览器后台响应，因此不会再出现后台通信导致的读取超时。
- 载入前只注册控制器，不创建采集窗 DOM、不读取图片、不联系后台。
- 插件更新后页面里只剩旧脚本时，入口会自动改用后台注入并重试三次；仍然失败才提示刷新页面。

## 升级说明

- 主应用每次更新仅递增一个补丁版本，即 `+0.0.1`。
- 既有配置、生成记录和图片资产不需要迁移。
- 生图工具模型默认仍是 `gpt-image-2`，质量默认仍是 `high`，未改配置的用户请求体与生成记录均不变。路由 B 的「生图模型」自由文本框、路由 C 的图像模型输入、模型列表获取、连接测试与尺寸档位不变。
- 套图、写真、文章插图与 PPT 没有独立质量控件，继续读（现已归一化的）配置默认值。
- API 复用清单从空开始，首次加载时用已保存的浏览器私有配置补种一条；此前保存过又被覆盖的 Key 无法追溯找回。
- 商品图采集扩展使用独立版本线，本次随主应用一并更新到 `1.1.33`。已载入旧版脚本的商品页需要刷新一次。
