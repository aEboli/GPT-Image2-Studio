## Context

瀑布画廊把当前预览记录保存在 `galleryCurrentFilename`，把批量删除勾选集合保存在 `galleryCheckedFilenames`。`createGalleryTile()` 目前为每张卡片无条件创建左上角复选框，`renderGalleryView()` 则根据当前筛选下的勾选数量启用“删除选中”。这导致普通浏览状态也永久覆盖图片左上角。

本次只改变画廊多选控件的显隐和可操作边界，不改变图片数据、筛选、分页、当前预览或删除 API。

## Goals / Non-Goals

**Goals:**

- 默认让画廊图片完整显示，不渲染左上角勾选遮罩。
- 通过标题操作区的显式模式按钮开启或关闭图片勾选。
- 让按钮具备原生可聚焦语义、`aria-pressed` 状态和移动端触摸尺寸。
- 保留已勾选集合，使短暂退出选择模式不会丢失用户操作。
- 仅在选择模式开启时允许启动“删除选中”。

**Non-Goals:**

- 不增加全选、反选、拖拽框选或按住修饰键选择。
- 不持久化选择模式或勾选集合到浏览器存储。
- 不改变“删除当前”、图片灯箱、筛选、分页或服务端删除协议。
- 不把其他资产记录页改为同一种模式。

## Decisions

1. **选择模式使用页面会话状态。** 在现有 `state` 中增加默认 `false` 的 `gallerySelectionMode`。刷新页面会回到无遮挡浏览状态，符合该模式只服务当前操作的性质。
2. **关闭模式时不创建复选框节点。** `createGalleryTile()` 仅在模式开启时创建 `label` 和 `input`，而不是通过 CSS 隐藏已渲染控件。这样关闭状态没有可聚焦或可操作的隐藏控件，图片也不会被透明命中区域遮挡。
3. **保留已勾选集合。** 模式关闭只隐藏控件，不清空 `galleryCheckedFilenames`；重新开启时恢复勾选状态。该选择集合仍独立于 `galleryCurrentFilename`。
4. **批量删除受模式门控。** “删除选中”在模式关闭时保持禁用，即使内存中仍有勾选项；开启后才根据当前可见勾选数量启用。按钮文案继续显示已选数量，方便用户确认保留状态。
5. **模式按钮使用现有资产头部控件语言。** 按钮位于“前往提示词生图”与“刷新”之间，使用 `aria-pressed` 和轻量激活样式；手机布局继承现有 44px 最小触摸高度，不新增动画。

## Risks / Trade-offs

- [关闭后看不到仍保留的勾选项] → 模式按钮在存在保留选择时显示数量，重新开启即可查看和修改。
- [筛选后保留隐藏选择造成误解] → 删除入口继续只统计并提交当前完整筛选集合中的显式勾选项，沿用既有删除控制器边界。
- [重新渲染导致滚动位置变化] → 只替换当前画廊卡片内容，沿用现有渲染路径和自定义滚动同步；浏览器验收复核桌面和窄屏滚动。
- [新增状态增加应用壳体体积] → 不引入新模块或抽象，仅在现有画廊状态、渲染和事件绑定位置增加最小逻辑。
