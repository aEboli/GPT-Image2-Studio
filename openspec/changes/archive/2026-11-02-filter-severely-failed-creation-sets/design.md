# Context

套图记录已经通过 `getCreationProgressSummary` 从清单条目推导 `total`、`completed` 和 `failed`，并通过一个完整筛选集合驱动列表、当前详情和“删除筛选结果”。现有筛选条件由关键词和时间构成；清空筛选、列表分页、选择和删除目标都依赖同一筛选状态。

Creation 清单可在生成过程中包含已完成和失败的条目，因此仅检查 `failed > 0` 会把仍在生成的套图混入结果。筛选必须等所有纳入进度统计的条目都已结束。

# Decisions

- 定义严重失败为：`total >= 10`、`failed > 0`、`completed < 10`，并且 `completed + failed >= total`。`total` 使用现有进度摘要的统计口径；被跳过或证据拦截的条目不计入待生成项。
- 以“成功少于 10 张”为判断重点。计划 20 张且成功 17 或 18 张的记录不会匹配；成功 4 张的记录会匹配；成功正好 10 张的记录不会匹配。
- 严重失败与关键词和时间条件按 AND 组合。筛选结果只计算一次，并继续作为列表、详情回退、选择范围以及批量删除的唯一数据来源。
- 把严重失败条件纳入活动筛选判断、筛选摘要、筛选签名和清空筛选操作，避免界面状态、确认文案与删除目标不一致。
- 复用现有筛选删除和路径安全实现，不增加新的删除接口。删除前仍需确认，确认中显示匹配套数；每套仍删除其专属图片目录、JSON 元数据目录和清单。

# Validation

- 为筛选规则增加纯函数测试，覆盖进行中记录、少于 10 张的计划、成功数边界、失败数和缺失数据。
- 验证关键词及时间组合、清空筛选和筛选删除目标均采用完整匹配集合。
- 运行相关套图筛选、删除与界面测试，公共浏览器库同步检查、OpenSpec 严格校验和 `git diff --check`。
