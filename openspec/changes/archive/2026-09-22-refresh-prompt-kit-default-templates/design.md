## Context

Prompt Kit 的默认模板由 `public/app.js` 中的 `SURPRISE_PROMPTS` 定义，再映射为 `DEFAULT_PROMPT_TEMPLATES`。模板和用户编辑内容共同保存在 `image-studio-prompt-templates-v2`。读取逻辑原本只在存储键缺失或解析失败时使用默认常量；只更新常量会让已有用户继续看到旧模板。

本次需求只改变提示词模式的内置起始内容，但“旧默认不保留”要求读取已有本地数据时主动替换旧内置项。迁移必须避免连带删除用户自己创建的模板和图片反推历史模板。

## Goals

- 默认入口提供十个高频、可直接使用的图像工作流模板。
- 让新旧版本的内置模板有稳定、可识别的 ID 边界。
- 升级现有浏览器存储时移除旧内置，保留用户模板与 Prompt Agent 模板，并沿用既有归一化后的内容。
- 对空列表、损坏存储和存储写入失败保持现有的容错语义。

## Non-Goals

- 不引入新的共享模块或服务端存储。
- 不改变模板面板的排序、编辑、保存、删除和应用操作。
- 不把界面比例、分辨率或生成参数硬编码进默认模板；这些仍由现有控件控制。

## Decisions

### 1. 保留存储键，版本化内置 ID

继续使用 `image-studio-prompt-templates-v2`，以便保留用户现有模板。新内置模板使用 `default-template-v2-${index + 1}`；旧内置模板只匹配精确的 `default-template-数字` 形式。这样不会把普通的 `template-*` 或 `prompt-agent-*` 条目误判为旧默认。

### 2. 只在发现旧内置时执行整套替换

`readPromptTemplates()` 先按现有规则归一化存储数组，再调用迁移函数。若数组中至少有一个旧内置 ID，迁移函数会：

1. 保留所有非旧内置、非当前 v2 内置的条目，并保持它们原有相对顺序。
2. 移除旧内置和重复的当前 v2 内置，避免旧新两套同时显示或产生重复。
3. 将当前十个 `DEFAULT_PROMPT_TEMPLATES` 的副本追加到列表末尾。
4. 尝试把迁移后的完整数组写回同一个存储键。

这意味着旧内置的改名、编辑或删除不会被逐项迁移；它们属于用户明确要求替换的旧默认集合。用户自己创建的条目不使用旧内置 ID，因此不受影响。

### 3. 保持首次加载、空列表和异常路径

- 存储键不存在时，直接返回当前十个默认模板的副本。
- 存储值是合法空数组时，不补回默认模板，以保留用户主动清空的选择。
- JSON 解析失败时沿用既有回退，返回当前默认模板。
- 迁移后的 `setItem` 失败（例如配额或隐私模式限制）不抛出；当前会话继续使用内存中的迁移列表，后续启动仍会再次尝试迁移。

### 4. 默认内容边界

默认提示词按“主体、场景、构图、光线、细节、用途”组织。证件照模板采用用户指定的灰白渐变摄影背景、柔和自然光、真实肤色、居中中景和职业肖像气质，但不声称满足任何地区的官方证件照法规。商品模板强调保持输入主体的外形、颜色、材质和已提供信息；海报模板预留后期排版空间并避免依赖模型生成长段文字。每条内容保持在现有模板编辑器的 3000 字符限制内。

## Risks and Trade-offs

- 旧内置模板若被用户编辑过，迁移仍会移除该条目；这是“旧默认不做保留”的直接结果，用户自定义条目则继续保留。
- 写入失败时迁移只在当前会话生效，无法保证下一次启动前完成持久化；不让存储异常阻断工作台启动比强制清空或抛错更安全。
- 默认模板内容是前端静态文案，不会随服务端或其他客户端自动同步。
