## Why

提示词模式的中途预览目前是"用完即丢"的单张覆盖，带来两个用户可见问题。

一是图片会无声无息换掉。`lib/responses-workflow.mjs` 在无法确认原任务结果时会自动重试一次，重新 POST 一次全新生成。这是一次全新的图像，但它的 `partial_image` 事件仍然覆盖同一个 `previewUrl`（`public/app.js` 提示词流处理），用户看到的是"刚才那张图突然变成了另一张"，且界面没有任何提示说明这是新的尝试。

二是失败时已经拿到的图会整张消失。error 事件、流中断未收到终止事件、以及异常三条路径都调用 `removeJob`，把整个任务连同 `previewUrl` 从内存状态里删除；失败活动记录只写文字，不带缩略图。服务端 `consumeResponsesSse` 虽然把中途预览累积在 `partialImages` 中返回，但没有任何调用方引用该字段，因此中途预览只存在于浏览器内存的一瞬间。

用户的诉求是：新的尝试不要挤掉已经拿到的图，同一个预览位置能同时呈现多张，并且失败尝试留下的中途预览可以另存为正式图片。

## What Changes

- 提示词模式为每个生成任务维护一个"尝试卡组"，把该任务的每一次上游尝试记录为独立一张卡，新尝试追加而不覆盖已有卡。
- 胶片条中该任务仍只占一个槽位；卡组含两张以上卡时槽位显示张数角标，点击角标在槽位内原地展开各尝试缩略图，点击某张切换主预览。
- 任务失败但已收到过中途预览时，保留最后一张中途预览作为该尝试的卡，并标记为未完成，不再随任务一起从界面消失。
- 未完成尝试的卡提供"另存为正式图片"操作，通过新增本地服务接口把该预览写入输出目录并加入画廊索引，落盘元数据标记其来源为未完成预览。
- 卡组仅存在于当前页面会话，不持久化；刷新后恢复为仅展示画廊历史。

## Capabilities

### New Capabilities

- `prompt-attempt-preview-persistence`: 新增把提示词模式未完成尝试预览另存为正式图片的本地服务能力，含落盘、画廊索引、来源标记与安全校验。

### Modified Capabilities

- `creation-mode`: 修改提示词模式预览与胶片条行为，定义尝试卡组的追加、原地展开、失败保留与会话生命周期规则。

## Impact

- 前端状态与渲染：`public/app.js`、`public/styles.css`、`public/index.html`（静态资源版本参数）。
- 服务端：`server.mjs` 新增落盘路由；`lib/gallery-store.mjs` 元数据白名单新增来源字段。
- 共享模块同步：`lib/` 与 `public/lib/` 经 `scripts/sync-public-lib.mjs` 保持一致。
- 回归测试：胶片条与预览布局测试、画廊落盘测试、本地服务安全测试。
- 不改变生成请求构造、上游重试次数、任务持久化、其他生成模式（Creation、Portrait、PPT、文章插图）或既有画廊 API 形状。
