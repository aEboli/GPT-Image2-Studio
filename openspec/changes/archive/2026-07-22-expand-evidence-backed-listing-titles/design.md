## Context

当前标题公式已经固定为“平台要求顺序/数量 + 商品核心词 + 证据卖点 + 直接支持的痛点解决 + 相关搜索词”，但最后一项没有数量、优先级或停止条件。真实四轮折叠手拉车记录因此只生成了商品身份和后备箱收纳价值，没有继续使用四轮、交叉折叠车架、伸缩拉杆、黑色/粉色选项等已支持事实。

## Goals / Non-Goals

**Goals:**

- 让标题在合规和可读的前提下包含更充分的搜索与决策信息。
- 明确硬长度上限、建议长度和无硬上限平台之间的处理顺序。
- 保持现有标题证据边界和非标题字段限制。

**Non-Goals:**

- 修改平台政策数据或人为放大任何平台硬上限。
- 在标题中加入尺寸、重量、材质、承重、刹车、静音、耐磨或其他未核实声明。
- 增加模型请求次数、结果审核流程或新 Listing 字段。

## Decisions

### 1. 用“必需核心 + 条件追加”替代笼统的剩余搜索词

标题先保留商品身份、一个最强证据卖点及其直接解决的痛点。完成核心后，从证据中选择 2–4 个不同概念的搜索或购买决策属性，例如结构、可见组件、颜色/变体、数量或包装事实。

追加数量是条件要求：仅在证据存在且平台硬限制允许时执行。标题不得为了凑数重复核心词、改写同一个属性或加入宽泛形容词。

### 2. 硬限制绝对优先，建议长度作为软目标

存在 `hardMaxChars` 或字节硬上限时，标题必须完全遵守。`recommendedMinChars` 和 `recommendedMaxChars` 用于控制信息密度与可读性，但不视为验证硬门禁；没有平台硬上限时，可为补齐证据属性适度超过建议上限，同时仍受通用字段上限和自然语言要求约束。

### 3. 不增加新的结果门禁

本次修改只增强生成指令和回归断言。现有高风险声明、禁尺寸、品牌清理、平台硬长度裁剪和非标题功能词门禁继续负责安全边界。这样避免因属性同义表达差异误判正常标题并触发确定性回退。

### 4. 回退先识别中文商品品类

真实请求遇到 HTTP 429 时，V1 会按现有单次请求规则进入确定性回退。若中文商品名没有命中已知品类映射，旧逻辑会继续扫描 SKU 说明并可能把 `1`、`300KG` 等 ASCII 片段误作商品身份。本次只增加折叠手拉车的明确品类映射，让回退以 `Folding Wagon Cart` 为身份；不把 `300KG` 转成事实，也不放宽高风险声明规则。

## Risks / Trade-offs

- [标题变得生硬或堆词] -> 要求每个追加属性回答不同购买问题，按决策价值排序并保持一个可扫读标题。
- [平台字数不足] -> 先保留商品身份和价值关系，再在硬上限内按优先级追加；不强制凑足 2 个属性。
- [建议长度与完整度冲突] -> 建议范围保持软目标，硬限制保持绝对边界。
- [模型加入无证据属性] -> 明确限定可追溯来源，现有高风险声明检测继续回退不安全结果。
- [上游限流触发错误回退身份] -> 已知中文折叠手拉车先映射为稳定英文品类，不再从数字声明推断商品名。

## Migration Plan

1. 增加失败测试，固定追加属性、长度优先级、去重和非标题不变规则。
2. 最小修改平台 V1 标题提示词。
3. 运行 Listing 定向测试、完整测试、Pages 构建和 OpenSpec 严格校验。
4. 重启 `3600`，备份并重新生成目标手拉车记录，确认标题和持久化结果。
