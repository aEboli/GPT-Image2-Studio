## Why

用户希望项目接入 IMAGE2.6，并完整支持模型可以使用的能力。2026-11-05 读取的 OpenAI 官方 SDK 源码已经列出 `gpt-image-2.6-sunburst`、`gpt-image-2.6-flare`，包括 Images API 与 Responses `image_generation` 工具。源码还定义了独立的图像规划复杂度、SVG 输出及其作者模型配置、GIF 输出及其帧参数，以及编辑标注输入。具体证据、已知限制与待验证项目见 `sources.md`。

现有项目只补模型名无法达成目标：路由 A 的白名单仅到 2.5；质量扩展判断只认识两个 2.5 ID；格式归一化仅允许 PNG/JPG；最终图片校验只接受 PNG/JPEG；画廊扫描排除 GIF/SVG；请求没有复杂度、SVG、GIF 或 markup 参数；直连解析只取第一张结果。套图等模块的队列、补图和历史快照还需要完整保存新参数。

用户于 2026-11-05 回复“行”确认实施。当前已完成接口能力接入、界面、资产链路和本地验证，主应用版本为 v0.2.127。真实账户验收因开发配置没有可用 API Key 而未执行；不能把本地模拟结果视为已验证账户权限或模型效果。实际证据和外部待验收项见 verification.md。

## What Changes

- 在现有路由 A 与路由 B 中识别两个 2.6 ID，继续保留旧模型和明确的用户配置。新旧默认值不在本次调研中自动替换。
- 增加一份小型共享能力描述，按模型、端点、生成/编辑操作与输出格式约束参数。它只服务现有生图链路，不引入新的通用提供方框架。
- 区分 `reasoning.effort`（外层文本模型）、`complexity`（图像规划，low/medium/high）和 `svg.reasoning.effort`（SVG 作者模型）。未设置复杂度时省略字段，保留上游默认/继承语义。
- 接通 PNG、JPEG、WebP、GIF、SVG 的可用输出路径；串通请求、结果解码、文件类型识别、MIME、保存、缩略图、画廊、灯箱、下载与元数据。功能开放以所选模型和账户实际权限为准。
- 接通 2.6 的 xhigh/max 质量档、JPEG/WebP 压缩参数、合法的自动质量/背景/尺寸选项和静态图片预览数。任意尺寸边界须补充模型级证据，不直接复制 2.5 的上限。
- 在现有编辑页提供标注引导，与局部 mask 模式分开。markup 与 mask 互斥，校验透明 PNG、方向归一化后的尺寸和首张源图绑定。
- 为 GIF 提供帧数、每帧时长、播放预览与原始文件下载；为 SVG 提供矢量预览、原始文件下载，以及有权限时的作者模型/推理配置。遵循当前指南，编辑入口不开放 GIF/SVG；GIF 帧数文档冲突在实施前核实。
- 贯通配置、各生成面板、请求快照、队列、任务恢复、重试/补图和参数检查器。单张图片槽位仍保持一个交付物；普通生图可选 Images API 原生多图并完整保存所有结果。
- 补齐模型级输入数量验证：接口支持的最多 16 张不能被当前全局 15 张常量悄悄截断；编辑页原有单源图交互继续保留，多参考图走现有支持多图的入口。
- 同步 `public/lib` 镜像，补充自动化、真实浏览器/桌面验证、两份 README 和发布说明，完成后按项目发布策略升版。

## Capabilities

### New Capabilities

- `gpt-image-26-support`: 两个模型的能力约束、复杂度、输出组合、资产保存、GIF/SVG、原生多图和端到端记录一致性。

### Modified Capabilities

- `runtime-configuration`: 新参数往返、共享能力校验、明确模型选择与实际模型记录一致。
- `image-edit-mode`: 标注引导编辑，保持既有单源图模式和局部蒙版流程。

## Impact

预计涉及模型/配置模块、`lib/responses-workflow.mjs`、`lib/output-format-options.mjs`、`lib/generated-image-validation.mjs`、`lib/gallery-store.mjs`、缩略图与视图模块、`server.mjs`、`public/app.js`、`public/index.html`、CLI、必要测试和共享镜像。具体最小写入范围见 `design.md`。

对套图、写真、文章和 PPT，完整支持指正确使用 2.6 及其适用的参数，不代表把只支持静态交付的槽位自动改成动画/矢量。若下游格式不兼容，必须在提交前提示，或让用户明确选择导出副本的转换，保留原始资产。

## Success Criteria

1. 两个 2.6 模型在路由 A/B 的实际出站请求、配置和历史中一致；路由 A 不发送 `tools[].model` 时不宣称已强制使用 2.6。
2. 新参数从控件到请求、保存、重试/补图均可复核；复杂度与三种推理/质量控制不混淆。
3. 五类输出均有实际字节校验、正确扩展名/MIME、预览、下载与重启后历史；多图响应不丢结果。
4. 无效组合在出站前被拒绝，拒绝/权限错误不通过改模型、改格式或重复 POST 掩盖。
5. 官方未明确或账户未开通的能力标记为待验证/不可用，不能仅以 mock 测试宣称支持。
6. 通过定向测试、共享镜像检查、回归检查、真实界面与有权限的真实接口验证，再严格校验和归档。
