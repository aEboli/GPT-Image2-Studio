## Context

套图记录由浏览器一次读取全部 manifest，保存在 `state.creation.sets`。当前 `filterCreationRecordSets()` 只处理关键词，详情选择、计数和按筛选删除都依赖该函数；左侧列表最后再 `.slice(0, 60)` 限制渲染数量。瀑布画廊已经使用“全部、今天、近 7 天、更早”和精确日期的本地时间语义，但其 helper 同时包含画廊专用的尺寸、参考图和排序逻辑，不适合直接承载套图记录筛选。

本次工作发生在包含其他 Listing 和 Creation Mode 改动的脏工作树中，必须把修改限制在套图记录筛选、删除目标联动、对应测试和 OpenSpec 工件。

## Goals / Non-Goals

**Goals:**

- 按 `createdAt` 的浏览器本地自然日筛选全部、今天、近 7 天、更早或某个精确日期。
- 关键词和时间条件按 AND 关系组合，计数、列表、详情和批量操作使用同一完整结果集合。
- 保持最多渲染 60 条只是展示优化，不改变筛选计数或删除目标。
- 只有关键词或时间条件至少一个为显式非默认值时，才允许删除筛选结果。
- 让日期计算和筛选删除安全条件可以通过纯函数单元测试固定。

**Non-Goals:**

- 增加服务端查询参数、分页、数据库索引或改变 manifest 格式。
- 按更新时间、生成完成时间或 Listing 更新时间筛选。
- 增加任意起止日期范围、保存筛选视图或跨会话持久化筛选。
- 为写真、文章插图或 PPT 记录同步增加时间筛选。

## Decisions

### 1. 使用独立 Creation record 日期 helper

新增 `lib/creation-record-filter.mjs`，并同步到 `public/lib`。它负责规范化快捷时间值和 `YYYY-MM-DD` 日期、按本地自然日比较 `createdAt`、生成快捷选项计数以及筛选记录。这样可以覆盖午夜边界、无效时间和未来时间，而不把套图记录耦合到画廊的尺寸与参考图筛选器。

### 2. 精确日期与快捷时间互斥

状态保存 `recordTimeFilter` 和 `recordDateFilter`。选择“今天、近 7 天、更早”会清空精确日期；输入日期会把快捷时间恢复为“全部”。纯函数仍把精确日期视为优先条件，使异常状态不会产生含糊的双重时间交集。

### 3. 关键词与时间共享一个完整过滤管线

先对全部记录应用现有关键词匹配，再应用日期 helper。计数、空状态、默认详情、快捷时间选项和删除目标都从该管线派生；只有列表 DOM 在最后取前 60 条。快捷选项计数基于当前关键词匹配集合，帮助用户预判切换后的结果数量。

### 4. 筛选删除接受显式时间条件

删除 helper 增加显式的 `hasFilter` 和 `filterLabel` 输入。关键词、非 `all` 快捷时间或精确日期任一存在时，筛选删除可用；三者均为默认值时仍返回空目标。确认框显示组合筛选摘要和完整匹配数量，不把时间筛选误写成关键词。

### 5. 沿用资产页紧凑筛选样式

套图记录上下文栏增加与画廊一致的四个紧凑时间选项、原生 `date` 输入和“清空筛选”命令。桌面允许同一行扫描，平板和手机在受限宽度下换行，控件保持至少 44px 触控目标，不引入新的浮层或卡片。

## Risks / Trade-offs

- [浏览器时区与 UTC 日期不同] -> 使用本地年月日构造日期键，不截取 ISO 字符串的 UTC 日期部分。
- [无效或未来的 `createdAt`] -> “全部”保留这些历史记录；有界时间或精确日期筛选不匹配它们。
- [时间经过午夜后计数变化] -> 每次渲染以新的当前时间计算，刷新或任何筛选交互都会得到当前自然日结果。
- [按“更早”可能匹配大量记录] -> 仍显示目标总数并经过不可撤销确认；空默认筛选不能触发删除全部。
- [移动端上下文栏拥挤] -> 时间选项可横向收纳并让日期/清空操作换行，保持主记录区域宽度稳定。

## Migration Plan

1. 先增加日期 helper、删除条件和静态布局失败测试。
2. 实现 helper、public 镜像、状态、控件、组合筛选和删除确认摘要。
3. 运行聚焦测试、完整测试、public-lib 同步、Pages 构建和 OpenSpec strict validation。
4. 用隔离 manifest 验证关键词与时间组合及筛选删除目标，再在真实记录页只读验证布局和计数。
5. 回滚时移除新状态、控件和 helper，并恢复筛选删除仅依赖关键词；manifest 和 API 无需迁移。
