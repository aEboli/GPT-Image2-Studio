## Context

现有平台 V1 提示词已经要求非标题字段只能描述可追溯的商品身份、数量、颜色、材质、形状、尺寸、型号、变体和包装内容，并通过功能词门禁拒绝功效、性能和问题解决表达。真实折叠手拉车记录仍出现字段偏短的问题：卖点拆成零散短语，购买前核对项偏模板化，五点和描述重复同一组事实，搜索词与关键词桶也存在明显重叠。

## Goals / Non-Goals

**Goals:**

- 在现有客观属性安全边界内提高非标题字段的信息密度和可读性。
- 让每个字段回答不同的购买决策问题，减少机械重复。
- 让中英文内容保持逐项一致，并让搜索词覆盖更多有证据的相关表达。

**Non-Goals:**

- 修改标题公式、标题长度或标题价值表达规则。
- 允许功能、功效、性能、兼容性、使用结果或问题解决声明进入非标题字段。
- 增加新的结果字段、模型请求、审核门禁或历史数据迁移。
- 在证据不足时强制达到字数或条目数量。

## Decisions

### 1. 增加独立的非标题完整度规则

平台 V1 提示词新增一组独立规则，不复用标题价值指令。证据足够时，`sellingPoints` 使用 4–5 条不同的客观事实组合，`painPoints` 使用 3–4 条购买前核对项；每条使用完整、具体的表述，但不得引入功能结果。每条核对项必须用已提供的正向事实回答，不能用“未知”“未说明”或缺失信息凑数。证据不足时允许减少条目，禁止复制同一事实凑数。

### 2. 固定五点标签并明确唯一职责

继续使用 `PRODUCT TYPE`、`PACK DETAILS`、`VISIBLE DETAILS`、`SPECIFICATIONS` 和 `PACKAGE CONTENTS`。每一条只承担对应职责，并优先补充前面字段尚未完整表达的相关事实；不得把同一句话换标签后重复。

### 3. 描述按事实层次组织

描述先说明商品身份和父 Listing 范围，再依次组织可见结构、已提供规格、颜色/变体和包装内容。证据充足且平台限制允许时使用 2–4 个短段落，并把英文总长度控制在 350–500 字符；现有 500 字符通用上限和更严格的平台上限始终优先。若事实有限则缩短，不加入警告、模板说明或泛化形容词。

### 4. 搜索词按搜索面分工并跨桶去重

后台搜索词补充标题和可见字段未覆盖的直接相关别称及客观长尾表达。四个桶分别承担核心品类、属性长尾、较宽但直接相关的品类和客观描述词；大小写变体、标点差异、机械单复数和同义重复不得跨桶占位。中文桶忠实翻译对应英文短语，不额外扩充声明。

### 5. 只增强提示词，不增加脆弱的生成后门禁

本次通过提示词和回归断言固定行为，不对自然语言长度、语义去重或条目数量增加确定性拒绝逻辑。现有结构校验、500 字符上限、品牌清理、高风险声明和非标题功能词门禁继续承担硬安全边界，避免低证据商品因无法达到建议条数而错误回退。

## Risks / Trade-offs

- [字段变长后重复] -> 明确字段职责、事实顺序和跨字段去重，并禁止改写同一事实凑长度。
- [为了条数编造内容] -> 条数只在证据足够时适用，事实不足必须少写或省略。
- [搜索词覆盖变窄] -> 允许直接相关别称和客观长尾词，但仍禁止竞品、功能和无关流量词。
- [模型不完全遵循建议] -> 保留现有硬门禁，先用真实记录验证效果；不引入可能误杀正常文案的新语义验证器。

## Migration Plan

1. 增加失败测试，固定非标题完整度、字段分工、去重和双语对应规则。
2. 最小修改平台 V1 提示词，保持标题常量和生成后验证不变。
3. 运行 Listing 定向测试、完整测试、公共模块同步检查、Pages 构建和 OpenSpec 严格校验。
4. 备份目标记录并在 `3600` 实机重新生成；若上游修改标题，则合并回已确认的中英文标题后再持久化。
