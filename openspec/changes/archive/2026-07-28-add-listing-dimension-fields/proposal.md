# Change: 在 Listing 末尾追加包装尺寸和产品尺寸

## Why

当前 Listing 只展示标题、卖点、痛点、五点描述、商品描述和搜索词，买家或运营人员仍需从其他区域查找尺寸。截图所示工作流需要在每条 Listing 的最下方直接给出包装尺寸和产品尺寸，同时清楚区分来源中已有的尺寸与生成时的预估值。

## What Changes

- 在统一 Listing 双语结构中追加 `packageDimensions` 和 `productDimensions` 两个字符串字段。
- 展示、整条复制和 JSON 导出均将包装尺寸、产品尺寸置于关键词分组之后，并保持包装尺寸在前、产品尺寸在后。
- 对来源中明确存在的对应尺寸如实复述，不把产品尺寸误当成包装尺寸。
- 缺少对应尺寸证据时生成保守数值预估，并在英文中以 `Estimated:`、中文中以 `预估：` 明确标记。
- 尺寸继续遵守用户选择的公制、英制或双单位模式，并保持本地服务与 Cloudflare Worker 语义一致。

## Capabilities

### Modified Capabilities

- `creation-listing-agent`: Listing 结构、生成提示、规范化、展示、复制和导出增加末尾尺寸字段及真实/预估边界。

## Impact

- 受影响代码：Listing Agent 结构化响应、草稿规范化与内容门、Listing 视图、共享浏览器镜像及对应测试。
- 新生成草稿保存两个字段；历史草稿无需迁移，仍可读取，重新生成后获得尺寸字段。
- 不增加发布动作，不改变图片生成结果或现有字段的相对顺序。
