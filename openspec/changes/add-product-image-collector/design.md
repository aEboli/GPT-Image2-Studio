## Context

Creation 当前通过 `applyCreationReferenceFiles()` 把浏览器 `File` 对象写入独立参考图状态，页面级 `paste` 处理也已经能识别剪贴板中的图片文件。现有前端、Local 和 Worker 均把 Creation 参考图限制为 15 张，分析结构和测试也依赖这个边界。

浏览器扩展需要处理的商品页可能一次暴露数十张图片。系统剪贴板在 Windows 上不能可靠保存多个原生图片项，而图片 CDN 网址又可能受 CORS、重定向或热链策略影响。因此扩展与 Studio 之间使用小型版本化文本清单，图片二进制由本地服务在用户确认后逐张获取。扩展下载路径继续使用 Chrome `downloads` API，只能定位到默认下载目录下的相对子目录。

## Goals / Non-Goals

**Goals:**

- 在 Creation 中提供可发现的一键剪贴板导入入口，并复用现有参考图业务状态。
- 对 1688、Amazon、Temu、TikTok Shop、SHEIN 和大健云仓 GigaB2B 当前消费者商品详情页执行高准确率优先的商品图采集，按主图、详情图和 SKU 图分组。
- 让扩展复制大量候选图时不受多图片系统剪贴板限制，并在 Studio 中保留显式选择和上限反馈。
- 让下载的全部选中图片位于同一个按日期和商品分层的文件夹中，并使用可读的中文类别与 SKU 规格文件名。
- 限制扩展权限和本地代理网络边界，避免任意页面扫描、认证数据外流和 SSRF。
- 让扩展源码可测试、可打包，并随桌面安装包持续分发。

**Non-Goals:**

- 不支持淘宝、天猫、商家后台、任意通用网页或未列入平台规则的区域站点采集。
- 不使用视觉模型猜测任意网页中的商品图，不承诺对未知 1688 页面结构静默降级。
- 不提高 Creation 参考图或上游生成请求的 15 张限制。
- 不读取浏览器 Cookie、请求头、账号资料或绕过登录和反爬限制。
- 不在本 change 中发布 Chrome Web Store 商品、配置企业强制安装或实现静默安装。
- 不建立 Native Messaging、预加载脚本、通用 Electron IPC 或固定本地端口。

## Decisions

### 1. 使用版本化文本清单，而不是复制多张图片二进制

扩展将 `GPT_IMAGE2_STUDIO_PRODUCT_IMAGES_V1` 作为第一行魔术标识，第二部分为 JSON。清单包含 `version`、`source`、`product`、`capturedAt` 和有序 `items`；每个条目只保存稳定 ID、类别、顺序、HTTPS 图片地址、建议文件名、尺寸和置信度。

Studio 按用户点击读取 `navigator.clipboard.readText()`。若文本不是受支持清单，再尝试 `navigator.clipboard.read()` 获取原生图片项，并继续调用现有文件导入函数。清单解析必须限制总字节数、条目数、字段长度、协议和类别，不能把任意剪贴板 JSON 当作网络请求。

该方案兼容只支持一个系统剪贴板项的 Windows 环境，也使来源和分组不会在复制过程中丢失。复制 Base64 图片会让几十张图片形成巨大剪贴板负载，因此不采用。

### 2. 粘贴清单直接进入带缩略图的批次预览，生成参考图上限保持不变

清单解析成功后，Studio 根据当前剩余槽位预选候选项。选择优先级为主图、SKU 图、详情图，在同类别中保留采集顺序；已存在或失败条目不占用最终槽位。用户可以在批次预览中修改选择，但可选数量不得超过剩余槽位。

套图界面的页面级 `paste` 处理先读取事件自带的 `text/plain`。若文本以受支持清单魔术标识开头，则直接解析并打开批次预览，不再要求用户先点击按钮授权第二次读取剪贴板；原生图片仍沿用现有页面级粘贴链路。普通文本不被拦截。

批次预览为每个规范化候选项渲染真实缩略图。缩略图地址指向当前 Studio 同源的受限代理 GET 请求，并使用浏览器原生懒加载；页面不把远程 CDN 地址直接设置为缩略图地址，因此不会携带浏览器中的 1688 Cookie、Authorization 或页面 Referer。粘贴受支持清单是缩略图读取的显式用户动作，但缩略图读取不得把候选项写入参考图状态。

候选计数与批量选择命令放在同一个不换行的工具栏中；窄视口空间不足时工具栏允许水平滚动。全选、反选和主图/详情图/SKU 分类选择都会替换当前选择，并通过同一确定性优先级裁剪到当前剩余槽位。每张候选图的放大按钮放在勾选标签之外，使用同一个受限代理地址在批次弹窗内部显示适配尺寸的大图；关闭大图后恢复原列表、焦点和选择状态。批次弹窗在自身 `keydown` 中显式拦截 `Escape`，并继续拦截原生 `dialog.cancel` 作为浏览器回退：大图可见时只收起大图，列表可见时保持弹窗与选择不变；事件不再传播给页面级覆盖层处理，用户继续通过现有显式关闭控件退出批次。

点击“导入所选”后才逐张获取图片。结束反馈分别报告已导入、重复、失败和未选择数量。这样可接收一个完整采集批次，同时不静默丢弃 15 张以外的素材，也不扩大上游请求体和分析模式。

### 3. 本地代理只允许受支持商品来源和可信图片主机

Local 新增单图代理端点。GET 缩略图请求从受限查询参数接收清单来源和单个图片地址，POST 确认导入继续从受限 JSON 请求体接收同一数据；两者共享完全相同的验证与获取实现。代理只允许 HTTPS、受支持平台的商品页主机以及该平台明确允许的图片 CDN 后缀；1688 对应阿里 CDN、Amazon 对应 Amazon 媒体 CDN、Temu 对应 `kwcdn.com`、TikTok Shop 对应 TikTok/ByteDance 商品媒体 CDN、SHEIN 对应 SHEIN/`ltwebstatic.com`，大健云仓对应 `gigab2b.com`/`gigab2b.cn`。来源平台与图片域名不匹配时必须在请求前拒绝；每次重定向都按同一平台重新验证，最多跟随 3 次。响应必须是 `image/*`，单图最多 20 MiB，并使用超时和流式字节上限终止异常响应。

端点不接收 Cookie、Authorization、Referer 或调用方自定义请求头。云端运行时返回结构化不支持信息。由于允许主机是固定后缀而不是任意 DNS 名称，本地服务不会成为内网地址或任意公网 URL 代理。

### 4. 使用平台适配器、受限悬浮入口、精确站点权限和 Manifest V3 action 注入采集窗

扩展声明 `activeTab`、`scripting`、`downloads` 和 `clipboardWrite`，并只增加六个平台明确商城域名的 HTTPS 站点权限，不使用 `<all_urls>`。Chrome 的 `scripting.executeScript()` 需要站点权限或由扩展 action 授予的临时 `activeTab`；网页内悬浮入口的点击不会授予后者，因此受支持域名需要显式权限。自动内容脚本按各平台可表达的详情路径注册；大健云仓的 `route=product/product` 位于查询参数中，Chrome 匹配模式无法表达该条件，因此入口脚本在 `index.php` 路径执行后必须先完成 URL 查询参数校验，非商品页不创建任何 DOM。后台和采集器继续对完整 URL 二次校验。入口脚本仅创建悬浮入口并发送打开消息，不查询商品 DOM、不读取图片、不发起详情请求，也不自动采集。

采集器先用 URL 选择唯一平台适配器。每个适配器独立定义商品 ID、标题、可信图片域名、JSON-LD 或平台公开声明数据以及主图、详情图、SKU 图的已知区域选择器；共享层只负责 HTTPS URL 规范化、尺寸与占位图过滤、同分类去重、连续编号、中文文件名和清单生成。平台未匹配、图片 CDN 与平台不匹配、结构化数据不可识别或已知区域为空时失败关闭，不回退到 `document.images` 或整页 `img` 扫描。

标题选择同样由平台适配器决定明确优先级。1688 当前 `#productTitle` 同时包住 `.title-content` 商品名和 `.sell-point-wrapper` 经营数据，因此适配器必须先读取 `#productTitle .title-content`，再考虑受限的通用回退，不得直接把父节点全文当作商品名。共享层在清理空白后为结果追加无引号的 `——<adapter.label>`；同一平台的纯文字、弯引号和直引号旧后缀都先从尾部移除，再追加一次当前格式，保证重复采集不会产生双后缀。长度边界先为后缀保留空间，使平台标识始终位于最终标题末尾。

大健云仓 GigaB2B 当前商品页使用 `#image-show .el-image.full-width img` 承载有序主图，并使用 `.options-wrap .options-item img` 暴露命名规格缩略图。两类节点的 CDN 地址都通过 `x-oss-process` 分别限制为约 500×500 和 74×74；平台适配器只移除这一已知非语义缩放参数，保留可信主机与其他 URL 边界，使清单、查看和下载指向同一图片对象的原图。当前 `.options-item-active` 规格使用有序主图库最后一张作为 SKU 图，因为其规格缩略图可能不是用户要求的当前款式图；其他规格使用各自缩略图对应的原始对象，规格名称从对应 `.options-item` 文本提取。主图候选在 SKU 映射前固定，采集器不点击规格、不跳转商品，也不依赖模拟 hover 才能恢复原图。每个 `.options-item` 优先从已实测的 `data-gmd-attr-product_id` 读取商品身份，缺失时只回退到同一关联商品链接中格式受限的 `product_id`；该值以 `gigacloud:` 前缀写入可选 `variantKey`，因此同图同名但商品 ID 不同的关联选项分别保留，同一商品选项的重复节点仍会合并。当前结构没有独立详情图区域，因此详情图保持 0，不从主图、推荐区或相似商品区推断补齐。

大健云仓规范化原图可能明显大于采集窗的 124–134px 卡片媒体区。面板仅为卡片缩略图在可信 GigaB2B 图片主机上派生固定上限约 300×300 的 `x-oss-process` 预览；查看器、复制清单和下载消息仍使用条目的原图 URL，预览地址不写入版本化清单。其他平台保持现有预览行为。

Temu 新版商品页不再依赖旧 `data-testid` 或哈希类名。主图按 `#leftContent [role='listbox'] [role='option'] img` 的首次出现顺序读取，SKU 图按 `#rightContent [role='radio'] img[alt]:not([alt=''])` 读取并使用图片或所属单选项的可访问名称，详情图按 `#goodsDetail img[data-src][role='img']` 读取。采集开始时只在 `#goodsDetail` 内查找文案或可访问名称精确匹配 `See more` 的按钮；点击后以受限轮询等待详情图片节点数量稳定，再执行一次统一采集。推荐区的 `View more`、`See more items` 以及 `#goodsDetail` 外任何同名控件均不点击。读取候选尺寸时使用节点自然尺寸、显式尺寸和实际渲染尺寸中的最大可信值，使已有 Temu CDN `data-src` 的图片不会因为当前 `src` 仍为 1×1 透明占位图而被误杀；候选仍必须位于上述已知商品区域并通过平台图片域名、祖先排除和非商品媒体过滤。

点击入口后，后台使用消息发送方的 `sender.tab.id` 注入采集窗；点击扩展 action 时，后台直接使用点击事件携带的标签页补充注入入口和采集窗，不通过 `chrome.tabs.query()` 猜测活动页。若采集窗已经存在，action 注入只发送“展开”语义：已贴边隐藏的窗口展开，已经展开的窗口保持展开，不再反向触发贴边收起。`activeTab` 只保留给用户从扩展栏 action 主动触发的其他页面失败状态，不作为商品页悬浮入口工作的前置条件。

采集窗通过消息发送方的 `sender.tab.id` 请求采集，并同时提交自身 `location.href` 供后台预检；采集器仍使用页面真实地址二次校验。因此即使 Chrome 隐藏 Tab 的 `url` 字段，也不会在已授权商品页上提前误报不支持。采集窗打开和关闭时发送不含页面数据的 DOM 状态事件，让悬浮入口在面板存在时隐藏、关闭后恢复。

悬浮入口和采集窗分别使用 Shadow DOM 隔离 1688 页面样式。采集窗初始以 `clamp(560px, 34vw, 600px)` 停靠在右侧并铺满网页可视区高度，列表在内部滚动，底部操作栏始终位于可视区底部。原本独立的品牌标题层合并进商品摘要标题栏：商品标题和选择计数占左侧弹性区域，`GPT-Image2-Studio / 商品图采集` 位于其右侧并在刷新、关闭按钮左侧使用自适应紧凑字号；整行空白区域仍作为拖动把手。桌面图片网格保持 4 个等宽列，分组使用 12px 水平内边距、网格使用 8px 间距，卡片使用 2px 边框和 6px 圆角，使方形媒体区稳定在约 124–134px；卡片操作栏收紧到 30px，分组标题栏收紧到 44px，图片名称使用 12px 加粗标签。在 1707×876 的常见验收视口、5 张主图加至少 7 张详情图的状态中，滚动区初始画面必须呈现四个可辨认的图片行，且底部复制和下载操作不被挤出。主图、详情图和 SKU 图分组背景统一采用 `hsl(210 24% L)`，仅把明度依次设为 98%、95% 和 92%，在不改变色相与饱和度的前提下形成可辨认的连续层次。六个选择与折叠按钮使用一个最小内容宽度为 534px 的六列网格，桌面同排显示，窄屏通过选择区横向滚动保持单行。用户可从合并标题栏非按钮区域开始拖动，拖动期间由窗口级指针监听持续更新位置，拖离边缘后恢复稳定浮动尺寸，释放到左右边缘阈值内时恢复全高停靠但保持展开。开启折叠后面板自动选择最近边缘停靠并收缩为仍可见的窄边缘栏，指针移入时展开、移出时再次折叠，关闭折叠后保持完整展开。折叠只改变面板位置和可见宽度，不销毁采集结果、选择状态或悬浮窗 DOM，也不恢复另一个悬浮入口。扩展不使用 `<all_urls>`、`tabs` 或 `sidePanel` 权限，也不扫描浏览历史；自动内容脚本的主机、路径和脚本文件必须精确匹配上述入口边界。

采集函数优先从 1688 页面内联商品状态中解析 `gallery.fields.mainImage`、`skuProps` 和 `description.fields.detailUrl`。`mainImage` 是主图权威集合，避免把 `offerImgList` 中重复追加的 SKU 图片误归为主图；`skuProps` 中每个带可信图片的声明规格都生成一个独立 SKU 条目，同一规范化图片 URL 只有在规格名称也相同时才视为重复，因此共用图片的大号、小号等规格仍分别显示、选择、复制和下载；详情描述只允许无凭据请求受限的公开 `itemcdn.tmall.com/1688offer/` 端点，并从 `offer_details.content` 中按顺序读取图片。详情请求设置超时和响应大小上限，失败时仍返回已经确认的主图与 SKU 图。

只有对应类别没有得到可用声明数据时，采集函数才查询版本控制的 1688 商品图库、详情内容或 SKU 区域选择器，并对候选节点执行祖先排除、协议、尺寸、文件类型和身份去重检查。公开详情描述已经成功返回图片时，不再追加页面 DOM 中的详情备用图。详情图片 URL 的无意义 `__r__` 缓存参数在去重前移除，同分类重复图片保留第一次出现的位置；采集器与后台清单规范化对主图、详情图按“分类 + 规范化 URL”维护去重集合。SKU 候选携带可选、受限且带平台前缀的 `variantKey`：GigaB2B 使用关联商品 `product_id`，Amazon 仅在现有 SKU 节点可证实 `data-defaultasin`、`data-asin` 或 `/dp/<ASIN>` 链接时使用 ASIN，TikTok Shop 当前声明数据使用带图销售属性的 `property_value_id`；有 `variantKey` 时按“分类 + 同资源身份 + variantKey”去重，没有时保留现有“分类 + 同资源身份 + 规格名称”回退。当前 1688 声明数据、Temu 与 SHEIN 实页未暴露可独立验证的来源变体 ID，因此这些路径继续使用回退而不猜测字段。主图、详情图和 SKU 图之间不执行全局 URL 去重，使同一图片承担多个声明角色或多个独立 SKU 规格时仍保留语义和独立连续编号。推荐、评价、头像、店铺、导航、Logo、广告、服务浮层、视频封面和占位资源均不进入默认结果。若结构化数据与已知区域都没有结果，界面显示未找到，而不是扫描整页兜底。

TikTok Shop 适配器保留旧 `www.tiktok.com/shop/pdp/<slug>/<id>` 路由，并新增当前 `shop.tiktok.com/<locale>/pdp/<id>` 与 `shop.tiktok.com/<locale>/pdp/<slug>/<id>` 路由。采集器只解析 ID 为 `__MODERN_ROUTER_DATA__`、类型为 `application/json` 且不超过受限大小的脚本，递归查找 `product_info.product_model` 后要求其 `product_id` 与地址末尾商品 ID 完全一致；同一脚本存在完整模型和全局占位模型时选择包含声明媒体的完整模型。`images[].url_list` 按声明顺序提供主图，JSON 字符串 `description` 中 `type=image` 的 `image.url_list` 提供详情图，`sale_properties[].property_values[].image` 提供 SKU 图。每个带图属性值只生成一个 SKU 条目，以受限 `property_value_id` 形成 `tiktok:` 前缀稳定键并使用属性值名称作为显示标签；不得把 `skus` 中每个尺寸组合展开成重复图片。声明图片的 `width`、`height` 与首个受信 `url_list` URL 一起进入清单，复制、查看、代理和下载都保留该页面声明地址。TikTok CDN 的查询参数与路径中 `~tplv-...` 后缀只用于判断同一资源，不改写最终 URL。完整声明模型存在时三个分类都不追加 DOM；声明不可用时，主图和详情图回退只接受 `alt`、`title` 与 `og:title` 一致的当前已知商品媒体节点。

Amazon 适配器从地址路径提取 10 位当前 ASIN，并只检查大小受限、明确包含 `ImageBlockATF` 或 `ImageBlockBTF` 的内联脚本。ATF 只有在其 `asin` 等于当前 ASIN 时才读取 `colorImages.initial` 的 JSON 数组，每项按 `hiRes`、`large`、`main` 最大候选的顺序选择受信 Amazon 图片；声明命中后主图仅使用该有序集合，不再追加 DOM 中其他规格的隐藏大图或 40×40 缩略图。BTF 只解码 `jQuery.parseJSON(...)` 的受限 JavaScript 字符串再执行 `JSON.parse`，不得使用 `eval`、`Function` 或触发页面注册函数；`landingAsinColor` 对应的 `colorToAsin` 必须等于当前 ASIN，每个带图选项再以其 10 位 ASIN 形成 `amazon:<ASIN>` 稳定键。脚本、字段或当前 ASIN 校验失败时分别保留现有 JSON-LD、Open Graph 和已知 DOM 回退。声明图片进入清单时尺寸设为未知，面板加载规范化原图后才用 `naturalWidth` 与 `naturalHeight` 更新，避免把缩略图或渲染尺寸误标成原始分辨率；A+ 详情选择器和非商品祖先排除保持不变。

SHEIN 适配器同时支持 JSON-LD `Product` 与 `ProductGroup`。当 `ProductGroup.image` 已按顺序声明 `900x` 主图时，采集器先采用这些 URL，再用 `section.main-picture[aria-label="Product images"]` 中的画廊节点补缺；页面状态 `allColorDetailImages` 中受信 CDN 的 `origin_image` 形成受限高清映射，只有 DOM 颜色缩略图与声明图片的路径哈希完全相同时才把 SKU URL 替换为该声明地址。声明、Open Graph 和 DOM URL 中已证实的 `_thumbnail_<尺寸>.<格式>` 只作为同一 SHEIN 资源的去重身份，不通过字符串拼接生成新 URL。详情回退只查询当前 `details-pic__img` 和已知旧版商品描述区域，绝不再查询覆盖主图库、商品信息、评价和店铺模块的 `goods-detail` 根节点。当前画廊和颜色选项的 `220×293` 节点只证明缩略图本身尺寸，面板最终从已选择的 `900x` URL 加载事件更新真实尺寸；没有声明高分辨率地址时保持保守回退，不猜测或拼接未证实的 CDN 变体。

### 5. 下载使用日期父目录、一个商品文件夹和中文确定性文件名

扩展把选中图片依次下载到 `GPT-Image2-Studio/<YYMMDD>/<商品ID-标题>/`，日期使用浏览器本地日期，例如 2026-07-27 为 `260727`。主图和详情图按各自分组顺序命名为 `主图-1.jpg`、`详情图-1.jpg`；SKU 图按独立规格命名为 `SKU-1-<规格名>.jpg`，即使多个规格共用同一图片 URL 也使用各自顺序和规格名生成不同文件名，并执行 Windows 非法字符清理和总长度限制。已知原扩展名继续保留。

下载使用 `conflictAction: "uniquify"`，只提交用户选中的图片，不创建或下载 `manifest.json`、数据 URL 或其他辅助文件。来源与全部 SKU 映射仍保留在用户主动执行“复制到 Studio”时生成的版本化文本清单中。

不使用 `saveAs`，避免每张图片重复弹出选择器。第一版不承诺选择默认下载目录之外的任意文件夹。

每张缩略图卡片下方提供仅显示熟悉图标的查看和下载按钮，按钮仍保留中文 `title` 与 `aria-label`。单图下载复用相同下载规划与 `downloads` 消息，只提交该卡片 ID。查看操作在采集面板内部打开绝对定位的半透明叠加层，仅覆盖插件内容，不超出面板边界、不打开新标签页，也不遮罩商品页其余区域；查看器删除左上角“返回”和图片说明标题，只在右上角保留紧凑的关闭图标。图片元素保持自然像素布局，不设置把它预先压进舞台的 `max-width` 或 `max-height`；缩放计算统一读取 `naturalWidth` 与 `naturalHeight`。默认打开按舞台和旋转后自然尺寸的最小比例 contain 完整适配，长图所需比例可以低于常规 50% 手动缩放下限；滚轮继续在默认适配比例与 400% 之间缩放并阻止底层页面滚动。舞台底部居中显示轻微着色的半透明浮动工具栏，依次提供“全屏”（按自然尺寸的最大轴比例 cover 铺满插件舞台）、向左旋转、向右旋转、放大、缩小和“恢复初始视图”。所有缩放状态都直接显示抓取光标并支持按住鼠标左键拖动，不再以图片是否溢出舞台作为拖动门槛；每个舞台轴的最大位移取该轴缩放后图片尺寸与舞台尺寸差值绝对值的一半，使小于舞台的图片始终完整留在舞台内，大于舞台的图片可移动到边缘且不会越界。拖动结束不会误触关闭。“恢复初始视图”使用内收四角图标和中文悬停提示；点击或快速双击图片触发该命令时，先结束正在进行的拖动，再把旋转角度与两个轴位移归零，并基于当前舞台和未旋转自然尺寸重新计算 contain 比例。复位后查看器保持打开，视觉结果与该图片首次加载完成时一致。“全屏”和“恢复初始视图”均为每次点击执行一次的可重复命令，不保留选中或锁定外观，所有操作都保持在插件边界内且不调用浏览器全屏。点击面板内图片外遮罩或右上角关闭按钮关闭查看。查看器底部删除文件名与“第 N / 共 M 张”说明，只保留左右分离的半透明上一张、下一张图标按钮；切换图片时旋转、缩放和位移重置，关闭查看后恢复原列表和选择状态。

### 6. 本地端点按需生成扩展 ZIP，商店安装作为后续分发步骤

扩展源码保存在 `extensions/product-image-collector/`，共享清单协议从 `lib/` 在打包时复制到 ZIP。Local 下载端点使用已存在的 `jszip` 生产依赖按需生成并缓存 ZIP。桌面构建白名单包含扩展源码，但不包含 `artifacts/` 或已生成 ZIP。

工具菜单入口下载 ZIP，并提供明确完成反馈。Chrome 在 Windows 上仍要求用户解压并通过扩展管理页加载，或未来从 Chrome Web Store 确认安装；应用不得使用注册表、本地 CRX 或外部协议绕过该确认。商店商品创建后，可以在独立 change 中把同一入口切换为精确允许的商店 HTTPS 地址。

菜单入口使用与按钮相邻的真实 `role="tooltip"` 说明节点，并通过 `aria-describedby` 关联。鼠标悬停入口或键盘焦点进入入口容器时，说明在桌面菜单右侧完整显示；单列、平板和手机布局改在按钮下方显示，宽度受视口约束。说明覆盖六个平台、三个图片分类、Studio 复制与按商品文件夹下载、主动采集和不读取登录凭据边界，以及浏览器安装或更新仍需用户确认；它不拦截指针，也不改变点击下载 ZIP 的原有命令。

### 7. 分组标题栏承担组内选择与下载，卡片选中态直接可见

每个分组使用独立白色标题栏：左侧显示 `主图（N张）`、`详情图（N张）` 或 `SKU 图（N张）`，右侧显示该组已选数量、原生复选框形式的“全选”和纯下载图标。组内全选只增删当前分类的 ID，不影响其他分类；部分选中时使用复选框 `indeterminate` 状态。组内下载复用既有批量下载消息，只提交当前分类已选条目，无选中项或正在处理时禁用。

图片卡片不再依赖细小勾选框作为唯一选中反馈。已选卡片使用 `#5b9cff` 蓝色边框，未选卡片保留中性边框；图片名称标签改为 14px 加粗深色半透明底，仍限制为单行省略，避免覆盖缩略图主体或改变网格尺寸。该调整不增加参考界面的翻译、复制链接等非现有业务功能。

卡片媒体区保持固定 1:1 布局并使用纯白背景，内部 `<img>` 使用 `object-fit: contain`，因此竖长图和横宽图都完整缩入边界，留白仅属于显示层。预览 URL 仍只赋给卡片 `<img>`；查看器、清单、Studio 导入和所有下载消息继续读取 `item.url`。带非空 `variantLabels` 的 SKU 卡片增加固定 20px 中间行，文本直接使用规格名称以 ` / ` 连接，不显示类别、序号或说明前缀，也不设置 `text-overflow: ellipsis`；主图、详情图及没有可证实规格名称的 SKU 不生成该行。

每次渲染后，面板按 SKU 卡片的实际 `getBoundingClientRect().top` 把规格节点分成视觉行。每个节点先以 10px 上限测量内容宽度，根据自身可用宽度求出完整单行显示所需字号；同一行取所有结果中的最小值并应用到全部节点，随后以 0.1px 步长向下校正，直到该行每个节点都满足 `scrollWidth <= clientWidth`，最小允许 1px。窗口宽度、响应式列数、折叠展开或重新渲染改变布局时通过下一帧重新分组和计算，避免不同长度规格在同一行出现不同字号。

## Risks / Trade-offs

- [平台更新 DOM 后采集数量下降] -> 每个平台适配器集中维护选择器并用代表性 fixture 回归；失败关闭而不是扩大到全页扫描。
- [公开详情描述端点变更或超时] -> 仅访问页面声明且主机/路径受限的无凭据端点，限制响应大小和等待时间；失败时保留主图与 SKU 图并显示部分结果提示。
- [公开 CDN 图片仍可能拒绝本地服务] -> 对每张失败项单独反馈，并保留扩展“下载全部”作为文件导入回退，不携带用户认证数据重试。
- [大量候选图使批次弹层拥挤或触发过多图片请求] -> 使用分组、固定比例真实缩略图、内部滚动、响应式列数和浏览器原生懒加载；缩略图只走同源受限代理，不直接访问 CDN。
- [大件云仓原图恢复或规格 DOM 变化] -> 只移除版本控制的 `x-oss-process` 参数，当前规格只在明确 `.options-item-active` 与有序主图库同时存在时绑定最后一张，缺少该契约时保留规格自身图片并由代表性 fixture 失败关闭；卡片继续请求轻量预览而不是一次加载全部原图。
- [平台变体身份字段变化或多个 DOM 表示同一选项] -> 只使用已证实且格式受限的平台字段，统一加平台前缀并随清单规范化；相同 `variantKey` 继续去重，字段缺失时退回 URL 与规格名称，不使用节点序号制造额外 SKU。
- [用户误以为 ZIP 已自动安装] -> 菜单文案使用“下载插件”，包内包含中文安装说明，完成反馈不声称安装成功。
- [多平台权限面扩大] -> 仅声明列出的商城 HTTPS 域名，不包含 Seller Center、任意顶级域或 `<all_urls>`；自动内容脚本使用最窄可表达路径，入口、后台和采集器继续执行完整详情页 URL 校验，采集和下载只由明确用户动作触发。
- [持久侧边栏丢失活动页 URL 可见性] -> 不在面板中调用 `chrome.tabs.query()`；action 负责注入，悬浮窗通过 `sender.tab` 让后台采集当前授权页。
- [本地代理内存占用] -> 单图请求、20 MiB 硬上限、超时和有限并发，不返回包含多张图片的 Base64 JSON。
