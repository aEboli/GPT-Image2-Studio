## Context

默认工作台 HTML 在 `head` 中引用 Google Fonts。画廊接口为每个本地图片返回相同的 `imageUrl` 和 `thumbnailUrl`，因此小尺寸的最近输出、胶片条和画廊瓦片仍读取完整原图。历史输出可能有数百张、总容量达到 GB 级；在列表扫描期间同步补齐所有缩略图会把问题从浏览器移到服务端。

项目需要支持普通 Node 启动、Windows 浏览器启动器和 Electron 桌面包。仓库的回归约束禁止原生预编译的图像处理依赖，因此缩略图实现必须可随现有 JavaScript 分发链运行。

## Goals / Non-Goals

**Goals:**

- 首屏在没有互联网连接时仍使用本机字体直接渲染。
- 新保存的可解码图片最终拥有小尺寸 WebP 缩略图；缩略图最大边长固定且不会替代原图。
- 旧图片只在浏览器实际请求缩略图时生成，重复请求共享同一项工作并复用落盘结果。
- 最近输出、胶片条和画廊瓦片请求缩略图；灯箱、主预览、下载和编辑继续请求原图。
- 端口检测一次读取操作系统监听端口集合，仍仅通过 Studio 的本地 HTTP 健康检查复用已占用端口。

**Non-Goals:**

- 不重构 `/api/creation/sets` 的列表或详情响应。
- 不在启动时扫描并回填既有全部历史图片。
- 不改变图片的原始文件、元数据语义、画廊筛选、删除或灯箱交互。
- 不把完整原图转换、替换或压缩为缩略图。

## Decisions

### 使用系统字体栈

移除 HTML 中的 Google Fonts 预连接与样式表，CSS 统一使用 Windows、macOS 和 Linux 可用的系统字体顺序。标题与正文保留不同的字重和大小规则，但不再引用需要下载的字体文件。这比把字体二进制复制进仓库更小，也避免额外许可、缓存和首屏请求链。

### 使用纯 JavaScript/Wasm 图像编解码生成 WebP 缩略图

新增纯 JavaScript 的 Jimp，并通过 `@jsquash/webp` 直接初始化随包分发的 WebAssembly 编解码器，生成最大边长 512px 的 WebP 文件。它不要求操作系统安装图像工具，也不会引入受现有仓库约束禁止的原生预编译图像依赖。PNG、JPEG 和 WebP 输入共用同一条缩放路径；无法解码的历史文件保留原图回退，且不得使图片保存或列表读取失败。

缩略图存放在输出目录的 `json/thumbnails/` 镜像路径下，使用原始文件名加 `.webp` 后缀以避免不同源格式的同名冲突。该目录本来就不进入画廊图片扫描。删除和重命名原图时同步删除或移动对应缩略图。

### 通过按需同源端点回填历史图片

画廊列表直接返回原图 URL 与 `/api/gallery/thumbnail` URL 的不同字段。缩略图端点验证相对图片路径（包括拒绝路径穿越、元数据目录和 Windows 替代数据流语法）、复用已有 WebP，缺失时才生成并返回；请求失败或不能解码时安全回退原图。浏览器的原生惰性加载确保不在首次列表请求中触发离屏历史图片的重建。

新保存图片和按需缩略图端点共用同一条串行转码队列，不阻塞生成结果保存。已落盘的缩略图会在入队前直接复用；缺失项按目标路径去重，避免同一张图或多个可见历史项并发解码造成 CPU、内存尖峰。

### 显式选择缩略图媒体

新增前端缩略图 URL 辅助函数。最近输出、胶片条和画廊瓦片调用该函数；预览、灯箱、下载与需要像素原图的操作仍调用既有原图 URL 函数。合并旧浏览器缓存时，服务端缩略图优先于历史缓存中的完整 data URL；默认启动只读取轻量缓存索引，不逐张恢复 IndexedDB 中的完整 data URL，避免旧缓存再次拖慢首屏。

### 单次监听端口快照

启动脚本用 .NET 的本地 TCP 监听端口集合建立 `HashSet`，端口查找只查询该快照。只有已被占用的候选端口才发起已有的本地 Studio HTTP 健康检查；启动后的等待仍以同一健康检查确认服务真正可用。这保留了“不误打开无关服务”的安全边界。

## Risks / Trade-offs

- [纯 JavaScript/Wasm 编码消耗 CPU 和内存] -> 新图后台任务和历史图按需请求都经受限队列执行，固定 512px 上限且同一路径去重。
- [历史文件损坏或编码不受支持] -> 缩略图请求安全回退原图，不阻断画廊列表、保存或删除。
- [Electron 包体增加] -> 依赖为可分发的 JavaScript/Wasm 模块；在打包冒烟测试中验证可加载。
- [系统字体与原字体的字形度量不同] -> 保持现有字号、间距和字重，使用跨平台回退顺序并做桌面与窄屏截图检查。
- [端口快照在探测后发生竞争] -> 原有启动后健康检查保留，竞争只会走既有超时反馈，不会复用无关服务器。

## Migration Plan

1. 部署后新生成图片逐步产生缩略图，现有原图与 sidecar 不需要迁移。
2. 用户浏览旧记录时，缩略图按实际可见范围渐进写入 `json/thumbnails/`。
3. 回滚时可停用缩略图端点并继续使用原图；缩略图文件是派生缓存，不影响已有原图或元数据。
