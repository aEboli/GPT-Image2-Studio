## ADDED Requirements

### Requirement: 所有文本模型调用以真实增量输出

系统 SHALL 为文本/视觉分析、营销规划、Listing、翻译、文章和 PPT 文本调用提供流式优先传输，按已配置的 Responses、Chat Completions 或模型兼容协议适配回答增量。浏览器 SHALL 在完整回答结束前显示已实际到达的安全回答文本。系统 MUST NOT 将私密推理、心跳或人为编造的过程作为模型输出。

#### Scenario: Chat Completions 逐段返回回答
- **WHEN** 当前文本模型使用 Chat Completions 且网关支持 SSE
- **THEN** 上游请求启用流式并接收回答 delta
- **AND** 用户在完整 JSON 返回前看到实际回答内容逐步更新

#### Scenario: 网关不支持或缓冲流式
- **WHEN** 已配置网关拒绝流式协议或只返回完整缓冲结果
- **THEN** 系统明确展示实际能力或缓冲状态
- **AND** 不擅自切换用户 API 地址，不把定时播放文字报告为真实流式

### Requirement: 可视草稿与最终业务结果隔离

系统 SHALL 支持转义和 UTF-8 跨分片的回答显示，完整结构化字段 MAY 进入摘要卡片；未完成内容 SHALL 标注接收状态。系统 MUST 在完整解析与既有业务校验通过后才将结果用于生成或保存为确认计划。取消、重试和切换输入 SHALL 隔离旧输出，连续更新 SHALL 保留当前阅读位置。

#### Scenario: 中文字段尚未结束
- **WHEN** 回答分片停在中文字符或 JSON 字符串转义中间
- **THEN** 视图保留已成功解码的安全文本且不产生乱码
- **AND** 不将该未完成字段视为已校验任务

#### Scenario: 重试期间收到旧请求分片
- **WHEN** 旧请求在新尝试开始后继续产生分片
- **THEN** 旧分片不能覆盖新尝试的可视草稿或最终结果

### Requirement: 单次逻辑文本操作共享有限重试预算

系统 SHALL 将结构化格式兼容和完整 JSON 修复纳入同一操作级预算，一次逻辑文本操作最多发出两次上游 POST。浏览器 MUST NOT 对同一服务端错误额外循环重放。取消和确认的账号/权限错误 MUST NOT 自动重试。系统 SHALL 展示实际尝试次数和重试原因。

#### Scenario: 格式回退后仍返回损坏 JSON
- **WHEN** 首次请求的结构化参数被拒绝且第二次兼容请求返回无法解析的完整回答
- **THEN** 系统停止并报告已用完重试预算
- **AND** 不发出第三次模型请求

#### Scenario: 首次回答需要 JSON 修复
- **WHEN** 首次完整回答无法解析且尚未使用重试预算
- **THEN** 系统至多发起一次明确标识原因的修复请求
- **AND** 修复失败后显示错误并允许用户手动重新开始
