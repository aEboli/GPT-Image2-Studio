## Context

套图记录已经具有按 `createdAt` 的本地自然日筛选，文章插图和写真只有关键词搜索，PPT 没有筛选栏。三类 Local store 均返回按时间排序且带 `createdAt` 的完整记录集合，浏览器可以一次完成筛选，无需增加服务端查询参数。现有共享删除控制器已经为三类记录提供当前项和显式勾选删除。

## Goals / Non-Goals

**Goals:**

- 三类资产页使用一致的快捷时间和精确日期语义。
- 文章插图、写真中的关键词与时间条件组合生效。
- 计数、空状态、详情选择、列表和删除后的相邻选择基于同一筛选集合。
- 桌面、平板和手机均能看见并操作筛选与现有删除命令。

**Non-Goals:**

- 不增加任意起止日期范围、服务端分页或查询参数。
- 不改变 manifest 或补写旧记录时间。
- 不增加 Delete filtered、Delete all 或自动清理能力。
- 不修改 Local 与 Cloudflare 的持久化能力边界。

## Decisions

### 1. 增加跨资产共享时间 helper 和 controller

新增 `lib/asset-record-time-filter.mjs` 和 `lib/asset-record-time-filter-controller.mjs` 并同步到 `public/lib`。前者负责规范化快捷值和 `YYYY-MM-DD`、按本地自然日比较 `createdAt`、生成带计数的快捷选项和判断活动筛选；后者集中持有 Article、Portrait、PPT 的关键词/时间状态，并负责控件渲染、计数和事件绑定，避免继续扩大浏览器主入口。保留现有 Creation helper，避免本次变更扩大到已经稳定的套图流程。

### 2. 浏览器对完整记录集合做筛选

共享 controller 让 Article 和 Portrait 先应用关键词、再应用时间，让 PPT 直接应用时间。列表、计数、空状态、默认详情和删除控制器的可见顺序都使用最终集合。选择快捷时间会清空精确日期，输入有效日期会恢复快捷值为 `all`。

### 3. 删除仍以显式目标为唯一依据

时间筛选只影响当前可见集合和当前详情，不创建筛选删除按钮。Delete current 只取当前详情；Delete selected 只取明确勾选且仍存在的记录。筛选前已勾选但暂时隐藏的记录仍是显式选择，只有用户触发 Delete selected 并确认时才会删除。

### 4. 复用资产工作区现有紧凑控件样式

三页使用与套图相同的分段时间按钮、原生日期输入和“清空筛选”，同时增加通用 asset 类名。移动端让快捷选项换成稳定的两列布局，避免控件或删除命令被挤出视口。

## Risks / Trade-offs

- [浏览器时区与 UTC 日期不同] -> 使用本地年月日边界，不截取 ISO 字符串日期部分。
- [缺失、非法或未来时间] -> “全部”保留记录；有界快捷时间和精确日期不匹配非法值，未来时间不匹配快捷窗口。
- [筛选后当前项不再可见] -> 自动选择筛选结果第一项；无结果时清空详情，但保留显式勾选状态。
- [用户误把筛选理解为批量删除范围] -> 不提供 Delete filtered，确认请求仍只包含当前项或勾选项。

## Migration Plan

1. 添加共享 helper/controller、纯函数与控制器测试，以及三页静态契约测试。
2. 接入状态、控件、组合筛选、计数与选择联动。
3. 运行聚焦测试、完整测试、public-lib 同步检查、Pages 构建和 OpenSpec 严格验证。
4. 在 Local 页面实测桌面与移动端筛选及删除按钮可见性。
5. 回滚时移除新控件、controller 和 helper；记录文件与 API 无需迁移。
