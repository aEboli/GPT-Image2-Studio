## Context

见 proposal.md。普通反推继续使用严格五组 JSON。`visual` 已包含风格锁定锚点；本变更只增强其中的清晰度和画面整洁描述，并扩展 `avoid` 对可见瑕疵的约束。

生图请求的像素尺寸由独立的路线参数决定。此次用户确认只增强反推提示词，所以“4K/8K级”只作为生成提示词中的视觉质量意图，不能描述为原图 EXIF、API 参数或实际输出尺寸。

## Goals / Non-Goals

**Goals:**

- 让反推提示词明确要求主体焦点清楚、源图可见纹理可辨、边缘自然清晰、主体与背景层次干净。
- 只规避与源图不符的虚焦、拖影、伪影、畸变细节和额外杂物。
- 保留源图中有意的散景、浅景深、柔焦、运动效果和颗粒质感。

**Non-Goals:**

- 不新增顶层 JSON 字段或修改历史记录结构。
- 不修改 Studio 的比例、尺寸、质量控件或生图请求。
- 不承诺 8K 像素输出，不加入 AI 超分辨率步骤。
- 不为追求锐利而发明源图不可见的纹理、道具或背景元素。

## Decisions

### 1. 将高解析度表述为视觉质量意图

`visual` 先保留最能决定源图辨识度的风格锚点，再使用一次简洁的“4K/8K级超高清成像质感”表述，并配合清晰主体、源图可见纹理和自然边缘等具体目标。指令明确该表述不等于实际输出尺寸或源图元数据。相较于在多个字段重复堆叠“8K、超清、极致细节”，此方式让风格更明确并减少生成噪声。

### 2. 对焦主体清晰，保留有意的虚化

清晰度要求限定在源图明确清晰的焦平面和可见纹理。若背景存在浅景深、散景、柔焦或运动模糊，则 `visual` 按原图记录，`avoid` 不得将其当作瑕疵删除。

### 3. 按源图证据控制杂乱

模型仅在与源图冲突时将随机装饰、重复物体、畸变边缘、压缩噪点、纹理涂抹或无关文案列入 `avoid`。它不因“整洁”而删掉原图已有的密集环境或叙事元素，也不生成原图不可见的微小细节。

## Risks / Trade-offs

- “8K”措辞可能被误解为真实像素尺寸。→ 指令、schema 和 UI 明确标注为视觉质量意图，不是尺寸或元数据。
- 清晰度要求可能把有意虚化错误识别为瑕疵。→ 以焦平面、背景层次和运动表现为对象作条件描述。
- 负面约束可能压制原图已有内容。→ `avoid` 只描述源图中不存在且可能误生成的偏差。
