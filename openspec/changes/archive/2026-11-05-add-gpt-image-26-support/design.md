## Context

项目是 Node.js/Electron 工作台，浏览器共享模块通过 `scripts/sync-public-lib.mjs` 复制到 `public/lib`。当前应用版本为 0.2.117；工作区存在与本任务无关的未提交改动，实施不能覆盖它们。

主要接入点：

| 位置 | 当前行为 | 所需最小变化 |
| --- | --- | --- |
| `lib/model-defaults.mjs` | 工具白名单到 2.5；扩展质量只认识两个 2.5 ID | 两个 2.6 ID、显示标签、模型级能力查询 |
| `lib/image-route-config.mjs`、配置模块 | 传递模型和直连流式开关 | 新能力参数按路由保存和恢复，不触碰其他提供方凭据 |
| `lib/responses-workflow.mjs` | 固定 n=1、直连带 response_format、中间预览固定 2、只取第一张图 | 按端点/格式建请求，完整读取结果数组、输出格式和用量 |
| `lib/output-format-options.mjs` | 非 JPG 一律归一化为 PNG | 新格式必须正确往返，不以 PNG 假成功 |
| `lib/generated-image-validation.mjs` | 只解析 PNG/JPEG | WebP/GIF/SVG 的结构、尺寸和有效性验证 |
| `lib/gallery-store.mjs` 与缩略图模块 | 扫描 PNG/JPEG/WebP，尺寸推断主要为 PNG/JPEG | GIF/SVG 原件、派生预览、元数据索引和历史扫描 |
| `server.mjs` | 多模式复用单张 finalBase64，保存前统一位图验证 | 有限扩展结果契约，分格式验证与正确任务完成时机 |
| `public/app.js`、`public/index.html`、视图 | 参数控件按旧静态图路径组织 | 随模型/端点/操作/格式动态显示有效控件及不兼容原因 |
| 快照、补图、CLI | 已保存旧模型和质量字段 | 保存并恢复新参数，CLI 提供相同约束，不改历史记录 |

## Decisions

### 1. 能力描述保持小而明确

建议新增 `lib/image-model-capabilities.mjs`，供前后端共用。只描述本次涉及的 GPT Image 模型；不重新设计 Gemini/Grok 路由，也不根据字符串包含“2.6”放开未知中继模型。能力至少区分：模型 ID、端点、生成/编辑、输出格式、复杂度、流式、中间预览、markup/mask、SVG 作者、帧参数、输入/输出数量和已核实尺寸边界。

未知能力用“未验证”表示，不等同于支持或永久不支持。模型/提供方的权限失败应明确显示，不能自动删掉 SVG/GIF/复杂度参数后重发并声称完成同一任务。

### 2. 三层规划与质量分开

- 外层文本规划沿用现有 `reasoning.effort`。
- 新增图像规划 `imageComplexity`，序列化为 `complexity`；默认省略，不把现有 high 思考等级自动复制过去。
- `quality` 仍代表渲染质量；保留 auto 的真实含义，不能静默归一化为 high。
- SVG 作者模型和 `svg.reasoning.effort` 单独显示、保存。Images 与 Responses 对省略 svg 对象的默认选择不同，按各自契约构造请求。
- 官方指南已确认两个 2.6 模型支持 xhigh/max，须补齐现有扩展质量函数；未确认的尺寸边界必须在真实验证前解决。

### 3. 按输出格式验证完整链路

PNG/JPEG 保留既有行为；WebP 补齐格式、压缩和结果识别。GIF 保留动画原件，提取首帧或海报用于列表，灯箱允许播放与暂停，原件下载不经过静态 canvas 重编码。SVG 保存原始矢量文件，列表可以使用派生位图预览；渲染不使用 innerHTML 注入，阻止脚本、事件属性、外部资源等活动内容。各格式校验真实字节，避免只改扩展名。

Images GIF/SVG 用普通 JSON 完成响应；Responses GIF 保留任务状态 SSE，省略中间预览。Responses SVG 的事件方式以进一步核实的协议为准，不从 Images 的约束直接类推。客户端沿用现有任务状态而不是伪造中途图片。

### 4. SVG 和 GIF 在适合的入口交付

普通提示词生图、Logo/图标等适合选择 SVG；图像编辑不显示 SVG/GIF。GIF 首先走官方指南明确的生成接口；SDK 虽列出编辑 gif 枚举，不能据此开放源图动画编辑。套图、写真、文章与 PPT 共享 2.6 模型和适用的静态参数，但这些下游的静态槽位不得在无提示情况下改成交付动画。对于 PPT/Temu 不支持的格式，提供明确的格式限制或由用户选择生成导出副本。

SVG/GIF 并不要求立刻新增顶级导航或独立项目；优先扩展现有参数区、编辑区与灯箱。

### 5. 标注引导复用现有编辑区

保留原有单图编辑、merge/sequential 蒙版策略。新增“标注引导”编辑方式，沿用画布、缩放、撤销与颜色交互，但导出透明 PNG 为 `markup`，不混作 mask。标注与首图在方向归一化后等尺寸，后端实际检查透明度与文件结构。markup 与 mask 同时提交时在出站前报错。当前 Responses 工具类型没有 markup 字段，标注编辑走支持它的 Images edits，并显示实际端点。

### 6. 多图与参考图保留业务边界

普通生图可通过原生 n 产生候选图，结果数组逐项校验和保存，用统一任务 ID 加结果序号去重；部分保存失败应报告成功与失败的数量，不能仅丢弃其他结果。其他现有单结果调用保持兼容适配，套图每个槽位仍为一个结果。参考图上限按模型和入口校验，在支持多图的入口对 2.6 接通 16 张；写真角色配额不随意扩大，原有单源图编辑不改变。

### 7. 新参数跟随不可变任务快照

新参数从配置默认值进入控件，提交时冻结为任务快照，排队、重试、原任务回查、补图、历史重开均使用该快照。记录请求参数和上游返回的实际格式/尺寸/质量/作者模型/用量；未发送 `tools[].model` 时工具模型视为未指定，不能仅根据下拉框把记录写成 2.6。不得保存 API Key 到公开元数据。

### 8. 兼容修复限定在新路径

2.6 官方 Images 请求省略不支持的 legacy `response_format`。对既有中继的特殊字段要求保留当前兼容边界，不全局重写其他提供方行为。新增参数的错误不自动触发重复收费请求；沿用既有取消、并发和重试预算。

## Risks / Open Questions

1. 本机文档请求 403 已通过网页检索工具补齐；官方指南与接口/SDK 仍存在 GIF 帧数及编辑支持差异。指南为 2–64 帧、接口/SDK 为 2–16 帧；先核实实际提供方，不以静默限缩或参数拒绝重试掩盖冲突。
2. GIF preview 与 SVG 作者选择依赖权限。未开通账户只能验收失败提示，不能宣称真实生成成功。
3. 输出类型影响验证、缩略图、画廊、导出和恢复，工作量主要在这里，不能只改前端选项。
4. 原生 n 改变单请求交付数量，必须区分候选图和套图任务并保存全部结果。
5. 源码类型能确认接口字段，不能证明特定中继已实现或推断模型价格/性能。

## Delivery Order

1. **模型与基础管线**：A/B 双路线、配置、复杂度、已确认质量/尺寸、WebP/压缩、静态预览、快照和各生成模式；验证真实请求与参数记录一致。
2. **标注编辑与数量**：markup、16 参考图、普通生图多结果；验证互斥、方向、结果数量和原有编辑回归。
3. **新输出完整交付**：SVG/GIF 参数及权限、格式验证、保存、预览、原件下载、用量与下游约束；验证完整用户路径。
4. **发布验收**：全量回归、同步、真实界面、获授权的最小真实调用、版本化发布、严格校验与归档。

阶段一完成只能称“2.6 基础接入”，所有适用阶段通过才称“全面支持”。用户已确认并完成本地实施与验证。真实提供方权限、尺寸与扩展帧数仍单独列为待验收，不能宣称真实账户能力已全部通过。

## 实施后的明确决策

- 共享字段使用 imageOptions.complexity；不引入另一套 imageComplexity 命名。
- 无真实凭据时不能确认模型尺寸上限。2.6 仅校验 auto 或正整数 WIDTHxHEIGHT，保留用户输入交由上游校验，不复制 2.5 的单边、像素和比例限制。
- GIF 接收指南范围 2–64，但 UI/CLI 明示接口参考/SDK 当前为 2–16；17–64 不是已验收支持，不做静默降帧。账户权限失败不转换为静态图。
- GIF/SVG 只在普通无参考图提示词生成入口开放；现有业务图槽位限制为静态输出。当前没有为 Logo 批处理或 PPT/Temu 新增动画/矢量导出转换。
- Responses SVG 使用 JSON 完成响应；Responses GIF 保留生命周期 SSE。只保存已收到的用量/实际质量，不为了尾部用量而延长已结束的图片连接；可能缺少后续 usage。
- 图片编辑保留全局指令并追加按颜色绑定的区域说明。原件与标注都从同一方向归一化画布导出，后端检查实际 PNG 透明度和尺寸。
- 写真/文章首次请求前保存高级选项，历史补图/重生成使用已保存的选项；没有高级选项的旧记录使用空选项，不继承当前的新增设置。
- Electron 在独立 userData/output 中完成启动、截图和 Resvg 原生渲染；未构建或安装正式发行包。
