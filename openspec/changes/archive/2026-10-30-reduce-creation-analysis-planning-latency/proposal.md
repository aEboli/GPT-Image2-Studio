## Why

用户反馈分析师和营销规划耗时长，实时接收不清楚。截图中两次调用分别显示输出 29,758 / 19,610 token、总耗时 185 / 131 秒，首字 12.66 / 22.73 秒；缺少关联请求 ID，不能据此认定哪个属于分析、初稿或局部修复，也不能认定网关是否缓冲。

现有界面的小修已独立处理：营销详情计时停在最后事件、同阶段字符量不刷新、计时触发相同草稿重绘；分析师准备图片时无状态、参考图观察等实际回答字段被显示过滤。这些修复不改变模型行为。

对现有 20 图测试夹具的本地回放，117 次部分 JSON 与草稿解析合计约 28 毫秒，远小于截图分钟级请求；这是夹具测量，不能代替真实模型对比。接下来需要优化输出与请求，并测量实际链路。

## What Changes

- 给分析和营销请求补充分阶段观测：资料准备、上游首包、首段回答、回答结束、校验和实际修复轮次，关联逻辑请求与每次真实调用；区分网关整包缓冲和流式回答。
- 复用仍有效的已识别事实与 ID；营销响应只输出策略与逐图任务，避免重复分析。输入变化继续使分析和计划失效。
- 精简重复的策划摘要、已有合格项修复上下文和非必要格式空白；完整提示词、事实、条件、主体与参考约束不截断，不设硬字符上限。
- 保持正常初稿一次整套请求、既有有界局部修复和用户选择的 High 等思考等级。基于同输入对比数据评估进一步并行拆分，当前阶段不新增逐图调用或自动降低等级。

## Capabilities

### Modified Capabilities

- `creation-mode`: 分析与营销的分阶段可观测耗时及有据内容去重。

## Impact

涉及 `lib/text-model-stream.mjs`、`lib/prompt-agent.mjs`、营销上下文与修复链路、分析师和营销进度展示以及测试。不修改真实 API 配置或历史冻结计划。
