## Why

代码审查确认当前发行维护流程和 Prompt Agent 历史补齐存在四个可复现边界：补丁更新在部分写入失败后会留下版本事实不一致的工作树；对整份文件执行版本字符串替换会误改历史版本文本；发行检查会把 HTML 注释中的标签当成可见版本事实，也不能可靠拒绝重复标签；Prompt Kit 会把参考图编排等非普通图片反推历史误导入为单条模板。这些问题虽然没有被现有测试捕获，但会直接影响发行可恢复性、版本事实可信度和用户模板内容。

## What Changes

- 将补丁版本更新改为先完成全部读取、锚定校验和内容暂存，再提交整组文件；任一目标失败时恢复原始文件并移除本次新建的发行说明。
- 为每个受维护文件定义唯一的当前版本锚点，只更新该事实，不替换示例、历史说明或包含旧版本数字的其他文本。
- 让发行检查验证 HTML 中唯一、可渲染的 `.app-version` 元素；注释、非渲染内容或任意额外版本元素均不能通过检查。
- 为新保存的 Prompt Agent 历史保留明确的分析模式，并只将普通图片反推历史补齐到 Prompt Kit；对缺少模式的旧记录采用结构化、失败关闭的兼容判断。
- 增加失败注入、版本边界、HTML 注释/重复元素、分析模式和旧历史兼容回归测试，并移除发布说明中易过期的固定测试数量。

## Capabilities

### New Capabilities

- 无。

### Modified Capabilities

- `project-maintenance`: 收紧补丁更新的原子性、当前版本锚点和工作台版本 DOM 检查。
- `image-to-prompt`: 限定只有普通图片反推历史可以自动补齐为 Prompt Kit 模板，并明确旧记录兼容边界。

## Impact

- 发行维护：`scripts/release-patch.mjs`、`scripts/check-release-readiness.mjs` 及项目维护测试。
- Prompt Agent：服务端历史写入与归一化、浏览器历史模板同步、公共模块镜像及相关测试。
- 持久化/API：新历史记录增加明确的分析模式事实；既有缺少该字段的记录不要求离线迁移。
- 文档：最终测试完成后移除 `docs/releases/v0.2.7.md` 中易过期的固定测试数量，同时保留可复核的验证命令与结果，不将该快照事实定义为外部行为。
- 不改变商品图采集扩展版本、生成接口、用户自定义模板或既有历史记录内容。
