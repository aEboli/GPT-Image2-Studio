# 套图画面重复优化验证

日期：2026-11-17。

## 观察与复现

只读核对当天 22:40、22:42 创建的两套实际计划，各 20 张。不同生活操作大量使用手部近景、商品大占比及虚化背景，首图、功能图和商业 CG 也多次采用悬浮商品与暖流。这里的观察依据为实际提示词和构图分工，不将提示词审核结果等同于实际成图语义检测。

原实现存在四处缺口：实际提示词只比较完全相同的归一结果；场景被完全排除在构图节奏检查外；通用 Agent 构图在每图重复注入，缺少逐图镜头优先级；动作识别把控制器外观、否定手机/车把及登山杖的“握把”误识别为其它操作。

首次新增 9 项回归，修改前 6 项失败。追加的两项镜头节奏回归、公共商品描述掩盖真实交互的回归和登山杖握把断言也分别在修改前复现失败。

## 修复

- 同实际操作且实际提示词高度近似时进入原有局部文字修复；共同商品描述、真实交互变化与数字差异采用保守判断。只在最终提示词仍含原始撰写内容时使用该内容，避免陈旧元数据覆盖用户修改。
- 同有据功能、同景别、悬浮姿态且效果说明近似的渲染跨图型共用现有两张备选上限。不同有据效果不只因商品悬浮而合并。
- 至少五张自动场景图时，同一可识别景别超过场景数一半（向上取整），只对超出项建议调整人物、环境、主体占比和拍摄距离。不同实际用途仍可共用构图；镜头节奏两轮修复后仍未改善时只保留警告，不把有效用途禁用或减少张数。
- 最终提示词明确给出本图构图优先级，Agent 构图作为整套风格语言；规划指令要求避免整套手部近景加虚化背景，或首图、功能图、CG 反复同一悬浮光效。
- 动作识别排除否定描述；控制器可见不等于按键调温，登山杖握把不等于骑行车把。
- 复用原有最多两轮局部修复、冻结和待调整机制；保持用户锁定、平台限制和严格白底要求。没有新增界面、图片自动重试或额外审核模型。正常合格规划仍只需一次文本规划请求。

## 生效与边界

重启正在运行的本地服务或桌面应用后，重新预览套图并生成，才能使用新规划。历史冻结计划、旧提示词和旧图片不自动改写。本次没有中断当前 3600 服务。

测试使用注入响应和隔离的本地模拟上游，没有调用真实付费生图。去重仍为文本和任务启发式审核，没有新增跨批次历史检索或成图相似度模型；不能据此宣称实际图片零重复。新画面的视觉改善需要重新生成后人工验收。
