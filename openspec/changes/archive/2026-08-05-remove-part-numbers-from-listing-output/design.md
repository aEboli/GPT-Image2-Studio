## Context

Creation Listing 会把商品名、SKU 标题和 SKU ID 作为模型来源，但当前只做品牌、声明和证据清理，没有把结构化来源中的内部货号视为标题禁用词。SKU 图计划器则优先将参考文件名拼入 `filenameToken`，服务端保存时又优先采用该 token，因此参考图货号会进入交付文件名。

这次修改跨越 Listing 规范化、Creation 计划和服务端文件名选择，但不改变 manifest 的 SKU/参考图关联结构，也不重写历史记录。

## Goals / Non-Goals

**Goals:**

- 新生成和重新生成的英文、中文 Listing 标题不包含结构化商品或 SKU 来源中的内部货号。
- 新 SKU 图显示名称和输出文件名不包含 SKU ID、商品货号或参考文件名中的货号。
- 颜色标签可靠时继续提供有意义的 SKU 图显示名和文件名短标识。
- 原始 SKU ID、参考文件名、参考索引、提示词引用和生成关联保持不变。

**Non-Goals:**

- 不清理卖点、描述、搜索词或内部 manifest 字段中的 SKU 标识。
- 不修改商品表面的真实型号文字，也不修改 SKU 生成提示词的主体保真要求。
- 不迁移历史 Listing、历史 `filenameToken` 或已保存图片文件。
- 不通过宽泛正则删除所有字母数字组合，以免误删正常材质、规格或关键词。

## Decisions

1. 货号候选只从结构化标识来源提取。优先读取 SKU `id`、显式标识字段、参考文件名和商品/SKU 标题中具备数字且呈编码形态的 token；清理时按完整 token、大小写不敏感匹配，避免删除自然语言。仅依赖模型理解“货号”的方案不可控，因此提示词约束之外必须有确定性后处理。
2. 仅清理 `title` 和 `zhDisplay.title`。内部标识仍可用于 SKU 去重、参考图匹配和导出，非标题字段保持当前证据/声明清理行为。标题清理后若为空，复用现有标题修复链生成安全商品身份。
3. SKU 显示名使用现有可靠颜色规范化结果；无颜色时固定为 `SKU image {序号}`。不再使用原始标题、ID 或文件名作为用户可见降级值。
4. SKU `filenameToken` 使用 `sku-{序号}`，有可靠颜色时可追加经文件名安全化的颜色 token；绝不采用参考文件名、标题或 ID。服务端仍优先使用 planner 提供的 SKU token，以保证本地与 Worker 路径一致。
5. 原始数据只留在 `skuSubject` 及已有引用元数据中。这样文件名展示与内部关联解耦，不需要新增数据迁移。
6. `creation-listing-agent.mjs` 与 `creation-planner.mjs` 只由本地服务、Cloudflare Worker 和 Node 测试从规范 `lib/` 路径引用；浏览器不直接加载这两个模块，因此本次无需新增或同步 `public/lib` 镜像。

## Risks / Trade-offs

- [普通商品词被识别为货号] → 仅接受来自结构化标识或包含数字的编码形 token，并使用边界匹配；通过中英文标题回归测试约束。
- [货号带连字符或文件扩展名导致漏清] → 对结构化标识先保留去扩展名后的完整复合编码，再补充分段候选并按长度优先清理。
- [货号清理后标题为空] → 从已去除同一批货号的安全来源商品身份修复，仍不可用时降级为 `Product` / `商品`。
- [标题清理后出现双空格或残留标点] → 复用标题规范化，并在清理后收敛空白和首尾分隔符。
- [文件名可读性下降] → 有可靠颜色时保留颜色 token，无可靠颜色时用稳定序号；可读性让位于不暴露内部货号。
- [历史与新记录命名不一致] → 明确采用只影响新生成的兼容边界，避免静默迁移和断开已有路径。
