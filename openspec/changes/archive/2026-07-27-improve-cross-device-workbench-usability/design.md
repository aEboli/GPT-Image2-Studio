## Context

工作台目前通过 `lib/studio-density.mjs` / `public/lib/studio-density.mjs` 根据视口宽度生成 `mobile`、`tablet`、`stacked`、`narrow-desktop` 和 `desktop` 布局模式，`public/app.js` 将结果写入根节点的 `data-ui-layout`，`public/styles.css` 再为各模式切换网格、滚动和密度。现有机制已具备响应式基础，但 `641px–1024px` 一律进入固定平板双栏，手机 `.studio-grid` 又把预览排在设置前，部分共享控件、记录视图和弹层仍使用桌面尺寸或固定视口高度，因此产生窄栏、首屏操作后置、触控困难和内容不可达。

本次变更横跨布局分类模块、共享样式、少量视口同步代码以及浏览器验收，但不改变现有业务状态模型。实现必须与当前未归档的 Creation、Lightbox 等 change 共存，只调整共享响应式契约，不覆盖其业务行为。

## Goals / Non-Goals

**Goals:**

- 让全部现有工作模式在手机、平板竖屏、平板横屏和桌面视口下采用适合当前可用空间的布局。
- 让手机首屏优先呈现输入与主要操作，并为触控环境提供至少 `44px × 44px` 的核心命中区域。
- 统一处理页面级横向溢出、内部滚动、软键盘、安全区和弹层关闭入口。
- 在 resize、旋转和布局断点切换期间保留当前模式、表单、上传、队列、预览与弹层上下文。
- 以代表视口的真实浏览器结果和针对性自动测试共同约束回归。

**Non-Goals:**

- 不重新设计桌面端视觉语言、导航信息架构或工作模式功能。
- 不修改生成请求、队列、保存、Gallery 数据结构、API、Prompt 或后端行为。
- 不通过复制移动 DOM 节点、建立第二份移动端表单或清空状态来切换布局。
- 不引入新的前端框架、CSS 框架或运行时依赖。
- 不在本 change 中实现其他未归档 change 的业务需求。

## Decisions

### 1. 扩展现有布局分类，而非建立独立移动页面

继续以 `getStudioLayoutMode()` 和根节点数据属性作为唯一布局信号，并将视口宽、高、方向和粗指针信息纳入分类。手机保持单栏；平板竖屏明确使用单栏；平板横屏只有在设置栏和内容栏都达到最小可用宽度时才使用双栏，否则退回单栏。桌面阈值和视觉变量保持现有行为。

选择该方案是因为现有模式已经共享同一套 DOM、状态和事件绑定，扩展分类可将影响限制在纯布局层。替代方案是在每个模式中使用零散媒体查询，容易出现断点冲突；另一个方案是创建移动端专用 DOM，会复制状态与事件，增加状态漂移风险。

### 2. 通过网格区域和 `order` 调整视觉顺序，不移动节点

手机端共享工作区使用“设置/操作 → 预览/结果”的网格顺序，并对 Creation、Portrait、Article、PPT、Reference Analysis、Image Decomposition、Image Edit、Quick Blend 等模式逐一确认其设置与输出区域顺序。DOM 中现有表单字段、文件输入和预览节点保持原位；如果 DOM 顺序已经是操作在前，则 CSS 视觉顺序必须与其一致。

这样既满足操作优先，也避免 resize 时销毁文件输入、焦点、队列或预览状态。替代方案是 JavaScript `appendChild` 重排，虽然可见结果相似，但会影响焦点、滚动和第三方事件状态，因此不采用。

### 3. 小视口使用内容约束与显式内部滚动

共享网格轨道统一使用 `minmax(0, 1fr)`，可变内容容器设置 `min-width: 0`，长路径与长文本允许换行；页面根层不得产生横向滚动。缩略图条、标签条、记录选择条等确实需要横向浏览的控件保留局部 `overflow-x: auto`，且其滚动不得扩张页面宽度。

该策略保留高密度工作台需要的局部横向浏览，同时消除由固定宽度、长文本或网格最小内容尺寸造成的页面级溢出。将 `overflow-x: hidden` 无差别用于所有子区域的替代方案会截断操作，因此只在根层做兜底并修正具体溢出源。

### 4. 触控尺寸作用于紧凑布局的核心交互面

在 `mobile` 和触控平板布局中，导航与菜单触发器、主要表单控件、生成/取消/关闭按钮、预览/Gallery/记录/Lightbox 工具按钮和折叠摘要的实际命中区域至少为 `44px × 44px`。图标或文字视觉尺寸可保持紧凑，命中区域通过高度、宽度或内边距扩展；桌面布局继续使用现有密度。

使用布局与输入能力组合，而不是 UA 或设备型号判断，可覆盖浏览器模拟、触控笔记本和平板。所有控件一律放大可能破坏信息密度，因此只覆盖完成核心流程和关闭浮层所需的交互目标。

### 5. 弹层统一使用动态可视高度、安全区和内部滚动

配置抽屉、Prompt Agent、通用弹层、资产面板、PPT 编辑器和 Lightbox 的外层尺寸以 `dvh`/`visualViewport` 可用高度和 `env(safe-area-inset-*)` 计算，内容区使用 `minmax(0, 1fr)` 与内部滚动。标题/操作区保持可见或粘性，关闭按钮不随长内容滚出可视区；操作组允许换行或在自身范围横向滚动。

`public/app.js` 只在浏览器提供 `visualViewport` 时同步一个视口高度 CSS 变量，不持有或重置业务状态；不支持时回退到 `100dvh`/`100svh`。这比固定 `100vh` 更能适应软键盘和移动浏览器地址栏，也避免为每个弹层实现独立尺寸逻辑。

### 6. 验证分为确定性规则测试与真实浏览器验收

在 `test/studio-density.test.mjs` 覆盖代表宽高、方向与布局分类，在现有布局测试中覆盖操作顺序、最小触控目标、根级无横向溢出以及弹层尺寸/滚动契约。随后启动真实应用，在 `320×568`、`390×844`、`768×1024`、`1024×768`、`1366×768`、`1920×1080` 下逐一检查共享工作台和高风险模式，并执行旋转、打开弹层、软键盘和状态连续性路径。

静态测试适合防止关键 CSS/JS 契约被意外删除，真实浏览器用于发现计算样式、内容溢出和遮挡问题。仅依赖截图或仅依赖正则断言都不能充分覆盖本变更，因此两者都必须完成。

## Risks / Trade-offs

- [风险] 共享选择器可能改善一种模式却压缩另一种模式 → 为每类工作区建立模式清单，并在六个代表视口检查核心操作、预览和记录区。
- [风险] 扩大触控命中区会增加小屏纵向长度 → 保持视觉图标尺寸，优先减少非必要间距并允许页面纵向滚动，不把核心按钮缩回 `44px` 以下。
- [风险] 软键盘与 `visualViewport` 在不同浏览器中的行为不一致 → 使用渐进增强的 CSS 变量，保留 `dvh`/`svh` 回退，并在至少一个真实移动仿真环境验证。
- [风险] CSS 视觉排序与键盘/读屏顺序不一致 → 以现有 DOM 顺序为准，只将视觉顺序调整为与“操作在前、结果在后”的语义顺序一致。
- [风险] 当前 worktree 存在其他功能改动，响应式选择器可能发生冲突 → 实施时限制文件和选择器范围，先读取当前版本，并运行相关 change 的现有测试而不回退用户改动。

## Migration Plan

1. 先补充布局分类和响应式契约测试，记录当前代表视口失败项。
2. 调整共享分类、移动/平板网格顺序与触控尺寸，再逐模式修正溢出和局部滚动。
3. 统一弹层动态视口和安全区行为，验证软键盘与关闭路径。
4. 运行针对性测试、public/lib 同步检查、完整测试套件和六视口真实浏览器验收。
5. 本变更不涉及数据迁移；若出现严重回归，可回退本 change 的布局分类、样式和视口同步改动，业务数据与 API 不受影响。

## Open Questions

- 无阻塞问题。平板横屏是否采用双栏由实现中的最小面板宽度判定，并以 `1024×768` 的无拥挤、无截断结果作为验收依据。
