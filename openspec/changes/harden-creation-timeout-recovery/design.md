## Context

Creation Mode 目前为每个条目创建一个生命周期信号。该信号既在客户端 SSE 连接关闭时取消，也在配置的上游流等待期限到达时取消。Responses 流已可能先给出 `response.id`，但在这个共享信号取消后，SSE 消费会直接抛出 `AbortError`，原任务 ID 无法进入既有的 `GET /responses/{id}` 回查路径。

因此，上游任务可能仍在运行或已经完成、但最终图片尚未通过流送达时，套图会把结果视作失败。自动补图随后会依据尝试次数再次 POST，造成重复生成和潜在重复计费。客户端同时允许任意迟到的 `item_status`、图片或失败事件，以及较旧的服务端清单，覆盖已经完成且带正式资产的条目。

用户明确要求保留当前套图并发。恢复窗口必须有界，并且在恢复结束前继续占用该条目的既有槽位，避免本地释放槽位后让仍运行的上游任务与新请求叠加。

## Goals / Non-Goals

**Goals:**

- 已取得 Responses 原任务 ID 的套图项在流等待到期后，只通过有界 GET 回查原任务。
- 客户端关闭仍会立即停止流和回查；流等待到期本身不会取消回查。
- 对流等待到期且未确认结果的条目阻止后台自动补图，但保留明确的手动补图路径。
- 已保存的正式资产在客户端保持终态，直到用户明确开始新的手动生成。
- 不改变套图并发上限、启动间隔、正常成功路径或其它模式的通用未知结果重试语义。

**Non-Goals:**

- 不把套图转换为长期后台任务服务。
- 不假设所有第三方 OpenAI-compatible 服务都支持 Responses GET 回查。
- 不保存 API Key、请求正文或其他敏感凭据到套图清单。
- 不改变用户主动发起的手动补图次数或并发。

## Decisions

### 将流等待与回查取消拆分

套图生命周期产生两个信号。流信号在客户端关闭或流等待期限到达时取消，传给 POST 和 SSE 读取；回查信号只在客户端关闭时取消，传给恢复 GET。流等待到期使用稳定错误码，便于仅在这个原因上进入恢复。

这比延长或移除单项期限更可控：上游流会及时释放，而回查仍有固定上限。恢复阶段保留原任务槽位，因此不会通过本地提前释放把实际第三方并发推高于当前配置。

### 将已知原任务 ID 带过流中止边界

Responses SSE 首次解析到 `response.id` 时通过内部事件上报，并在 abort 异常上附带该 ID 和取消原因。Creation worker 立即把非敏感的回查状态写入清单，不持久化原任务 ID。只有流等待期限导致的 abort 且存在 ID 时，工作流才把 abort 转为 GET-only 恢复；客户端关闭维持取消语义。

### 使用有限的 GET-only 恢复窗口

流等待到期后的回查采用固定两分钟窗口、五秒轮询。恢复 GET 成功时沿用既有最终图片事件和保存路径；上游明确失败、持续处理中、无法读取或不支持 GET 时，返回可审计的结果而不再 POST。该窗口的自身到期是业务结果，不是客户端取消。

通用图像工作流原有的未知结果重试保持默认行为。Creation 传入禁用未知结果 POST 重试的选项，以确保自动路径不会为流 deadline 或任何未确认的 Creation 结果创建第二个上游任务。

### 完整最终图是流读取的充分终态

代理可能已传递完整图片字节，却长期不关闭 SSE 连接或不补发 `[DONE]`。一旦解析到真实最终图，工作流即发送最终图与完成事件、停止读取并取消上游 body；不再等待流关闭或本地期限。只有不含图片字节的工具完成通知仍继续等待，因此不会把渲染已完成但尚未传图的中间状态误判为成功。

### 持久化最小的自动补图保护状态

每个套图项只保存回查状态/原因/状态码、最近检查时间及 `originalResponseAutoRetryBlocked`；原任务 ID 仅在当前请求生命周期内保留，用于 GET 回查，不写入套图清单。这些持久化字段不含 API Key、请求内容或上游响应 ID。收到 ID、进入回查、回查完成和失败都会更新状态；即使到期时未取得 ID，也会设置保护标记，因为上游请求可能已创建但代理没有交付 ID。

自动补图在浏览器和服务端均排除该标记，防止直接调用补图接口绕过前端。用户明确单项手动补图在真正 POST 前清空原任务的保护状态，表示用户接受开始新的生成。

### 保护客户端已保存资产

清单合并优先保留上一份已完成条目的正式资产及其完成态，而不只是中途预览 URL。所有可能把条目改为生成中、排队或失败的套图 SSE 事件，都先检查该条目是否已完成且有正式资产；除非用户发起的本地补图已将其切换为生成中，否则忽略迟到事件。补图请求网络失败时重新同步套图清单，避免本地永久停在生成中。

## Risks / Trade-offs

- [第三方代理不支持 `GET /responses/{id}`] -> 将条目明确标记为未确认且停止后台自动补图，提示用户手动补图；不会猜测性重发。
- [回查增加最长两分钟占槽] -> 窗口固定且只针对已到期的条目；配置并发不变，且避免活跃原任务与新 POST 同时占用第三方容量。
- [代理没有返回 response ID] -> 仍阻止自动补图；用户手动操作是开始新任务的明确确认。
- [客户端收到不同尝试的迟到事件] -> 终态资产保护只拦截本地仍为已完成的条目；手动补图预先变为生成中，允许新尝试正常显示。

## Migration Plan

1. 先部署工作流、清单字段和客户端终态保护，并保持现有配置值。
2. 已存在的清单没有保护字段时按未阻断处理，保持历史补图行为；新到期条目开始写入字段。
3. 如需回滚，移除新调用选项即可恢复旧流终止行为；额外清单字段为可忽略的向后兼容元数据。
