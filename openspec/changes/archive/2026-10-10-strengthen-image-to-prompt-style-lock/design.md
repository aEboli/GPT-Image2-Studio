## Context

普通图片反推的结果会被直接复制到 Studio 提示词框，结构化 JSON 本身就是下游模型的输入。当前 `visual` 只有一个简短字符串，且系统指令明确要求背景和视觉精简；这会让模型把风格信息压缩成少量宽泛形容词。新增顶层字段会破坏现有严格结构和自动模板识别，因此采用兼容性更高的字段内格式。

## Goals / Non-Goals

**Goals:**

- 让 `visual` 成为稳定、可复用的风格锁定段，而不是泛化的画面摘要。
- 让模型保留影响最终像素的具体风格词，并把风格漂移写入 `avoid`。
- 保持旧历史 JSON、模板同步和现有五组结构兼容。

**Non-Goals:**

- 不新增第六个顶层字段或修改历史数据。
- 不根据用户示例硬编码某一种古风、人像或配色风格。
- 不改变图像生成接口、参考图流程或模型选择。

## Decisions

### 1. 在现有 `visual` 字符串中使用显式风格锁定段

`visual` 仍保持字符串类型，并要求以“风格锁定：”开头。模型随后用分号分隔的具体短语覆盖适用的风格维度：整体审美/流派、媒介与渲染、色彩与对比、光线、材质与表面、镜头与景深、后期与氛围。这样下游模型能把整段识别为必须保留的风格约束，旧记录仍可被读取。

### 2. 只提取有图像证据的锚点

指令继续禁止编造品牌、身份和不可见内容。风格词必须来自可见的媒介、服饰、材质、光线、色彩、纹理或摄影效果；不确定时使用保守描述，不用固定的示例风格替代观察结果。

### 3. 用 `avoid` 固定风格边界

`avoid` 除了构图和姿态错误，还要列出当前图像最容易被生成模型替换的风格方向，例如插画/动漫、现代棚拍、白天光线、错误的色彩体系或过度磨皮。它只记录与当前图像相关的偏差，不加入通用质量词。

### 4. 保持公共模块和历史结构不变

只修改源模块后运行 `sync:public-lib`，不手工维护两份实现。已有五组 JSON 继续通过原有归一化和模板资格判断，新增约束只影响新请求的模型指令。

## Risks / Trade-offs

- 风格字段变长会增加输出 token，但能减少再次生图时的风格漂移；指令要求短语具体且去重以控制增长。
- 模型可能把主体细节重复到视觉字段；通过“主体事实只放 subject，风格事实优先放 visual”的规则和测试约束降低重复。
- 对无法可靠判断媒介的图片，风格锁定仍可能较短；失败关闭并保留可见证据比猜测风格更安全。
