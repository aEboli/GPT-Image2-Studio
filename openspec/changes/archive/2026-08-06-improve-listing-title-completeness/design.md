## Context

平台 V1 提示词已经要求证据丰富时写到至少 120 个英文字符，但当前接受策略明确保留任何可用 JSON，短标题不会触发第二次模型请求或本地补全。因此标题长度完全受单次模型服从程度影响。与此同时，SKU planner 已产生安全 `filenameToken`，但浏览器规范化没有保留该字段，临时队列 SKU 也没有生成它，导致服务端存在回退使用显示标题的路径。

## Goals / Non-Goals

**Goals:**

- 有足够、安全、同语言 Listing 文案时，让过短标题达到平台建议下限或可用内容上限。
- 补全后仍遵守平台字符/UTF-8 字节硬上限、通用 500 字符上限与货号清理。
- 封闭 planner、浏览器状态、队列和本地/Worker 落盘之间的 SKU 安全短标识链路。

**Non-Goals:**

- 不增加上游请求次数，不把短标题变成生成失败。
- 不从原始商品描述重新生成新事实，不为凑长度重复同义词或添加通用夸饰。
- 不迁移历史 Listing、历史 `filenameToken` 或已生成图片。

## Decisions

### 1. 在全部安全清理之后做标题补全

先执行现有无品牌、证据词、阻断声明和货号清理，再从同语言的已清理 Listing 字段中收集候选。英文候选顺序为卖点、五点、痛点和描述；中文使用 `zhDisplay` 的同构字段。这样补全只复用本次模型已经生成且通过现有安全边界的内容。

备选方案是因短标题再次调用模型，但这会破坏“可用响应不重试”的现有合同，增加时延与失败面，故不采用。

### 2. 平台建议下限作为修复目标，不作为失败门禁

当标题低于 `recommendedMinChars` 且存在可复用候选时，按词语或短语边界追加不重复内容，直到达到建议下限或候选耗尽。最终始终按 `hardMaxChars`、`hardMaxUtf8Bytes` 与通用上限裁剪。候选不足时保留较短标题并正常完成。

证据丰富且平台允许至少 120 字符时，修复目标提升到 120；低上限平台仍以其建议下限和硬上限为准。中文标题不机械追求 120 个汉字，只补到平台建议下限。

### 3. SKU 文件短标识由序号和可靠颜色唯一构成

planner 与临时队列共用相同规则：`sku-{序号}`，可选追加已由颜色解析器确认并文件名安全化的颜色 token。原始标题、ID、参考文件名只保留在关联元数据和生成提示词中。浏览器 view normalization 必须原样保留 `filenameToken`，服务端和 Worker 继续优先使用它。

## Risks / Trade-offs

- [补全形成长句片段] → 先按句子拆分，再去掉 Bullet 标签和末尾标点，按完整词边界追加。
- [补全重复原标题概念] → 以规范化词组和已存在标题文本去重，候选无新增信息时跳过。
- [清理货号后又被候选带回] → 候选与最终标题都再次经过同一货号清理。
- [低硬上限平台被截断] → 最终统一执行字符与 UTF-8 字节硬上限裁剪。
- [历史记录外观改变] → 只在新生成/重新生成与新队列构建路径执行，不修改读取历史记录的逻辑。

## Migration Plan

1. 添加标题补全和 SKU 队列/浏览器边界失败测试。
2. 实现最小后处理与安全 token 保留。
3. 同步 `public/lib`，运行定向测试、项目测试、构建和 OpenSpec 严格验证。
4. 验证通过后合并增量规格并归档；如需回滚，仅回退代码与规格变更，历史数据无需处理。
