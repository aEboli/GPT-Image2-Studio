## Context

Creation Mode 的 `effect-comparison` 是已保存计划、角色选择和历史任务使用的稳定角色 ID，但它的中文展示名已经是“功能效果渲染图”。当前通用规划提示词、促销和搜索场景提示词、套图分工文本、类目提示词以及平台图片类型策略仍含有比较或分栏语义；这些文本会共同进入生成提示词，因此仅修改某一处不能可靠地消除对比构图。

## Goals / Non-Goals

**Goals:**

- 新计划中的功能效果渲染图以一个完整可见、占主导的商品主体为视觉锚点。
- 用有证据支持的箭头、局部剖视叠层、动态轨迹、能量或材质流向等方式，围绕同一主体展示全部已提供的功能、机制、效果路径或结果。
- 在通用、促销、搜索及平台原生计划中一致禁止对比构图。
- 保持角色 ID、平台图片类型 ID 和已保存计划兼容。

**Non-Goals:**

- 不重写已保存任务中的历史提示词或已生成图片。
- 不改变多款式/SKU 选择图等本来需要比较的角色。
- 不凭空补充未提供的性能、技术结构、参数、认证或效果。

## Decisions

1. 保留 `effect-comparison` 与 `comparison-proof` 作为内部兼容 ID，只将其展示标签和构图语义改为功能效果渲染。重命名 ID 会使历史计划、覆盖项和平台预设失去可解析性，收益不足。
2. 在规划器中为该角色写入正向的“单一主体、统一构图、展示全部已提供功能”要求和明确的版式禁令；平台原生槽位也必须接收该角色约束。只修改角色 `brief` 无法覆盖场景、套图分工和平台策略注入的相反文案。
3. 将促销、搜索和类目层的该角色特定文案替换为功能可视化语义；平台图片类型的构图从 `side-by-side-functional-evidence` 改为 `single-product-functional-rendering`。这样平台规划传递的构图字段与角色提示词不冲突。
4. 用规划器测试覆盖通用、促销、搜索和平台原生路径，并断言正向文本存在、被禁止的布局词不存在；平台策略测试覆盖稳定图片类型 ID 与新标签、构图值。

## Risks / Trade-offs

- [图像模型仍可能偶发生成不符合提示词的布局] → 在所有输入路径添加明确禁令，并使计划预览可复核最终提示词。
- [内部 ID 仍含 comparison 单词] → 仅把它作为兼容键，不将其作为用户可见标签或模型构图指令；测试锁定新的展示与构图值。
- [旧任务重试沿用历史 prompt] → 不静默改写用户保存的任务；新建或重新规划任务使用新规则。
