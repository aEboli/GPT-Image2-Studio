## Context

`lib/creation-product-insights.mjs` 的场景规范化只判断环境与动作字符串，分配器用余数循环场景。`buildCreationProductInsightPrompt` 用图片序号对买点取模，不知道其他图片已经选了什么；同一函数为卖点总览只返回一个买点。`lib/creation-planner.mjs` 在存在分析时省略原有事实分配，却保留角色模板和部分用途提示，因此可能同时出现“本图只有尺寸证据”和“画充电步骤”。

现有 `test/creation-product-insights.test.mjs` 的 2 个用例通过，但主要确认来源有效和环境名称不同，没有覆盖相同核心动作、信息覆盖或版式与事实的一致性。这次需要围绕可见任务增加回归，不以提示词字符串不同作为达标证据。

## Decisions

### 继续使用现有分析请求，明确操作组

在候选场景上增加可选的 `actionGroup`／识别 JSON 的 `action_group`，相同核心操作必须共用同一标识。环境变化、手机应用变化和准备前后不拆分操作组。运行时保留旧分析兼容：缺少该字段时使用规范化后的动作与交互对象做保守判重；无法可靠判断的项标记待核对，不能直接轮询视为新场景。不能把相同 `factIds` 直接认作相同动作，例如相机按键与牵引绳握持可以使用同一个手部灵活性依据。

### 先安排整套任务，再生成提示词

在现有规划入口内完成分配，逐图保留任务摘要、事实 ID、买点 ID、表达形式和可选场景 ID／操作组。不是再新增一个串行 agent。实际传给单张生成的角色、参考来源、证据和版式必须来自同一份分配；冻结计划、队列和补图复用它。

先满足首图及有依据的尺寸／信息表达，再安排可见细节、视角和不同真实用途。自动方案中同一核心操作最多作为一张普通轮播图的主任务；主图小插图可以摘要复用，但不得再成为另一张完整操作照。

### 主套图承担自己的信息覆盖

信息图是独立表达任务，不是任何带文字的照片。在资料充分时，6–10 张自动方案至少包含 2 张、12–18 张至少包含 3 张；每张必须有不同的主要信息任务。附加信息图重构不抵扣，避免前面生成大量重复照片、把信息表达全推给尾部。

此门槛受资料约束。只有一条可靠卖点时，不能拆成三张近义信息图；没有操作步骤不能选步骤版式，没有可靠内部结构不能选爆炸图。无法满足的配比与缺少的资料要展示出来，不生成占位内容。

### 自动替换与用户选择分开处理

默认三张 `scene-fit` 不再无条件占位；不同行为不足时，可以改用现有的信息／细节角色。被替换项使用实际图型和标题，并保留稳定的槽位身份用于界面、文件与队列对位。详细任务而非角色名决定内容是否重复，兼容注册表中的图型 ID 不因本提案删除。

手动选择或填写提示词的项目不自动改写；只展示重复与覆盖提示。平台主图禁字、SKU 来源、尺寸缺数据拦截及商品身份锁继续优先。旧记录不会在读取或补图时被套用新规划。

## 加热手套的可审阅分工示例

下表是任务示例，不是保证必须生成的固定模板。资料与当前主主体绑定不明确或存在冲突时，先排除对应条目；现有材料不足以支持 18 个独立任务时，建议收敛张数。

| 任务 | 表达形式 | 与其他图片的分工 |
| --- | --- | --- |
| 商品主视觉 | 完整一双的产品主图与一项主卖点 | 负责识别和摘要，不罗列全部信息 |
| 加热与电池关系 | 产品局部加功能标注 | 只使用已确认文字和可见部位，不虚构剖面 |
| 电量／续航参数 | 简洁参数卡或对应关系图 | 数值及适用关系无冲突才启用，不再重复完整主图 |
| 指尖操作方式 | 一个操作过程的说明图 | 与场景照分工，只有状态／步骤有依据才展开 |
| 控制器细节 | 显示窗和按键近景 | 证明可见结构，不猜按键功能和档位 |
| 掌心与腕口细节 | 两处不同局部的标注板 | 不把纹理自动写成防滑性能 |
| 尺寸规格 | 可靠宽高和单位的尺寸图 | 独立覆盖规格，不把它误分配成充电卖点 |
| 产品多视角 | 清晰的正反面或侧面展示 | 与两张相似桌面平铺区别开 |
| 真实操作场景 | 一张手机操作照 | 全套只保留一次手机操作主任务 |
| 准备或穿戴场景 | 袖口关系或实际穿戴尺度 | 与手机动作不同；不再复制手机到新背景 |
| 到手内容 | 已确认的一双手套清单 | 配件不明确时不新增电池、线缆或赠品 |

## 实现边界

- 在 `lib/creation-suite-content-plan.mjs` 内完成确定性的整套分配，不增加模型请求。新的分工在存在有效商品事实分析时启用，未分析的旧调用继续使用兼容路径；旧分析中的手机近义动作会合并，其他未提供操作组的旧动作提示用户核对或重新识别。
- 自动分配先保留已有角色的信息任务，再以其他有依据的信息任务替换空缺或过量场景。尚有不同的主主体外观事实时可以补充局部近景；辅助变体外观不作为新的主体细节任务，纯尺寸核对不作为新的场景。
- 逐图 `contentAssignment` 保存任务、事实、表达形式与来源文本，预览、队列、记录和补图复用同一份。参考图选择与标签只使用该任务分配的辅助事实，防止整段旧备注重新引入其他卖点。
- 手选角色不受保底角色替换；仅更改图片张数不再被当成用户手选全部角色。逐图手写提示词继续优先，仍保留尺寸和真实 SKU 的既有来源约束。
- 预览在现有计划区域提供可展开的“逐图内容分工与依据”，并展示替换、跳过和资料缺口。

## Risks / Verification

- 操作组依赖分析准确性，必须同时验证提示词要求、运行时分配和预览可见结果。只加一句“多样化”不能视为修复。
- 内容充分性比张数和信息图比例优先，允许明确缺口，不承诺任何商品都能凑满 18 张。
- 用 3 个手机近义候选场景与重复循环的脱敏夹具做失败用例；再验证真实不同动作不会因共享事实而被误删。
- 验证卖点总览收到多项匹配事实，尺寸不会误进入操作步骤，原有冲突过滤与主主体保护不退化。
- 真实图片验收与规划、模拟端点验证分开记录；本轮不使用真实图片生成额度。
