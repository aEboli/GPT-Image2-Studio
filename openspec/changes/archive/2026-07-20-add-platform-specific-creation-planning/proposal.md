## Why

当前套图模式虽然已经提供 19 个平台选项，但平台差异只体现在附加提示词上，图片类型、顺序、张数、比例、分辨率、语言和生成管线参数仍沿用同一套默认逻辑。这会让 Amazon 白底主图等严格要求与现有通用首图模板直接冲突，也无法生成淘宝长图、小红书 3:4 封面等平台原生资产。Listing 入口虽已对所有平台开放，生成器仍固定使用 Amazon US English、数量前置标题、恰好五条要点和后台搜索词契约，非 Amazon 平台实际得到的仍是 Amazon 文案。

## What Changes

- 增加版本化、结构化的平台策略注册表，为通用电商及 18 个平台分别声明默认图片类型、顺序、推荐张数、逐图比例、分辨率档位、语言、构图、文字密度、SKU 规则、来源和证据等级。
- 将平台原生图片类型及逐图 Logo 策略设为计划项的一等字段，并保留现有 Creation 角色 ID 作为内容意图和历史兼容字段。
- 增加统一策略解析器，按“通用基线 < 平台策略 < 平台与类目覆盖 < 参考图覆盖需求 < 用户手动覆盖”生成最终计划，并在用户覆盖后验证图片类型绑定的官方硬规则。
- 所有 19 个平台自动方案至少保留一个尺寸或真实尺度图片槽位；没有精确尺寸依据时仍保留该用途，但禁止编造数值，只能使用已提供的尺寸或不带数值的可验证尺度/适配表达。
- 让每个轮播项的最终提示词直接携带当前平台 profile 的专属图库策略，而不是只套用通用角色 brief；共享执行管线不再等于共享图片策划。
- 将版本化、可序列化的 `effectivePlan` 设为预览、生成、队列、manifest、记录和修复共用的冻结契约；未经用户实际操作的表单默认值不构成覆盖，所有保留的套图级和兼容图片类型覆盖应用后都必须重新校验，执行边界必须拒绝 `canGenerate=false` 的计划。
- 区分平台 `recommendedCarouselCount`、证据解析后的 `automaticCarouselCount`、用户覆盖后的 `effectiveCarouselCount`、用户增减量以及最终总请求数；通用电商保留原有 18 个原生轮播槽位，命名平台以内置槽位数作为数量控件上限；缺少事实证据时优先安全替换槽位，只有没有安全替换时才减少命名平台的有效张数并显示原因，不再用跨平台或 `custom` 槽位把命名平台扩展到固定 18 张。
- 支持每张计划图独立使用比例、分辨率和语言；用户在套图控件中显式选择的目标语言、比例和分辨率必须冻结为套图级覆盖并应用到每张轮播图，本地服务与 Cloudflare Worker 共用同一解析结果和生成行为。
- 保留套图级快捷覆盖和兼容图片类型启停；移除逐图高级编辑和所有面向用户的套图提示词编辑、微调及覆盖入口，计划提示词只由规划器依据商品事实和平台策略生成。
- 平台切换前要求用户确认；确认后仅重置平台相关自动值和覆盖，保留商品资料、类目、尺寸、参考图、风格图、Logo、SKU、输出格式和模型/API 配置，取消则完整恢复原状态。
- 对参考图分析增加平台/类目请求版本校验，防止旧平台异步结果回写到新平台状态。
- 在队列快照和 Creation manifest 中持久化策略版本、平台 provenance、有效覆盖、轮播/SKU/重构计数及逐图参数；旧记录保持原计划，不因策略升级漂移，只有显式重新规划才使用新策略。
- 让当前可编辑表单的“套图数量”始终与当前计划的轮播图数量一一对应；后台生成或选中的队列快照保持独立冻结，不得用旧任务计数覆盖当前表单摘要。
- 用户修改“套图数量”后立即请求新计划；生成操作必须等待该次最新预览完成，并在第一次提交时冻结修改后的数量。
- 用户启停 SKU 图后立即刷新当前平台计划；该开关只改变追加 SKU 项和总数，不得清空或改写平台轮播槽位、轮播数量及兼容图片类型列表，也不得在刷新期间回退为通用电商角色列表。
- 计划面板隐藏“缺失证据槽位已省略/安全替换”和“自定义槽位已补足张数”这类例行内部调整，对仍需用户处理的警告去重展示，同时保留未知平台、能力不足和阻断校验反馈。
- 对官方规则不足的平台使用可见的保守建议和较低证据等级，不把推断标记为官方硬约束，也不在运行时抓取平台网站。
- 所有 19 个 canonical 平台及旧记录均可进入 Listing Agent；新增独立、版本化的 Listing policy registry，以 5 个跨类目 archetype 复用基础策略，并为 19 个平台分别声明 locale、标题、高亮、描述、搜索面、转化顺序、来源和证据等级覆盖。
- 新生成和显式重写的 Listing 统一恢复旧版字段合同：`title`、`sellingPoints`、`painPoints`、`fiveBullets`、`description`、`backendSearchTerms`、`keywordBuckets`，并保留结构同构的简体中文 `zhDisplay`；旧 V2 草稿只在视图层映射，不批量改写历史存储。
- 19 个平台继续使用各自版本化 policy、locale、写作顺序、搜索意图和内容侧重点；平台差异只影响提示词和字段内容，不改变旧版字段名、展示顺序或复制/导出结构。
- 全部新内容统一禁止品牌、商标、店铺、卖家和平台名称。source builder 在请求前剥离禁止词，model、mock 和确定性 fallback 在返回前执行无品牌净化；该要求是本产品硬规则，不冒充任何平台官方规则。
- Listing 只调用模型一次，不做 validator 驱动的重试、人工审核、`needs-review`、失败重写或复制/导出门控。模型请求或解析失败时直接返回 `completed` 的旧版确定性 fallback；缺少 API 配置仍作为明确配置错误返回。
- 成套采用/淘汰审核、可持久化的暂停/取消/重排队列、商品版本管理、多平台差量派生和生成后视觉/OCR 质检留作后续独立 change，不扩入本次平台规划变更。

## Capabilities

### New Capabilities

- 无。

### Modified Capabilities

- `creation-mode`: 从统一角色切片和整套共用参数，调整为版本化平台策略驱动的图片类型规划、逐图生成参数、手动覆盖、平台切换、持久化与兼容行为。
- `creation-listing-agent`: 在全平台可用的入口上保留版本化平台文案策略，并统一恢复旧版英中对照字段、直接完成状态、无品牌净化和本地/Worker 一致性。

## Impact

- 规划与策略：`lib/creation-planner.mjs`，以及新增的平台策略和策略解析模块。
- 浏览器交互：`public/app.js`、`public/index.html`、`public/styles.css`，包括平台摘要、覆盖状态、可排序图片槽位和切换确认；浏览器使用的平台模块通过 `scripts/sync-public-lib.mjs` 从 `lib` 精确镜像到 `public/lib`。
- 生成路径：`server.mjs`、`cloudflare-pages-worker.mjs`，改为按计划项解析并提交比例、分辨率与语言。
- 队列、修复与存储：`lib/creation-suite-queue.mjs`、`lib/creation-repair.mjs`、`lib/creation-store.mjs`。
- Listing：共享 Listing policy registry 继续决定各平台内容策略；草稿 schema、提示词、fallback、记录页展示、复制和导出恢复旧版字段合同，本地服务与 Worker 继续调用同一实现。
- 测试：平台策略、解析优先级、规划器、浏览器交互、队列、存储、修复、本地/Worker 一致性和端到端回归测试。
- 现有未提交平台功能属于本变更的实施基线，实施时必须保留并最小化修改用户当前脏工作树中的其他改动。
