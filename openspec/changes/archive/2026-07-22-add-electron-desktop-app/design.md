## Context

项目当前由 `server.mjs` 在固定回环端口启动本地 HTTP 服务，浏览器负责呈现 `public/` 工作台。现有 IExpress 安装包会携带独立 `node.exe`，通过 `.cmd` 启动服务后打开系统浏览器；它可以免环境安装运行，但不是独立窗口桌面应用，并且启动器把服务作为脱离进程运行。

桌面封装必须复用现有页面、API、文件存储和生成逻辑，不能建立第二套业务实现。它还必须与本地 Node.js、Cloudflare/Vercel 和旧安装包入口共存。应用会处理 API Key、本地图片和生成记录，因此渲染进程权限、导航边界、数据目录和退出清理属于本变更的核心约束。

## Goals / Non-Goals

**Goals:**

- 提供具有独立窗口、应用图标、任务栏身份、单实例和标准安装卸载体验的 Windows 桌面程序。
- 直接复用现有本地服务与浏览器工作台，并让桌面进程确定地管理服务启动、就绪和关闭。
- 使用动态回环端口，避免与现有 `3600` 服务或其他应用发生端口冲突。
- 保持渲染进程无 Node.js 权限、隔离上下文并限制导航、新窗口和外部协议。
- 让配置、Electron 会话和窗口内本地存储写入用户可写目录，并在应用升级后保留。
- 保留现有 Web、CLI、云端及 IExpress 构建行为，并提供可自动验证的桌面启动与安装包产物。

**Non-Goals:**

- 重写页面、API、生成流程、存储格式或引入桌面专用业务功能。
- 在本变更中提供自动更新、崩溃上报、托盘常驻、多窗口或文件协议关联。
- 在本变更中购买或配置 Windows 代码签名证书。
- 自动迁移其他浏览器 profile 的 `localStorage`、IndexedDB 或缓存。
- 替换当前 IExpress 安装包或删除浏览器启动方式。

## Decisions

### 1. 使用 Electron 直接承载现有本地工作台

新增一个最小 Electron 主进程，在现有 HTTP 服务就绪后用 `BrowserWindow.loadURL()` 加载回环地址。页面仍从 `server.mjs` 提供，因此相对资源、API、SSE、上传、下载和输出目录操作继续走同源路径，不需要 `file://` 适配或渲染层 IPC。

选择 Electron 而不是 Tauri，是因为当前后端和依赖均为 Node.js，Electron 可直接加载现有模块；Tauri 仍需携带 Node sidecar 或重写后端。选择 HTTP 同源加载而不是 `file://`，是为了保留现有 API 契约并避免扩大本地文件访问权限。

### 2. 后端与 Electron 主进程同进程运行

桌面主进程在导入 `server.mjs` 前设置 `HOST=127.0.0.1`、`PORT=0` 和桌面数据目录。`server.mjs` 在监听完成后导出实际 URL、服务实例和关闭函数；Electron 等待导入完成再创建窗口，并在退出前关闭 HTTP 服务及活动连接。

选择同进程导入而不是派生 Node 子进程，可以直接复用 Electron 内置 Node 运行时、减少一份运行时和跨进程就绪协议，并从结构上避免遗留孤儿服务。代价是服务与 Electron 主进程共享 Node 事件循环；现有服务主要是异步网络与文件工作，当前负载可接受，后续若出现可复现的主进程阻塞再单独迁移到 utility process。

为了保持命令行兼容，`node server.mjs` 仍会自动监听并保持运行；新增导出只补充生命周期可观察性，不要求现有调用方改造。

### 3. 使用系统分配的动态回环端口和桌面用户数据目录

桌面模式传入端口 `0`，由操作系统分配空闲端口，并从 `server.address()` 得到最终 URL。主机固定为 `127.0.0.1`，不暴露局域网监听。`IMAGE_STUDIO_LOCAL_DATA_DIR` 指向 Electron `userData` 目录，图片输出继续使用现有默认 `Pictures` 根目录或用户环境覆盖。

动态端口避免扫描固定端口及误连另一个项目。Electron 会话数据和服务端私有配置都位于稳定的用户目录，应用更新不会覆盖；旧 IExpress 安装目录中的配置不自动移动，以避免未经确认覆盖现有配置。

### 4. 使用单窗口最小权限安全模型

窗口显式设置 `nodeIntegration: false`、`contextIsolation: true`、`sandbox: true`，不提供 preload 或 IPC 桥。窗口仅允许与启动时确定的本地 origin 同源导航；新窗口一律拒绝。代码使用 `URL` 解析器判断目标，只将明确列入允许范围的 HTTPS 链接交给 `shell.openExternal`，拒绝其他协议、主机和用户构造的任意外链。

主进程使用 `app.requestSingleInstanceLock()`。第二次启动不创建服务或窗口，只恢复、显示并聚焦现有窗口。服务启动或页面加载失败时展示可理解的错误并退出，不留下空白窗口。

### 5. 使用 Electron Builder 生成按用户安装的 NSIS 包

新增 `desktop` 开发启动、桌面冒烟测试和 `build:desktop` 脚本。Electron Builder 只打入运行所需的 `desktop/`、`server.mjs`、`lib/`、`public/`、生产依赖和许可/说明文件，输出到忽略提交的 `artifacts/desktop/`。Windows 目标使用 x64 NSIS、按用户安装、可选择安装目录，并创建桌面和开始菜单快捷方式及卸载入口。

应用图标从现有 CSS 品牌标记确定性渲染为 PNG/ICO，避免引入与当前品牌不一致的新 Logo。安装包文件名包含产品名、版本和架构，与现有 IExpress 产物区分。

新增 Electron 开发依赖后，旧 IExpress 构建不得继续复制根目录的完整 `node_modules`，否则会把 Electron 和打包工具链带入浏览器安装包。旧构建改为在其 staging 应用目录运行 `npm ci --omit=dev`，仍携带现有生产依赖但排除所有桌面开发依赖。

### 6. 分层验证桌面契约和真实产物

Node 测试覆盖服务动态端口/关闭、URL 安全判定、单实例和窗口安全配置的静态契约、打包文件白名单及中文文档入口。Electron 冒烟模式实际创建窗口、加载真实首页、保存截图并自动退出；构建后再运行未打包和打包应用，确认标题、页面非空、单实例聚焦和退出后无监听端口。

## Risks / Trade-offs

- [Electron 安装包明显大于旧 IExpress 包] -> 只打入 x64 目标和运行必需文件，并在文档中说明体积来源；不为缩小体积重写后端。
- [桌面开发依赖污染旧 IExpress 产物] -> 旧构建在隔离 staging 中按 lockfile 只安装生产依赖，不复制根 `node_modules`。
- [未签名安装包触发 Windows SmartScreen 提示] -> 明确记录未签名状态和 SHA-256 校验方式；代码签名作为独立发布工作处理。
- [ASAR 内文件读取或第三方模块与打包后路径不兼容] -> 先用默认 ASAR 构建，执行打包应用冒烟；仅对实际失败的原生或可执行资源使用 `asarUnpack`，不整体关闭 ASAR。
- [应用退出时仍有生成请求] -> 关闭窗口即表示退出，主进程先关闭窗口再停止服务连接；当前任务数据仍按现有保存时机处理，不声称恢复未完成的上游请求。
- [外链白名单遗漏合法页面] -> 默认拒绝比默认放行更安全；通过单独更新允许列表和测试添加必要静态链接。
- [同进程任务造成主进程短暂阻塞] -> 保持本次最小封装并通过真实工作台冒烟验证；有性能证据后再迁移到独立 utility process。

## Migration Plan

1. 先补充服务生命周期和桌面安全契约测试，记录当前缺失行为。
2. 修改 `server.mjs` 暴露实际监听信息和关闭函数，确认现有 Node 启动与 API 测试不变。
3. 增加 Electron 主进程、品牌图标和 Electron Builder 配置，完成未打包桌面冒烟。
4. 构建 NSIS 安装包并运行打包应用，检查快捷方式、窗口、数据目录、单实例和退出清理。
5. 保留旧启动与安装入口；回滚时可移除 Electron 入口、依赖和构建配置，服务生命周期导出对现有调用方无破坏性。
