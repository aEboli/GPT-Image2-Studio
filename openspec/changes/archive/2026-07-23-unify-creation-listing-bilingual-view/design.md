## Context

Creation 记录中的 Listing 草稿使用共享渲染模块输出七个固定字段。当前实现把字段包在 `copy` 与 `search` 两个分组中，通过 `state.creation.listingSectionMode` 控制可见组；同时使用 `listingLanguageMode` 在英文、中文和双语之间切换，并在宽屏把双语值排成左右两列。字段数据、独立语言复制、完整复制和导出均已有稳定契约，本次只调整记录页的展示与交互。

## Goals / Non-Goals

**Goals:**

- 七个 Listing 字段按既有顺序在同一页面连续可见。
- 每个字段及列表条目固定为英文在上、对应简体中文紧接在下。
- 删除内容分组和语言视图切换及其会话状态。
- 保留中英文独立复制、字符数、完整复制、导出、生成与历史草稿兼容性。
- 桌面、堆叠和移动布局采用同一纵向双语顺序。

**Non-Goals:**

- 不修改 Listing 提示词、生成、验证或文案规则。
- 不修改 JSON schema、API、持久化、完整复制或导出载荷。
- 不补写历史草稿中不存在的中文内容。
- 不调整 Creation 图片结果、记录筛选或其他资产页面。

## Decisions

### 1. 固定双语单页视图不再保存视图状态

删除语言/内容模式常量、状态读写、分段控件和控件事件委托。渲染函数始终创建双语内容，因此重渲染无需恢复视图状态，也不会留下已不可操作的 `listingLanguageMode` 或 `listingSectionMode` 分支。保留模式状态但把控件隐藏会造成不可见状态继续影响渲染，因此不采用。

### 2. 七个字段直接按固定顺序加入同一内容框

标题、卖点、痛点、五点描述、商品描述、后台搜索词、关键词分组直接成为同一 `creation-listing-content-frame` 的连续子项。这样搜索字段自然位于商品描述下方，同时避免无可见标题的分组容器让样式再次从“第一个字段”开始计算。

### 3. 每个双语复制对始终使用纵向排列

`creation-listing-copy-pair` 固定为单列；中文目标使用上边框和上间距与英文建立紧邻关系。删除基于语言模式、屏幕宽度和 `data-ui-layout` 的双列/单列分支，保证宽屏也不会回到左右对照。若历史字段没有中文值，仅显示英文，不生成占位翻译。

### 4. 复制与导出契约保持不变

继续使用现有 `data-creation-listing-copy-text` 事件委托和语言标记。每个字段仍显示英文与中文字符数及独立字段复制按钮；逐条点击只复制当前语言，完整复制与 JSON 导出仍覆盖七字段双语映射。

### 5. 共享模块继续由源文件同步

只编辑 `lib/creation-listing-view.mjs`，再运行 `npm run sync:public-lib` 生成 `public/lib/creation-listing-view.mjs`，避免浏览器副本漂移。

## Risks / Trade-offs

- [单页内容比切换视图更长] → 保留 Listing 工作区粘性操作栏，并维持紧凑字段分隔样式。
- [用户误解上下两段的语言] → 保留 `EN`、`中文`字符数和“复制英文 / 复制中文”字段按钮，中文继续使用差异色和分隔线。
- [历史草稿缺少局部中文] → 只呈现实际存在的中文值，不合成或伪造内容，其他字段仍正常连续显示。
- [移除状态后残留事件分支或样式] → 增加源码和样式回归，明确禁止视图控件、状态选择器和双列网格。

## Migration Plan

1. 先更新渲染与布局回归，固定七字段顺序、无切换控件和纵向双语 DOM 顺序。
2. 移除视图状态/控件逻辑，扁平化字段容器并调整纵向样式。
3. 同步公共模块并运行定向测试、全量测试、Pages 构建和严格 OpenSpec 验证。
4. 在真实 Creation 记录中核对桌面和窄屏；回滚仅需恢复展示层文件，无数据迁移。
