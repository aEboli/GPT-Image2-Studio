## Context

Creation 参考分析当前以 `sku_subjects[].color_names` 返回每个完整产品单位的颜色。该数组在模型输出端具有“一单位一项”的顺序语义，但后续归一化会把数组拼成逗号字符串，再按逗号拆分。与此同时，分析提示只要求主导色并排除共有中性色，最终既丢失黑色带子等真实部件色，也无法可靠区分“一个单位的多个特征色”和“多个单位各自的颜色”。

## Goals / Non-Goals

**Goals:**

- 每个完整产品单位保留一个完整特征颜色标签，标签可包含多个颜色及必要部件名。
- 端到端保留 `color_names` 的数组项边界和单位顺序。
- 对旧 `colorName` 字符串载荷保持兼容，并继续在证据不足时不生成标签。
- 最终生图提示要求将完整标签翻译为目标语言，不得漏掉标签中的中性部件色。

**Non-Goals:**

- 不修改 SKU 主体识别、SKU 数量、参考图角色或同 SKU 组合数量逻辑。
- 不增加独立的颜色编辑控件、颜色词典服务或材质识别能力。
- 不保证实际图像模型的排版质量；本变更保证分析数据和生成提示完整传递。

## Decisions

### 1. 数组项表示完整单位标签

`color_names` 的每一项继续对应一个完整可见产品单位，但单项内容从“单一主导色名”扩展为“完整特征颜色标签”。例如单个护目镜使用一项 `brown, black, silver lenses`，而不是三项颜色。

内部 SKU 载荷增加 `colorNames` 数组以保存该边界，同时继续投影 `colorName` 字符串供历史记录和旧调用方兼容。选择兼容扩展而不是替换字段，可避免现有 manifest、修复请求和前端状态失效。

### 2. 数组输入保留边界，旧标量按单位数兼容解析

归一化遇到数组时不再拆分数组项内部的逗号，也不去重相同数组项，因为两个完整单位可以拥有相同标签；遇到旧标量时，单单位把完整字符串视为一个标签，多单位继续按现有分隔符拆分。这样新数据无歧义，历史多单位颜色字符串仍可工作。

### 3. 分析覆盖关键可见部件色而非只取主导色

视觉分析提示要求纳入所有清楚可见、对主体外观有辨识价值的物理部件色，包括黑色带子、灰色边框等共有中性色；仅在颜色词可能混淆所指部位时添加简短部件名。背景、阴影、高光、镜面环境反射、主体外文字和不确定颜色仍排除。

### 4. 生成提示消费完整标签

单单位提示使用完整的一项结构化标签；仅在缺少结构化标签而从历史说明推断时，才将同一主体识别出的多个颜色合并为一个标签。多单位提示按数组顺序逐项绑定，不把标签内部颜色拆成多个单位。提示要求在目标语言中呈现完整含义，而不是把英文证据字符串与“精确原文”同时强制给图像模型。

## Risks / Trade-offs

- [历史多单位 `colorName` 字符串无法区分项内逗号] -> 仅对新 `colorNames` 数组提供无歧义保证；历史标量维持原拆分规则。
- [视觉模型可能把镜面反射误判为镜片颜色] -> 提示区分物理表面色与环境反射，并允许证据不足时返回空数组。
- [特征色过多导致标签过长] -> 要求只保留关键可见部件色和必要的短部件名，不输出材质说明或营销描述。
- [非英语目标语言翻译丢词] -> 生图提示明确要求翻译整条标签并保留每个颜色与部件限定词，自动测试验证提示约束；真实出图质量另行实测。

## Migration Plan

1. 增加视觉分析、SKU 载荷和规划提示的失败测试。
2. 扩展分析契约并贯通结构化 `colorNames`，保留旧 `colorName`。
3. 同步公共浏览器模块，运行定向和全量验证。
4. OpenSpec 严格验证通过后合并增量规格并归档。
