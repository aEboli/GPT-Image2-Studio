## Why

平台 V1 已要求标题加入证据支持的卖点和痛点解决表达，但实际套图记录可能没有手填 `productDescription` 或 `sellingPoints`。套图规划已经在逐图 `conversionIntent` 中保存了买家动机、使用语境和证据重点，Listing source 却在压缩逐图数据时丢弃这些字段；提示词同时保留“标题只能写客观属性”和“所有字段禁用功能表达”的旧措辞，导致模型继续返回数量、结构和颜色组成的属性标题。

## What Changes

- 从套图逐图 `conversionIntent` 中提取紧凑、可追溯的标题价值证据，供 Listing 标题使用。
- 明确区分可用于标题的买家动机/使用语境/证据重点与仅表示缺失信息的 objection，不把未核实疑虑写入标题。
- 消除平台 V1 提示词内部冲突：标题必须在有价值证据时表达一个卖点及其解决的买家问题；功能词禁令继续严格作用于所有非标题字段。
- 保留旧式双语字段、固定五点、单次模型请求、高风险声明门禁和确定性回退。

## Capabilities

### New Capabilities

- 无。

### Modified Capabilities

- `creation-listing-agent`: 当手填卖点为空但套图规划包含可追溯价值证据时，标题仍必须表达证据支持的卖点和痛点解决关系。

## Impact

- Listing source 构建：增加紧凑的标题专用证据字段。
- 平台 V1 提示词：将旧功能词禁令精确限定到非标题字段，并强化有证据时的标题必选规则。
- 测试：增加真实折叠手拉车式空描述/空卖点记录的 source 和请求提示词回归覆盖。
- 不迁移历史 manifest；用户重新生成 Listing 后才写入新标题。
