## 实现结果

- 文本请求统一通过 `requestStreamingText` 启用流式传输：Responses、Chat Completions 与现有 Gemini 兼容分支均消费回答分片。Chat 请求按协议转换 messages 与结构化格式；Gemini thought 和推理字段不进入进度。
- 分析、营销、Listing、翻译、文章与 PPT 文本链路已接入真实进度。旧 JSON 客户端仍得到完整 JSON；缓冲网关显示实际缓冲状态。展示草稿不作为生成输入。
- 识别前端不再循环三次重放；结构化格式回退和完整 JSON 修复共享一次重试预算。正常规划一次，失败时最多两次上游 POST。
- 已确认有效的分析使用 items-only schema，复用事实 ID。相同会话、输入、模型配置和参考内容合并在途请求并短暂复用结果；有效冻结计划生成与补图不再次规划。
- 营销条目保存用途、场景、动作、景别和证据焦点；近义购买问题与重复动作/证据表达给出软诊断。主体锁及平台/手工约束继续有效，不为诊断发起额外模型调用。
- 分析师和营销面板按生图区定位，桌面宽度约为该区域的 88%、最大 1440px、高度最多为视口的 82%；正文 15px，窄屏单列。实时草稿保留节点与滚动位置，最终态收起实时草稿区以突出结构化结果。
- 上游请求头和营销记录保留随机请求关联 ID、真实尝试数与首个回答耗时，不记录 API Key、原始图片或私密推理。
