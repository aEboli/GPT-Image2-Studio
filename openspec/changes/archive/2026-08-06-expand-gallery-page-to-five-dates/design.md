## Context

普通画廊当前先按日期生成 section，再以两个 section 为一页。桌面缩略图尺寸由当前两天共同计算：每组最多分配三行，得到截图中的 `2 张 -> 4 列/1 行` 与 `15 张 -> 8 列/2 行`。如果只把分页数量改成五，再把五天一起交给现有布局函数，五个日期会各占一行，密集日期需要更多列，图片会明显变小，与“保持现在的图片高度”冲突。

## Goals / Non-Goals

**Goals:**

- 普通历史每页展示连续五个完整日期。
- 分页数量变化前后，同一日期在同一数据集中的桌面列数保持一致。
- 保留搜索、平板、手机、勾选、灯箱和删除行为。

**Non-Goals:**

- 不要求五个日期都塞进三行或单屏高度。
- 不裁图、不拆分日期，也不改变服务端数据。
- 不增加用户可配置的分页数量。

## Decisions

1. 普通历史默认 page size 从 `2` 改为 `5`，分页仍只切 date section，保证每个日期完整。

2. 桌面布局在分页前按完整的筛选后 section 列表建立稳定的连续两日期组：`[0,1]`、`[2,3]`、`[4,5]`……每组独立复用现有 `getGallerySectionLayout()` 三行算法。渲染当前五日期页面时，再从全局布局表中取当前 section 的列数。这样第一页的第 5 个日期仍与第 6 个日期共同计算，第二页的第 1 个日期也沿用同一组结果，跨页前后不会改变图片尺寸。最后只剩一个日期时，行为与旧分页最后一页一致。

3. 新增纯函数封装“两日期分组后扁平化布局”的逻辑，避免把分页边界与视觉密度耦合在 `public/app.js`。函数保留 group size 参数用于测试，但产品调用固定为 2，不增加 UI 配置。

4. 摘要改为“每页显示 5 个日期”，并将“三行”描述明确为“每 2 个日期最多 3 行”，避免让用户误解整页五天只占三行。

## Risks / Trade-offs

- [一页内容明显变长] → 这是保持现有图片高度的直接结果，继续使用画廊内部纵向滚动查看。
- [第 5 个日期的布局依赖下一页第 1 个日期] → 先对完整筛选结果计算稳定布局，确保同一日期在翻页边界两侧尺寸一致。
- [单日图片过多] → 沿用现有最大列数与完整日期优先规则，允许该两日期组超过三行。
