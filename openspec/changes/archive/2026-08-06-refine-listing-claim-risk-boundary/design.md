## Context

标题补全从已清理的卖点、五点、痛点、描述和搜索字段收集短语。当前实现先无条件删除冒号前标签，因此既删除纯结构标签，也删除 `PORTABLE DESIGN`、`USB CHARGING` 等可用搜索词。现有阻断规则对排名、认证、医疗、兼容、性能等声明分类处理，但没有把高功率、高亮、防水统一定义为平台资质敏感词。

项目目前只保存商品事实、参考说明和生成证据，没有独立且可验证的资质证明对象。因此来源文本中的普通性能描述不能等同于平台要求的资质证明。

## Goals / Non-Goals

**Goals:**

- 保留有来源支持的便携设计、USB充电等普通商品属性和语义标签。
- 排除纯字段结构标签和没有来源支持的语义标签，只保留有来源支持的标题候选。
- 对高功率、高亮、防水及其英文对应表达执行确定性阻断，即使普通商品描述重复这些词也不视为资质证明。
- 维持普通属性“有来源才能使用”的事实门禁和现有单次可用响应接受语义。

**Non-Goals:**

- 不新增资质文件上传、审核或证明状态模型。
- 不放行无来源的便携、充电或其他具体商品属性。
- 不改写历史 Listing，也不扩大到图片提示词或非 Listing 工作流。

## Decisions

### 1. 将标签拆成语义标签和结构标签

标题候选解析冒号前文本后，精确匹配 `PRODUCT TYPE`、`PACK DETAILS`、`PACKAGE CONTENTS`、`产品类型`、`包装内容` 等结构标签并丢弃。其他短标签只有在标签本身能从商品事实或 Listing 证据别名中追溯时才成为候选；正文仍按既有顺序成为候选并经过同语言、货号、事实和风险清理。相比维护安全标签白名单，这能保留不同品类自然产生的具体标签，同时避免模型新造的语义标签绕过事实门禁。

### 2. 普通属性仍由事实门禁处理

`portable design` 已属于可追溯具体属性；新增 `USB charging` 为可追溯供电/充电属性。事实门禁同时扫描英文公开字段和 `zhDisplay`，并为 `portable design` / `便携设计`、`USB charging` / `USB充电` 建立保守的中英等价证据关系。模型响应只有在商品描述、卖点、SKU、参考说明或结构化 Listing 证据中存在对应表达时才能保留。

### 3. 资质敏感性能词使用无条件阻断规则

新增独立风险规则覆盖 `high power`、`high brightness`、`ultra bright`、`waterproof`、`water resistant`、`高功率`、`大功率`、`高亮`、`超亮`、`防水`、`耐水` 等表达，支持模式为 `never`。普通来源文字不是资质证明，因此不会绕过该规则。V1 和 V2 的全部公开字段在返回前执行同一清理，V2 的 `buyerObjections`、`highlights`、`searchTerms` 也纳入处理；提示词同步要求使用中性、可验证的具体结构描述代替这些性能词。

## Risks / Trade-offs

- [不同品类出现新的结构标签] → 使用精确结构标签集合，后续只在实际噪声用例出现时增补。
- [安全标签本身包含无来源事实] → 标签与正文走相同的响应前置清理，不绕过事实门禁。
- [真实防水商品也被删除该词] → 当前没有资质证明模型，优先避免平台风控；未来若增加资质对象再设计受控放行。
- [风险词删除后文案残缺] → 复用现有标点清理和必填标题/描述修复，不因删除内容重试或失败。

## Migration Plan

1. 固定安全语义标签被误删和资质敏感词被放行的失败测试。
2. 实现语义标签候选、USB充电事实门禁和资质敏感性能规则。
3. 运行 Listing、V2、本地/Worker、构建和 OpenSpec 验证。
4. 合并规格并归档；历史记录不迁移。
