## MODIFIED Requirements

### Requirement: 生图并发数量是客户端会话级全局上限

系统 SHALL 将用户配置的生图并发数量作为同一 `clientSessionId` 内所有图片生成模式的总上限。提示词生图、图片编辑、风格迁移、融图分析、图片拆解、快速溶图、套图、写真、文章插图、Logo 批量、补图和 PPT 页面生成 SHALL 共享同一个生成槽位池。不同 `clientSessionId` SHALL 保持独立。

#### Scenario: 不同模式共享并发预算

- **WHEN** 用户把并发数量设置为 `3`，同时运行提示词生图和套图模式
- **THEN** 两种模式发往上游的活动图片生成请求合计不超过 `3`
- **AND** 套图不能再额外取得一份独立的 `3` 个槽位

#### Scenario: 不同路由共享并发预算

- **WHEN** 同一会话同时使用 GPT、Gemini 或 Grok 路由生成图片
- **THEN** 所有路由合计的活动图片生成请求不超过配置值

#### Scenario: PPT 请求参与全局限制

- **WHEN** PPT 正在生成页面，同时另一模式已经占用部分生成槽位
- **THEN** PPT 页面请求只能使用剩余槽位
- **AND** PPT 页面请求释放槽位后其他模式才能继续取得该槽位

#### Scenario: 活跃会话不因后续请求扩容

- **WHEN** 同一会话已经以并发 `3` 运行，另一个模式提交并发 `20`
- **THEN** 当前活跃全局槽位上限仍为 `3`
- **AND** 后续请求必须等待现有槽位释放
