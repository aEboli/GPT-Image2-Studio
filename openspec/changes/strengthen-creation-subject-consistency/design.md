## Context

Creation Mode 的参考图存在两个不同的顺序：用户上传时的原始顺序，以及单个套图项经过角色选择、coverage、去重和预算裁剪后的实际附件顺序。主体图可以在原始上传列表中排在第二张或更后，也可以在浏览器压缩后获得新的文件名。若标签构造把筛选后数组下标当作原始索引，或只依赖已变更的文件名，角色会错位：原先的包装或材质标签可能落到主体图上，模型随即把支撑图理解为主商品。

现有智能调度器已经要求主体锚点优先，并在首次生成与补图之间复用选择逻辑；已归档的主体内容保护规范也已经保护物理商品表面的图案、Logo 和原语言。本变更不改变这些边界，而是补齐调度后附件的稳定身份映射和明确的主体优先级。`infographic-rebuild` 已有 source-only 分支，必须在普通主体锁进入提示词前保持隔离。

## Goals / Non-Goals

**Goals:**

- 让每张上传参考图在压缩改名、筛选、去重、coverage 重排和重复文件名情况下仍能恢复正确角色。
- 让普通轮播项与 SKU 项的首个实际附件始终明确为当前项唯一主体身份权威。
- 让后续支撑参考图只能贡献所属角色证据，不能把模型引导到另一个商品或变体。
- 让新计划、历史冻结计划、首次生成、补图、重生成和修复共享相同的运行时主体锁。
- 保持主体内容保护、智能参考图调度、SKU 精确主体匹配和信息图 source-only 契约兼容。

**Non-Goals:**

- 不依赖文件名作为唯一图片身份，也不要求历史文件被重新命名。
- 不改变调度器的动态数量/字节预算，不重新引入固定支撑图配额或整批上传图兜底。
- 不把生成模型的概率性输出描述为像素级完全一致，也不增加 OCR、遮罩、图像合成或人工审核流程。
- 不新增 `input_fidelity` 或任何新的上游模型参数。

## Decisions

### 稳定上传索引优先于文件名和裁剪后位置

每张接收的参考图携带一基 `referenceIndex`，代表原始上传顺序。角色和 coverage 来源可以使用 `index`、`referenceIndex` 或 `reference_index` 指向该顺序；归一化路径必须保留此信息。存在有效稳定索引时，选择器和标签构造都优先按该索引关联角色，不得使用当前已裁剪附件数组的下标作为原始索引，也不得因为压缩文件名改变而失去关联。

没有稳定索引的旧输入仍可按既有文件名和输入顺序做兼容回退；该回退不能覆盖已存在的稳定索引。这样既能处理新上传图、同名图和压缩改名，也不会破坏缺少索引的历史记录。

### 调度后的首个实际附件是当前项主体锚点

普通轮播项先使用既有角色选择或 SKU 精确主体匹配找出当前项的主体图，再由调度器将它置于实际附件列表首位。该首张图不是“原始第一张上传图”的同义词，而是本次请求中已选定的主体锚点。参考图标签和提示词在第一张前声明其为唯一身份权威，要求保留同一物理商品及变体的轮廓、比例、几何、配色、材质、Logo、标识、五金和可见结构；相机、场景、布局、灯光、背景和已允许的画布外文案可以变化。

后续附件保留其自身角色说明，但附加 supporting-only 边界。材质、包装、尺寸、场景以及其他商品图只能贡献其被分配的事实或视觉证据；与主体锚点冲突时，首张主体锚点优先。多个主体类参考图也不允许静默切换当前项的主体身份。

### 规划可见，运行时兜底

规划器将主体身份语义写入新计划，便于用户和测试检查。共享运行时参数构造器同时为历史冻结提示词、用户编辑后的提示词和修复路径补充同一约束，因此无需重新规划才能获得主体锁。首次生成、补图和重生成继续调用同一参考图选择及标签路径；相同的上传图、角色元数据和当前项应产生相同的主体锚点、附件顺序和角色边界。

这一身份锁与既有主体内容保护互补：内容保护规定主体表面现有内容不能被翻译或重绘，身份锁规定哪一张附件定义该物理主体。两者都不授权把辅助参考图的内容扩展为新的主体身份。

### 信息图重构在普通身份锁之前短路

`infographic-rebuild` 继续按已保存的精确来源匹配只附加对应源图，并在生成和补图时使用 canonical source-only 提示词。该分支不生成普通套图参考图标签，也不追加主体身份锁或支撑图约束，避免产品主体、语言、平台或角色装饰污染信息图来源重构。

### 不以新的上游保真参数解决角色错位

问题根因是本地附件身份和标签错位，而不是上游请求缺少一个保真度开关。因此不新增 `input_fidelity` 参数，也不修改模型路由。通过稳定索引、附件顺序和明确 prompt 边界修正模型真正读取到的参考图语义，影响范围更小且适用于当前所有支持的生成路径。

## Risks / Trade-offs

- 生成模型仍可能在细小文字、反光或复杂几何处出现偏差；主体锁降低主动换主体的概率，但不承诺像素级复制。
- 稳定索引缺失的历史输入仍须使用兼容回退，重复文件名在这种旧数据中可能无法完全消歧；新上传和重新上传路径应保留稳定索引以避免该问题。
- 当前项将主体锚点排在前面会改变附件展示顺序，但这是为了让模型先读取主体身份；其余附件仍保留原始相对上传顺序，以兼容编号参考图语义。
- 动态调度器仍可裁剪低相关辅助图；本变更只固定锚点和已选辅助图的身份，不扩大单项请求负载。

## Migration Plan

1. 新增增量规范和失败回归用例，固定压缩改名、非首位主体、筛掉中间参考图和辅助图冲突的预期。
2. 在服务端接收的参考图对象上保留稳定上传索引，并在角色、coverage、选择和标签路径中优先传递和使用它。
3. 在规划和共享运行时 prompt 中接入主体身份锁，同时保持 `infographic-rebuild` 先行返回。
4. 验证首次生成、补图、重生成与历史冻结提示词路径，并运行聚焦测试、全量测试、静态检查和严格 OpenSpec 校验。

无需数据迁移或新的公开 API 字段。已有可用索引会被兼容读取；缺少索引的历史记录保留原有回退行为，重新上传后的请求使用本次上传的稳定索引。
