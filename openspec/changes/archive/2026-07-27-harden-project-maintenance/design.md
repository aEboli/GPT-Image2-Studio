## Context

当前默认模型分散在 `config-store`、`browser-config`、`image-route-config`、Cloudflare Worker、Listing agent 和多个浏览器视图中。本地默认是 `gpt-5.4`，浏览器与 Worker 默认是 `gpt-5.5`，同一用户在不同运行形态首次打开时会得到不同结果。官方模型文档确认 `gpt-5.4-mini` 支持 Responses、Chat Completions、流式、图像输入和 `image_generation` 工具，因此无需改变现有请求协议。

本地服务默认只监听回环地址。显式监听 `0.0.0.0` 等非回环地址时，现有逻辑允许所有 GET 请求，并允许同源浏览器绕过写令牌。这适合可信单机，但不构成远程访问认证。

项目已有完整测试、共享模块同步、Cloudflare 构建和 OpenSpec 校验命令，但缺少仓库内 CI 与统一发布一致性门禁。

## Goals / Non-Goals

**Goals:**

- 用一个共享常量统一缺省 Responses 与直接文本视觉模型。
- 保留所有显式用户、环境和请求级模型选择。
- 让直接连接本地服务的非回环客户端在读取任何项目资源前完成认证。
- 将现有维护命令固化到 CI，并在发布前检查版本事实一致。
- 记录可信本机、远程访问、密钥和生成资产的安全边界。

**Non-Goals:**

- 不改变图片生成模型 `gpt-image-2`、Gemini/模型协议默认值或 API 请求结构。
- 不迁移或覆盖已有 `.local/config.json`、浏览器 localStorage 或环境变量。
- 不为 Cloudflare/Vercel 增加用户账号、租户或应用级登录系统。
- 不在本变更中拆分整个 `public/app.js`、`server.mjs` 或 Worker。
- 不代替项目所有者选择开源许可证，也不创建发布提交、标签或 GitHub Release。

## Decisions

### 1. 默认模型使用单一共享模块

新增 `lib/model-defaults.mjs`，集中导出默认 Responses、直接文本视觉、直接图片和模型协议模型。现有模块继续导出兼容名称，避免扩大调用方修改面；浏览器镜像由现有同步脚本维护。

`gpt-5.4-mini` 只参与缺省解析。配置文件、环境变量、浏览器私有配置和请求 payload 中的非空值始终优先，避免升级后静默覆盖用户选择。

### 2. 非回环客户端统一令牌认证

新增纯函数认证模块，统一处理回环地址、Host/Origin、`X-Image-Studio-Token`、Bearer 和 Basic 凭据。直接远程客户端必须为页面、静态资源、输出文件和 API 提供令牌；浏览器通过 `studio` 用户名和现有令牌完成 Basic 认证，随后同源资源请求复用浏览器凭据。

回环客户端保留当前行为：GET 和静态资源直接访问，同源浏览器可执行写请求，命令行仍可使用请求令牌。反向代理连接若在服务端表现为回环地址，代理必须自行承担外部认证，安全文档明确这一点。

### 3. 认证逻辑从服务入口抽离

认证与网络地址判断从 `server.mjs` 移到 `lib/local-server-auth.mjs`，以纯输入输出测试远程、回环、Basic、Bearer、令牌错误和同源边界。令牌比较使用固定时序比较，避免继续扩展服务入口中的安全分支。

### 4. CI 固化现有项目验收

CI 使用 Node.js 22 和锁定的 OpenSpec `1.6.0`，依次运行串行测试、共享模块同步检查、发布一致性检查、Cloudflare 构建、OpenSpec 严格校验、`git diff --check` 和生成后工作树检查。串行测试成为 `npm test` 默认行为，消除服务测试的端口竞争。

### 5. 发布检查区分日常与正式发布

日常 `check:release` 只验证 package、lockfile、README、Windows 文档和当前 release notes 的版本一致性，可在普通分支和 CI 执行。`check:release:strict` 额外要求干净工作树和当前提交上的匹配标签，只用于正式发布前，不阻塞日常开发。

## Risks / Trade-offs

- [远程浏览器新增认证提示] -> 只影响非回环客户端，并在启动日志、README 和安全文档中给出用户名与令牌来源。
- [兼容网关不认识新模型] -> 仍允许界面、环境变量和请求覆盖；默认值不强制迁移已保存配置。
- [共享常量引入浏览器镜像遗漏] -> 把模块加入同步注册表并由 CI 执行 `--check`。
- [CI 时间增加] -> 使用单一 Node 版本和现有测试命令，优先保证当前单仓库的确定性。
- [反向代理误以为后端已认证] -> 明确代理回环场景必须在代理层认证，不信任转发头自动判定客户端。

## Migration Plan

1. 增加失败测试，固定默认模型与远程认证预期。
2. 引入共享默认值和认证模块，更新各运行时调用点。
3. 同步 `public/lib`，更新配置示例与远程访问文档。
4. 增加发布检查、CI、安全和贡献文档。
5. 运行完整测试、构建、同步、OpenSpec 与 diff 检查。
6. 归档本变更，将三个新增能力合并回主规格。
