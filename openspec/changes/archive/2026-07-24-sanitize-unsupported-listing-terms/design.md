## Context

Platform V1 只请求模型一次。当前响应先经旧版字段归一化，再同时执行严格结构检查、高风险声明检查和低风险证据词检查；任何一项失败都会抛出生成错误。截图中的 `adjustable`、`gray`、`black`、`rechargeable` 属于低风险证据词，但现有实现要求这些英文词必须逐字出现在有限的来源字段中，因此即使模型输出整体可用，也会与标题长度、Bullet 格式等非关键偏差一起导致整份 Listing 被丢弃。

## Goals / Non-Goals

**Goals:**

- 单次模型响应中出现未支持的低风险属性词时，删除对应词并继续返回可用 Listing。
- 将结构验收限定为英中标题、英中描述和旧版字段类型等最小可展示条件。
- 保持一个模型请求，不增加重试、人工审核、确定性兜底或 mock 兜底。
- 保留上游失败、解析失败、缺失双语主体和高风险声明的明确错误。

**Non-Goals:**

- 不为缺失文案编造新卖点、翻译或商品事实。
- 不放宽排名、认证、医疗、价格、保证、兼容性、性能或竞品比较等高风险声明。
- 不修改 Listing 的外部字段名、存储格式、页面布局或发布流程。

## Decisions

1. 复用现有 `TRACEABLE_CONCRETE_CLAIM_PATTERNS` 和来源证据集合识别可清理词。这样截图中的具体属性、材质、颜色、形状、结构、模式和使用场景沿用同一分类边界，不引入第二套词表。
2. 新增纯内容净化函数，只处理 `title`、`sellingPoints`、`painPoints`、`fiveBullets`、`description`、`backendSearchTerms`、`keywordBuckets` 及 `zhDisplay` 对应内容。它按完整词边界删除未支持词并整理相邻空格与标点，不修改 ID、平台元数据、证据或来源数据。
3. Platform V1 验收顺序改为“归一化 -> 低风险词净化 -> 最小结构检查 -> 高风险检查”。低风险证据错误不再进入最终错误列表；高风险检查针对净化后的最终内容执行。
4. 最小结构只要求双语标题和描述非空，旧版列表及关键词桶保持正确值类型。标题推荐长度、Bullet 数量与标签、痛点句式、英中数组等长和关键词桶非空继续作为提示词质量目标，不再作为整单失败条件。
5. 净化不产生面向用户的内部证据警告。最终 Listing 只展示清理后的公开文案；若清理导致英中标题或描述为空，仍按不可用主体返回错误。

## Risks / Trade-offs

- [删除单词后英文语句可能略显生硬] -> 只按完整词删除，并统一清理多余空格、悬空分隔符和首尾标点。
- [低风险词清理可能使英中表达不再完全对称] -> 不凭词表猜测中文翻译；当英文列表项被完全清空时同步移除同索引中文项，其他情况保留模型的中文原文。
- [放宽格式验收会接受质量较低但可展示的文案] -> 提示词继续要求完整双语结构和高质量格式；验收仅去除会阻断生成的非关键格式门槛，高风险安全边界保持不变。

## Migration Plan

无需迁移历史 Listing。部署后仅影响新的 Platform V1 模型响应；回滚时恢复原结构检查和低风险证据错误汇总即可。
