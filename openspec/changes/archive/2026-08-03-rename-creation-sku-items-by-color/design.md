## Context

当前计划器和本地队列各自将 `skuSubject.title`、ID 或参考文件名拼接到 `SKU image {序号} - ` 后。计划器另有一套私有颜色解析逻辑，用于 SKU 图内文字；队列没有复用它，导致两条名称路径无法保证一致。颜色识别必须延续现有安全边界：只接受结构化或可规范化的颜色证据，不从背景、覆盖文字或不确定文本猜测颜色。

## Goals / Non-Goals

**Goals:**

- 让计划预览和本地队列对同一个 SKU 显示相同的颜色名称。
- 保持单一 SKU 的多颜色为一个标签，保留分组 SKU 中多个主体的稳定顺序。
- 在没有可靠颜色时保持现有可追溯名称降级，而不是生成猜测性颜色。

**Non-Goals:**

- 不改变 SKU 图内颜色标签的视觉布局或生成提示词语义。
- 不修改 SKU ID、输出文件名、`filenameToken`、Listing、Temu 导出和已保存历史记录。
- 不扩展支持的目标语言或颜色词表。

## Decisions

### 共享现有颜色解析，而不是从显示标题重新提取

将计划器现有的结构化颜色优先、显式颜色字段、受限文本识别和英/简体中文本地化逻辑迁移为颜色模块的导出函数。计划器继续用它生成图内颜色标签，队列也用它生成卡片名称，避免两处规则漂移。

备选方案是仅在队列中扫描标题或文件名。该方案会忽略 `colorNames` 的分组边界和目标语言，且与计划器的图内标签不一致，因此不采用。

### 名称以颜色为主，缺失时沿用原有降级顺序

有一个或多个可靠颜色标签时，名称使用 `SKU image {序号} - {标签}`。多个完整主体的标签按原始顺序以 ` / ` 分隔；同一主体内的多颜色继续以空格组成一个标签。没有可靠标签时，名称仍使用原始标题、ID、参考文件名的现有顺序。

备选方案是显示“未识别颜色”或删除后缀。两者都会丢失当前识别 SKU 的信息，且容易把不同 SKU 显示成相同名称，因此不采用。

### 历史项目不迁移

新建计划和本地排队集合使用新名称；已持久化项保留原名称。这样不改变历史记录、文件名或下游关联，也符合最小行为变更原则。

## Risks / Trade-offs

- [没有可靠颜色的 SKU 仍显示原始标题] -> 这是失败关闭的降级路径；不会伪造颜色，且保留区分 SKU 的信息。
- [分组 SKU 名称较长] -> 保留现有完整标题显示行为；使用 ` / ` 只分隔不同完整主体，不拆分同一主体的多颜色。
- [共享解析调整现有提示词] -> 使用现有回归测试覆盖图内颜色标签，并增加计划器与队列命名一致性测试。

## Migration Plan

1. 先添加共享颜色名称解析和名称回归测试。
2. 更新计划器和队列命名入口，并同步浏览器模块镜像。
3. 执行 focused 测试、完整测试、镜像检查和 OpenSpec 严格验证。
4. 回滚只需恢复名称调用点；不需要数据迁移，因为历史记录未改写。
