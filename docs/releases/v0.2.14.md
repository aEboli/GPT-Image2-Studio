# GPT-Image2-Studio v0.2.14

`v0.2.14` 将主应用版本从 `0.2.13` 更新到 `0.2.14`。

## 更新内容

### Gemini 通道保留请求的画面方向

- `Gemini模型` 通道只接受 10 个比例：`1:1`、`2:3`、`3:2`、`3:4`、`4:3`、`4:5`、`5:4`、`9:16`、`16:9`、`21:9`。界面提供 15 个。
- 此前多出的 `9:21`、`2:1`、`1:2`、`3:1`、`1:3` 会静默变成 `1:1`：就近匹配只肯从 `size` 反推宽高，而该通道的 `size` 是档位字符串（`512`、`1K`、`2K`、`4K`），解析不出宽高便直接返回方形。提示词里仍带着原始比例描述，于是请求横幅却得到方图。
- 现在在 `size` 无法解析时改用比例字符串自身推导比值，沿用既有的对数距离就近匹配。实测 15 个比例的方向全部保留：

  | 选择 | 实际发送 | 选择 | 实际发送 |
  | --- | --- | --- | --- |
  | `2:1` | `16:9` | `1:2` | `9:16` |
  | `3:1` | `21:9` | `9:21` | `9:16` |
  | | | `1:3` | `9:16` |

- 受支持的 10 个比例继续原样透传；`size` 可解析出宽高时仍优先使用 `size`；只有比例与尺寸都无法解析时才回落 `1:1`。

### 派生版本事实纳入维护

- 新增 `scripts/version-facts.mjs` 声明派生版本事实模板：两份 README 的版本徽章、正文引用的桌面安装包与免安装 ZIP 文件名、发行说明链接、`v<version>` GitHub Release 表述，以及 Windows 文档中的安装包文件名。
- `check:release` 校验这些事实并在失败时报出文件、行号、实际值与期望值；`release:patch` 在同一事务内一并改写。
- 此前每个维护文件只校验一条锚定事实，升版后徽章和安装包文件名会继续指向上一个版本而检查依然通过。`v0.2.10` 就是为修复这类漂移单独发布的纯文档版本。
- 模板均以分隔符结尾，因此散文、版本历史章节、tag 示例保持逐字节不变，且 `v1.2.3` 不会匹配进 `v1.2.30`。

### 文档

- 两份 README 精简版本历史：只保留当前版本条目，更早版本指向 GitHub Releases；配置参考段不再重复新手教程内容。英文由 539 行降到 488 行，中文由 784 行降到 707 行。
- 补充按源码核对的通道事实：路由模式的图片编辑始终改走 `images/edits` 并忽略配置的后缀；分辨率只对其所属比例合法，否则报 `当前比例 X 不支持分辨率 Y`；切换调用通道会把非默认分辨率重置为自动适配；Gemini 通道不接受质量与输出格式；走哪一种请求体由模型名嗅探决定。
- 「版本发布」中的 tag 示例不再写死具体版本号，避免随升版过期。

## 升级说明

- 主应用每次更新仅递增一个补丁版本，即 `+0.0.1`。
- 既有配置、生成记录和图片资产不需要迁移。
- 商品图采集扩展使用独立版本线，本次主应用更新不会修改扩展版本。
- 在 Gemini 通道使用过 `9:21`、`2:1`、`1:2`、`3:1`、`1:3` 的用户，本次更新后这些比例会得到方向正确的近似比例而不再是方图；历史记录中已生成的方图不会被改写。
