# 设计

## 数据来源

使用支持 IPv4/IPv6 的固定 IP 反射服务，并通过 `upstreamStreamFetch` 发起请求，使查询经过 Studio 生图上游请求共用的 Node HTTP transport。响应中的地址必须通过 IP 格式校验。查询超时、服务不可用或返回无效地址时返回空字符串；不得回退到 `CF-Connecting-IP`、`X-Real-IP`、`X-Forwarded-For` 或 socket `remoteAddress`。当前各生图模式共用同一出站 transport，因此字段表示 Studio 本机通过该 transport 可观察到的公网出口地址。

查询结果在服务进程内缓存 5 秒并合并并发请求，避免并行生成任务重复访问反射服务，同时限制网络模式切换后的旧值窗口。生成开始时取得的值随任务、结果和 Gallery 元数据保存；历史记录保持原样。

## 显示行为

`/api/config` 的 `requestIp` 表示 Studio 服务端当前可观察的公网出口 IP。图片详情仍显示记录中的 IP；记录缺失或查询失败时显示“未记录”。浏览器私有 API 配置不保存该字段。

## 边界

当前各图像路由共用同一个上游 `fetch` transport，路由主要选择不同的 API 地址。部署网络若按目标主机名分别路由或代理，固定反射服务只能报告其自身所见出口，不能证明某一 API 主机所见的地址。历史记录中的旧 `requestIp` 可能是入站地址，不迁移或改写。

## 风险

- IP 反射服务不可用或被网络策略阻止时，地址显示“未记录”。
- 查询服务会收到一次普通 HTTP 请求并看到 Studio 主机当前的公网出口地址；不发送 API 密钥、提示词或生成图像。
