## Context

提示词生图的后台队列已经把 `background=1` 用作“服务端异步执行”的控制信号，而 Responses 图像工具又需要 `background` 表示成品背景。当前输出格式只有 PNG 和 JPG，且请求构造把图像背景固定为 `opaque`。

## Goals / Non-Goals

**Goals:**

- 在提示词生图中提供默认关闭的透明背景控制，并让单个入队任务冻结该选择。
- 默认请求继续显式使用 `opaque`，透明请求使用 `transparent`，且透明输出始终为 PNG。
- 防止新字段影响后台队列控制、风格迁移、图片编辑、套图、写真、文章插图和 PPT。

**Non-Goals:**

- 不把背景选项保存为全局配置或迁移历史记录。
- 不新增 WebP 输出格式，也不为模型协议通道推测或模拟透明背景能力。
- 不改变参考图、队列、模型选择或其他生成参数的既有语义。

## Decisions

### 使用独立的 `imageBackground` 表单字段

浏览器把提示词任务的背景选择快照到 `imageBackground`，服务端再映射为上游 API 的 `background`。这样不会与已经存在的 `background=1` 后台队列控制冲突。

替代方案是复用 `background` 并改造队列识别逻辑，但这会让一个字段同时拥有布尔调度和枚举图像参数两种语义，容易导致异步任务失效。

### 透明请求强制 PNG

开启透明背景时，前端把输出格式固定为 PNG；服务端也再次强制 PNG，避免绕过浏览器的请求得到不含透明通道的 JPG。关闭后恢复此前的格式选择。该决定遵循官方 OpenAI 图像生成文档对透明背景与 PNG/WebP 输出格式的约束。

### 在支持路径上按请求透传

Responses 图像工具总是接收归一化后的背景值，保持默认 `opaque` 请求字节语义不变。直接图像 API、Responses 和聊天兼容路径只在值为 `transparent` 时附带背景字段，使现有不透明直连请求不新增参数。模型协议通道不展示此控制，避免承诺未知的上游能力。

### 服务端拥有最终白名单和模式边界

服务端只接受 `transparent`，其余任何值都归一化为 `opaque`；只有无 `mode` 的提示词任务会使用该值。即使客户端被篡改，其他生成模式也不会收到透明背景请求。

## Risks / Trade-offs

- [第三方直连服务不支持透明背景字段] → 默认不透明请求不添加新字段；用户显式开启透明背景时由上游返回其兼容性错误。
- [浏览器状态与排队任务不同步] → 将值存入任务快照，并在服务端任务元数据与保存记录中保留实际值。
- [用户以 JPG 启用透明背景] → 前端立即切换并锁定 PNG，服务端再次兜底。

## Migration Plan

无需数据迁移。历史记录缺少 `imageBackground` 时按既有不透明语义处理。回滚时移除前端控件和服务器透传即可，旧请求仍因默认值保持不透明。
