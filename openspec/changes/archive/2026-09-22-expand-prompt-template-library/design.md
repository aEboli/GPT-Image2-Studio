## Context

Prompt Kit 的入口是位于提示词字段旁的浮层。现有实现把状态和渲染集中在 `public/app.js`，而用户模板存储在 `image-studio-prompt-templates-v2`。目录模板如果混入该数组，会放大 localStorage、污染用户排序并让目录更新变成破坏性迁移，因此采用独立静态模块。

## Goals

- 提供稳定的一级/二级分类浏览和每个二级分类十条模板。
- 让默认瀑布流适合快速扫图，同时为长提示词提供可读的列表模式。
- 用现有 lightbox 展示目录预览图和完整提示词，避免再造一套图片查看器。
- 保持应用、编辑、删除和 Prompt Agent 历史路径的行为边界。

## Decisions

### 1. 独立静态目录模块

`lib/prompt-template-library.mjs` 导出目录树、扁平化查询和预览图 URL 生成器。预览图使用确定性的内联 SVG 数据 URL，在无网络或桌面离线模式下仍可显示；模块只保存模板描述和预览键，不把生成图片写入磁盘或图库。该模块加入 `scripts/sync-public-lib.mjs`，保持 `lib/` 与 `public/lib/` 镜像。

### 2. 目录与用户模板分离

`state.promptTemplates` 继续只承载用户可编辑模板、当前默认模板和 Prompt Agent 历史。新增 `state.promptTemplateLibrary` 视图状态保存分类、搜索、视图模式、列表字号和当前目录条目。目录模板应用时直接写入主提示词；“复制到我的模板”创建新的普通模板，之后沿用现有编辑和删除逻辑。

### 3. 三级浏览与视图

侧栏显示一级分类及其二级分类按钮。选择一级分类时显示该分类下全部二级分类；选择二级分类时只显示该分类的十条模板。搜索在当前分类范围内过滤名称、分类名和提示词。瀑布流使用 CSS columns，列表使用稳定的两列缩略图/文本布局，图片视图只显示缩略图并在 hover/focus 时显示应用操作。

### 4. 预览和应用

点击缩略图或图片卡片主体构造 `isPreviewLightboxItem` 的 lightbox 条目，复用现有图片查看器和提示词面板。目录条目不参与图库导航，也不触发生成记录更新。应用操作使用现有 `applyPromptTemplate` 的同一提示词输入和计数更新路径；复制操作只新增用户模板，不修改目录快照。

### 5. 响应式与可访问性

桌面采用“分类侧栏 + 目录主区 + 我的模板/编辑器”布局；平板和手机将侧栏变成横向滚动分类条，目录切换为单列或双列，长提示词使用 `overflow-wrap:anywhere`。视图切换使用 tab 语义，分类和应用操作使用按钮，图片卡片支持键盘聚焦；字号调节只改变列表文本的 CSS 变量，不改变卡片宽度或网格轨道。

## Risks and Trade-offs

- 内联预览图不是外站原始图片，换取离线稳定性和不引入版权/跨域依赖；模板文本按参考站点的常见分类和工作流整理成静态快照。
- 目录条目数量明显增加，首次打开面板需要创建更多 DOM；只渲染当前筛选结果，并在搜索或分类改变时重建目录，避免启动时渲染全部卡片。
- 现有 lightbox 面向生成资产，目录条目使用预览标记绕过图库刷新；若未来 lightbox 字段契约变化，需要同步目录适配层。

## Verification Plan

- 新增目录模块单元测试：分类树、每个二级分类十条、稳定 ID、提示词非空和预览 URL。
- 扩展模板静态契约测试：HTML 控件、资源版本、目录渲染函数、三种视图、字号调节、lightbox 应用和用户模板保留。
- 运行聚焦测试、完整 `npm test`、`npm run sync:public-lib -- --check`、OpenSpec 严格校验和 `git diff --check`；启动本地服务后用桌面与窄视口人工检查分类、应用、放大和响应式布局。
