## Context

主应用当前以 `package.json` 的 `0.2.6` 驱动 Electron 和 Windows 安装包命名，`package-lock.json`、README、Windows 文档和发布说明由发行检查约束。浏览器、本地 Node、Electron、Vercel 和 Cloudflare Pages 共用 `public/index.html`，但界面中没有版本事实。Cloudflare 构建会原样复制 `public/`，因此只依赖 Electron API 或本地服务接口会造成运行方式分叉。

## Goals / Non-Goals

**Goals:**

- 让用户在工作台左下角直接识别当前主应用版本。
- 保持 `package.json` 为唯一权威版本，并让自动检查发现页面或文档漂移。
- 用一个可重复命令完成严格的 `0.0.1` 补丁递增和维护中版本事实同步。
- 保持标签在窄屏和安全区内可见、不交互、不造成横向溢出。

**Non-Goals:**

- 不增加版本查询 API、Electron preload/IPC 或运行时网络请求。
- 不自动创建 Git 标签、提交、安装包或外部发布。
- 不改变商品图采集扩展的独立版本。

## Decisions

### 1. 页面保留一条受校验的静态版本事实

在 `public/index.html` 中写入唯一的 `v<version>` 标签，发行检查要求它与 `package.json` 一致。这样所有共用 `public/` 的运行方式均可显示版本，即使应用脚本初始化失败也仍有版本信息。相比运行时 API，这一方案不增加云端分支和权限面。

### 2. 标签固定在视口左下安全区

版本标签放在滚动工作区之外，以 `position: fixed`、安全区 inset、小号等宽数字和 `pointer-events: none` 呈现。它不使用卡片或交互样式，也不参与主布局，避免挤压现有全屏工作台。

### 3. 补丁命令先验证再同步

新增 `release:patch` 命令：读取并验证包与锁文件当前版本，计算补丁位加一，在确认所有受维护文件包含旧版本且目标发布说明不存在后，再统一写入新版本。命令要求一条真实更新摘要，用它创建新的简体中文发布说明；不会复制旧版本说明或伪造安装包验证结果。

现有 `check:release` 继续作为闭环门禁，并新增页面和兼容安装包文档检查。手工只改某一处版本时，检查必须失败。

## Risks / Trade-offs

- [静态标签可能与包版本漂移] -> 将唯一页面版本事实加入 `check:release`，并由补丁命令同步。
- [固定标签遮挡窄屏内容] -> 使用极小占位、低视觉权重、安全区偏移和不接收指针事件，并进行桌面/手机渲染验证。
- [自动发布说明内容失真] -> 命令强制接收维护者提供的更新摘要，只生成事实性的版本递增说明，不声明构建、签名或发布结果。
- [全局替换误改历史说明] -> 只处理维护中的 README、Windows 文档和页面，不修改 `docs/releases/` 中既有版本历史。

## Migration Plan

1. 先加入 `v0.2.6` 页面事实、样式、补丁命令和回归测试。
2. 使用补丁命令将主应用更新为 `0.2.7`，同步当前发行事实并生成 `v0.2.7` 说明。
3. 执行测试、Pages 构建、桌面冒烟、发行检查、视觉检查和 OpenSpec 严格校验。
4. 若需回滚，恢复本变更涉及的版本、页面、脚本、文档和规格文件；不触碰用户数据或独立扩展版本。
