## Context

本次包含四项独立目标：文本流式显示、扩大分析/营销阅读空间、减少营销图语义重复并保持主体一致，以及解释并减少多次文本请求。工作树已有同日相关改动；实施必须基于当前内容做局部补丁。

## Decisions

### 1. 真实流式贯通

按现有配置解析最终协议，不用一个通用 `stream` 字段假定所有网关都支持 SSE。Responses 与 Chat Completions 使用各自的请求字段和回答 delta；Gemini 兼容分支需验证现有网关的流式能力，只有配置明确支持原生 Gemini 时才使用其原生流式端点。不能擅自改写用户 API 地址。

实现沿用现有 Gemini 兼容网关地址，提交流式请求并消费 candidates 回答分片，排除 thought 部分；不新增或猜测原生端点。协议验证使用本地模拟 SSE，未调用用户真实网关。网关普通 JSON 或完整缓冲返回会明确显示缓冲状态。

内部事件表达请求开始、首次回答文本、回答增量、已完成字段、重试、校验和终态。心跳只保活。只展示回答内容，不展示 reasoning、analysis 或原始调试包。旧 JSON 客户端保持最终 JSON 契约，新浏览器主动请求事件流。

针对结构化内容维护独立的可视草稿：完整字段可进入卡片；未闭合字符串只用于标注“接收中”的显示文本，使用安全文本节点并正确处理转义与 UTF-8 分片。草稿不进入最终业务解析，不计为已验证条目。更新采用合并批次与稳定 DOM 节点，避免每个 token 重建整个面板或重置滚动位置。

上游完整缓冲时显示真实接收状态，不能按定时器编造阶段，也不能宣称已经实现首 token 提前到达。无法兼容的协议应给出明确能力提示。

### 2. 阅读浮层利用生图区

以生图区可视矩形为定位依据，避免仅按整个视口居中而遮住左侧关键控制。建议宽度为生图区的 88%，高度上限为可视区的 82%，桌面最大宽度 1440px。标题与收起按钮保持可见，概览与任务列表有清晰留白，屏幕不足时降为单列。

浮层不改变图片网格布局，沿用互斥展开、Esc 收起和焦点恢复；任务跳转后收起。手动向上浏览时不强制滚动到最新文本。

### 3. 商品不变，使用表达可变

分析师负责可核对事实、主体部件归属和真实能力；营销师负责用不同画面回答不同购买问题。每个任务补充用途、适用场景、主要动作、景别/构图与证据焦点，形成可检查的分工表。先由同一次营销回答安排覆盖，再给出本地重复风险诊断。

截图中的骑行、手机触控、通勤等可形成不同任务，但必须有该商品事实支持。白底展示、到手清单和规格表可保留相同主体姿态，因为购买问题不同；不能仅凭相似姿态全部判重复。反之，“冬日温暖”和“雪日暖意”只改文案或背景不能视为两项独立价值。

主体一致性约束商品身份、数量、比例、部件位置、表面归属、开合状态、标识和可见数字。场景适应允许参考支持的手势、持握、佩戴和光照，禁止把部件复制到错误表面或用辅助商品替换主商品。单图只引用本图所需事实与参考。

### 4. 请求链路与预算

当前路径为：智能识别 →（可选前端重试）→ 服务端结构化回退/JSON 修复；营销预览 → 整套规划 → 生成复用冻结计划。它不是固定五次调用。截图也缺少将日志归入同一次操作的 ID。

2026-10-28 使用注入的本地 `fetchImpl` 复现了同一次营销规划的四次 POST：结构化参数被拒绝 → 兼容请求返回损坏 JSON → 严格 JSON 修复再次使用结构化格式并被拒绝 → 再次兼容请求成功。该实验只使用测试夹具和模拟响应，没有请求用户实际上游，也不能用于断言截图五条日志的具体归属。

目标正常路径：无分析直接规划 = 一次模型请求；先识别再规划 = 两次；确认预览后生成/补图 = 零次额外文本规划。已有分析应通过输入指纹与来源校验后复用，营销响应使用规划专用 schema，避免要求模型重复重写整份分析；无分析仍使用完整 schema，并沿用最终事实校验。

在途合并键包含商品/参考内容、角色手工修订、分析版本、平台、语言、数量、场景、画幅、用户锁定项与实际模型配置。不能只用商品名称。取消一个消费者不应误取消其它仍在等待的相同请求；全部消费者取消后终止上游读取。缓存仅在当前会话作用域内复用，相关输入变化即失效。

实现为浏览器相同输入在途 Promise 合并，加上服务端会话隔离的短期计划池。服务端以完整 input、实际 config 与参考内容哈希作为键，最多保留八份完成计划、有效期两分钟；没有 clientSessionId 的兼容请求不进入共享池。规划专用上下文只有在前端确认分析仍有效且服务端规范化后确有有效事实时启用，旧客户端和只有原始资料的请求继续使用完整分析 schema。共享上游使用独立取消作用域，已用两个真实本地 HTTP 消费者验证首个客户端断开不会误取消另一个消费者。

一次逻辑操作最多两次上游 POST。首轮结构化参数被明确拒绝可消耗一次兼容重试；首轮完整文本 JSON 无效可消耗一次修复重试，两者不叠加。权限/余额/账号错误、取消、语义重复风险不自动重放。预算耗尽显示原因并允许用户手动重试。

请求可观测数据仅记录随机逻辑 ID、用途/触发来源、协议、尝试数、原因和时间；敏感凭据与原始图片不进入日志。五条实际历史日志的归因需已有活动记录或后续同样操作复现，不能由 token 数量倒推。

## Validation

- 分片模拟三种现有协议：完成前已观察到文本；拆分 UTF-8、JSON 转义、终态、取消和缓冲网关行为可复核。
- 请求计数：正常一次、合并并发一次、确认计划生成零次规划；兼容回退与 JSON 修复任意组合不超过两次上游 POST。
- 20 张营销图覆盖不同购买问题，重复诊断不增加审查请求；主体锁逐图保留，掌背面与标识不串位；强制平台项和手工锁定项保持。
- 1920×1080、1366×768 与窄屏人工核对面板尺寸、字号、滚动和任务定位；图片网格尺寸不变化。
- 执行相关回归、共享模块同步检查、版本一致性检查、OpenSpec 严格验证和差异检查；用户确认且全部实施验证完成后再归档。
