# Change: 补全旧 Listing 的缺失尺寸

## Why

新版页面可能连接到尚未重启的旧服务，旧服务会保存不含尺寸键的完成稿。即使后续切换到新版服务，这类草稿仍显示“无”，迫使用户再次调用模型。

## What Changes

- 读取套图记录时，对已完成但缺少尺寸键的 Listing 进行非持久化补全。
- 产品尺寸优先使用套图记录中的明确物理尺寸；缺少对应证据时才标记预估。
- 历史 Listing 已包含可由原始证据逐项核对的部件尺寸时，按部件输出紧凑尺寸，不直接拼接失去部件关系的 Length/Width 列表。
- 包装尺寸只接受明确包装证据，否则输出带 `Estimated:` / `预估：` 的保守数值。
- 新前端拒绝把缺少四个中英尺寸值的生成响应当作成功。

## Capabilities

### Modified Capabilities

- `creation-listing-agent`: 历史草稿读取兼容和生成响应接受边界。

## Impact

- 受影响代码：Listing 尺寸回退、套图记录 GET、Listing 浏览器控制器及测试。
- 不重写历史清单，不触发模型请求，不改变已有非空尺寸。
