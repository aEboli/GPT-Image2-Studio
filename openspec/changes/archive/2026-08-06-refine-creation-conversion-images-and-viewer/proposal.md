## Why

当前套图首图只抽取少量信息，`benefit` 与末尾卖点角色的营销职责仍有重复，冲动氛围图也容易退化成平淡陈列；功能效果图在多功能商品上虽然禁止对比，却缺少“不得漏功能”和必要时连续拼接场景的明确规则。图片详情同时给检查器固定分配较大宽度和高度，主图不是查看过程的视觉中心。

## What Changes

- 首图成交主视觉在平台允许营销文字时，合并所有可靠的非尺寸商品信息，以目标语言做可读的电商信息层级，并保留围绕主商品的圆形场景窗。
- 保持稳定角色 ID `benefit`，将其从“核心信息融合图”改为“目标人群共鸣图”，用一个目标买家、一个熟悉处境和一个购买触发点替代第二张卖点堆叠图。
- 冲动下单氛围图把商品融入决定性使用瞬间或有共情的生活情境，禁止平淡静物陈列和只有装饰氛围的画面。
- 功能效果渲染图必须覆盖全部可靠功能；默认围绕一个完整主商品统一渲染，确实无法同时清楚表达时，允许使用无硬边框、非对比式的连续场景拼接，但不得遗漏功能或退化成前后对比。
- 收窄图片详情检查器宽度，限制参数文本的默认高度，并保持移动端图片优先、信息可滚动和触控可用。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `creation-mode`: 调整首图、`benefit`、冲动氛围图和功能效果渲染图的角色名称、信息覆盖及构图规则。
- `lightbox-image-viewer`: 调整图片与检查器的桌面/窄屏占比，使主图保持主要查看面积。

## Impact

- 规划与平台策略：`lib/creation-planner.mjs`、`lib/creation-platform-policies.mjs`、`lib/creation-category-templates.mjs` 及需要同步的浏览器镜像。
- 前端预览与查看器：`public/app.js`、`public/styles.css`。
- 规格与验证：Creation planner、平台策略、前端静态布局测试及 OpenSpec 变更工件。
- 不改变稳定角色 ID、生成 API 请求结构、历史 manifest、图片文件或现有平台主图的无文字硬约束。
