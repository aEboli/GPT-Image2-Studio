## Context

主题区已有七套允许使用的预设，但它们使用横向滚动条，并且下方还提供三类自定义颜色和可选花卉纹样。颜色覆盖会影响 Studio 与嵌入的 Temu 工作台，花卉开关也需要在两端维持状态。

## Goals / Non-Goals

**Goals:**

- 将预设选择变成固定四列网格，使每项只包含色块与名称。
- 保留预设选择、预设 ID 和深浅主题的持久化行为。
- 完整移除自定义颜色与花卉点缀的界面、运行时状态、首次绘制读取、样式覆盖及跨文档消息字段。

**Non-Goals:**

- 不修改七套预设的颜色值、调用通道或其他界面装饰。
- 不迁移或删除用户浏览器中已存在的旧本地存储键；新版本不会读取这些值。

## Decisions

### 预设固定为四列

主题项采用 `repeat(4, minmax(0, 1fr))` 网格而非横向滚动。每个名称限制为两个汉字，配合紧凑色块可在窄抽屉中维持四列且不截断文本。

替代方案是保留可滚动单行或在窄屏切换为两列。前者不符合快速比较要求，后者会改变每行四项的明确布局要求。

### 删除跨文档的旧主题扩展字段

Temu 工作台主题消息只保留 `theme` 与 `palette`，并移除花卉与自定义颜色字段的读取、应用和 CSS 覆盖。这样已保存的旧值既不会在 Studio 首次绘制时生效，也不会被重新发送到工作台。

替代方案是保留但隐藏旧状态以便未来恢复；这会继续保留不可见行为和维护负担，不符合删除功能的要求。

## Risks / Trade-offs

- [旧本地存储键仍保留在浏览器中] -> 新版不读取或发送这些键，因此不会改变界面；不主动清理可避免无关的持久化写入。
- [四列在窄抽屉中的单项宽度较小] -> 名称统一为两字、色块尺寸受限且网格轨道允许收缩，避免文本裁切或横向滚动。

## Migration Plan

1. 部署更新后的静态资源。
2. 页面重新加载后，只恢复已选择的预设与深浅主题；旧自定义颜色和花卉设置不再应用。
3. 如需回滚，恢复此前资源即可重新读取旧本地存储值；不涉及服务端数据迁移。
