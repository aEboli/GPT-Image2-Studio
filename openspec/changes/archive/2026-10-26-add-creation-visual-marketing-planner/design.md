## Context

`handleCreationPlan` 当前直接调用本地 `buildCreationPlan`；它没有请求 AI 来创作整套提示词。参考图识别单独请求视觉模型，返回商品洞察和单个目标买家概括。已有营销建议通过 `buildCreationProductInsightPrompt` 进入对应事实的图片任务，但完整构图和任务仍主要由本地模板决定。

服务端和浏览器的数量选项均为 0–18；平台解析器还会用固定槽位数量再次裁剪。这意味着仅增加下拉菜单的 20 张选项不能实现目标。

目前工作区还有其他未提交的商品保真、参考图和提示词变更。本方案以实施时的当前代码为基线，仅调整所需入口，不回退或归档其他变更。

## Decisions

### 1. 分开处理分析深度与提示词创作

分析深度提升对现有智能识别生效；AI 整套提示词规划是额外开关。不能因为用户关闭新开关，就继续只给泛泛的买家、外观属性或空白痛点。

分析师职责改为“电商视觉营销专家”：基于商品用途与真实资料，识别适合的主要和次要买家，提炼购买动机、使用困扰、顾虑、商品价值以及可用于画面表达的证据。受众按使用任务和需求划分，不从人物外观推断人口属性。

新增 `productInsights.audienceSegments`，对应模型字段 `audience_segments`。每组至少包含稳定 ID、群体名称、使用/购买语境、核心需求、购买触发点、主要顾虑及事实 ID；简体中文展示。旧 `audienceStrategy.targetAudience` 保持摘要兼容，新界面优先展示分组，而不是把多个群体挤进一个长字符串。

卖点、痛点继续保留独立字段和事实 ID。卖点需要说明“这个特征对买家有什么用”；痛点需要描述购买前或实际使用中的具体阻碍，不把所有痛点都写成“规格不清楚”。推断的需求和创意表达与已知商品性能分开，参考图中真实可读的功能、参数与配件继续可用。

空卖点、空痛点、空受众分组明确显示缺口或重新识别提示，不能整栏消失，也不能把平台默认文案伪装成分析完成。

### 2. 新开关与数量口径

“AI 整套营销提示词”按用户确认默认开启，记住用户上次选择。关闭时保留现有规划方式与数量口径；开启时普通营销轮播支持 1–20 张，0 张继续表示当前独立追加任务，不触发空的 AI 规划请求。

20 指普通营销图片数，SKU 与源图重构仍按当前界面分别计数。开启后可选 19/20，关闭时若草稿选择超过模板容量，明确提示并同步回有效数量；不改写已经排队或保存的冻结计划。

用户对具体图型或单图提示词的手动选择是规划约束。AI 可以在同一已知图型下生成多个不同的营销任务，例如不同用途的场景或不同结构的细节；每项 ID 唯一，任务和画面必须有区别，不把同一句话换词当作新图。

### 3. 一次请求统筹整套 N 条

开关开启时，规划器接收当前商品资料、有效分析、参考图及稳定编号、目标语言、张数、平台和视觉风格，以及用户锁定的图型/提示词。

已有有效分析作为本次规划依据；没有有效分析时，同一次整套请求按现有识别结构返回商品分析与参考用途，同时给出 N 个图片条目，不另发逐图识别请求。这样正常成功路径仅发一次整套请求。一个完整规划可以因网络或协议错误而整体失败或重试，但不得退化为 N 次逐条规划。

每个普通营销图片条目至少包含：

- 稳定 `itemId`、受支持的 `imageType`/`role` 和中文标题；
- 一个清楚的 `marketingGoal`，说明本图要促成什么购买判断；
- 采用的受众、卖点、痛点、营销建议与事实 ID；
- 使用哪些参考图，以及主体、细节、功能或场景等使用目的；
- 可直接用于生图的完整 `prompt`，包含构图、景别、真实动作、光线/色调、信息层级与必要画布文案。

分析及预览摘要使用中文，最终提示词和新加画布文案遵循目标语言。AI 已输出并校验的最终提示词不再被原有固定模板或逐段翻译重新改写。商品实体上已有的文字与标识继续按当前保真规则处理。

这是一轮返回 N 条的普通模型请求，不使用耗时更长的异步 Batch 作业，也不意味着一个图片请求同时生成全部 N 张图片。出图仍按当前任务并发规则运行。

### 4. 专家提示词的核心职责

以下为实施时系统指令的核心内容，具体结构由字段 schema 配合：

> 你是一名电商视觉营销专家，同时承担整套商品图片的视觉策划与转化文案职责。你的目标是帮助买家快速认出商品、理解与自己相关的价值、获得可信证据并降低购买犹豫。
>
> 根据当前商品资料、已确认的卖点/痛点、具体受众分组和参考图，在一次回答中规划完整的 N 张图片，并一次性输出全部 N 条可直接用于生图的提示词及其图片类型和参考图分配。
>
> 先统筹整套图片要覆盖哪些购买问题，再为每张图确定一个主要营销任务。图片之间可以使用同一商品事实，但必须在购买问题、使用动作、证据表达或画面形式上有明确区别。不要把同一摆拍换背景或改文案当作新的内容。
>
> 将商品特点转化为买家能够理解的价值，用具体构图、镜头、真实动作、可见细节和简洁文案表达。每条提示词应描述最终要生成的图片，而不是泛泛写“突出卖点”“高级质感”“提高转化”。
>
> 每条都说明适合谁、回应什么需求或顾虑、展示什么商品依据、使用哪些参考图以及画面文字如何排版。严格商品展示图可以通过比例、质感和证据体现价值，不强行添加人物或大字。
>
> 使用已提供的功能、规格与配件，不凭空增加；主主体外观保持一致。资料不足时明确缺口，不能为了填满 N 条发明性能。只输出约定的结构化完整结果，不给占位条目。

### 5. 服务器验证与参考分配

使用严格结构化输出时仍执行服务端语义校验，不假设兼容上游总能正确执行 schema。至少检查：条目数与 N 一致，ID 唯一，提示词非空，类型可用，引用的受众/事实/卖点/痛点/建议存在，参考图编号属于当前上传，主主体绑定有效，角色与参考用途不冲突。

AI 模式的条目不经过固定 18 槽裁剪。同类图型可以出现多张独立任务；现有平台硬规则、用户手动锁定和生成前资料校验继续生效。参考图选择必须真正进入逐项请求，不能只在提示词中写“参考图 2”却仍发送全部参考图或错误编号。

若现有逐图参考预算不能容纳必需证据，规划需调整分工或提示资料问题。数量不齐、引用错误、整体结果无效时不提交图片生成，不静默替换为模板内容；用户可以整体重新规划或主动关闭开关。

### 6. 预览、冻结与复用

预览可以展开查看每张的类型、受众/核心营销点、参考图缩略图和完整提示词。生成采用预览中同一份已校验计划。无预览时先完成一次整套规划，再启动图片请求。

生成队列、保存记录和补图保留规划模式、输入指纹、规划模型/时间，以及逐图任务、引用和最终提示词；不保存凭据。已有有效预览、普通重试与补图不重新请求提示词。用户主动“重新规划”才生成新整套方案。

商品资料、参考图内容或用途、目标语言、张数、平台、视觉风格、分析结果、图型锁定或开关改变后，新草稿计划失效。旧的异步结果不能覆盖新输入；已有排队和历史记录继续使用各自冻结数据。

## Verification

- 分析契约：示例商品能展示多个具体受众分组，卖点/痛点与有效事实绑定；旧结果可读，空字段有明确说明。
- 批量调用：选择 20 时正常路径只发生一次规划请求，并得到 20 个完整且唯一的条目；数量不得被压回 18。
- 语义校验：缺条、多条、重复 ID、空提示词、非法图型、失效事实和未知参考图均被拒绝；不会发出图片请求。
- 映射执行：本地模拟上游逐项核对最终提示词、参考图字节/编号和类型，确认 UI 分配与实际请求相符。
- 生命周期：预览后生成不再次规划，队列/保存/补图维持相同内容，资料变化不会应用旧结果。
- 关闭路径：原有模板、SKU、重构、手动提示词和平台规则保持预期行为，用户显式选择的模式有可辨识状态。
- 界面：开关、19/20 张选项、分析分组和逐图预览可复核，中文无乱码；完成后运行相关测试、同步检查及 OpenSpec 严格校验和归档。
