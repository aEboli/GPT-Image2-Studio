## Context

当前平台 V1 提示词只把标题建议长度视为软目标，真实响应接纳逻辑也只检查结构、风险声明与证据可追溯性。确定性摩托车护目镜回退虽然已有八项可追溯别名，却只取前两项标题属性，因此完整证据集生成的英文标题只有 72 个字符。

## Goals / Non-Goals

**Goals:**

- 在平台硬上限允许且来源至少提供六个去重的本地化证据别名时，将 120 个英文字符作为真实响应的明确接纳下限。
- 保留现有标题核心，在其后加入不同的结构、佩戴与场景事实。
- 让完整摩托车护目镜回退达到 120–200 个字符，并保持中英文事实顺序一致。
- 保持稀疏证据与低平台上限优先，禁止为补长度虚构或重复。

**Non-Goals:**

- 修改平台 policy 注册表、官方来源或字段硬上限。
- 对证据稀疏商品强制补齐 120 个字符。
- 修改卖点、痛点、五点描述、详情或搜索词逻辑。
- 迁移或重写历史 Listing；只有重新生成才使用新规则。

## Decisions

### 1. 120 是有条件的接纳下限

新增平台 V1 标题下限常量。仅当标题硬字符和 UTF-8 字节上限均未低于 120，并且来源至少有六个不同的 `listingEvidenceAliases` 时启用。该阈值让当前完整证据集进入严格路径，同时让只有商品身份和少数属性的稀疏来源继续输出较短但真实的标题。

### 2. 提示词、接纳与回退使用同一规则

提示词明确写出“至少 120”，说明这不是大约值或优化建议。真实响应结构检查接收来源和平台 policy；达到启用条件但英文标题不足 120 时，直接走现有单次确定性回退，不增加第二次模型请求。

### 3. 已有标题核心保持在前部

摩托车护目镜回退继续以数量、`Vintage Motorcycle Riding Goggles`、`180 Wide View` 和 `Anti Fog` 开头。随后按已有证据加入 `PC Lens`、`Indirect Vents`、`Adjustable Headband`、`Soft Frame` 与 `Nose Pad`；仅在参考说明明确同时提供户外、越野和骑行场景时加入对应场景短语。

### 4. 平台和证据优先于长度

平台硬上限低于 120 时不启用下限。证据别名不足时保持短标题；不会重复商品词、堆叠同义词或把尺寸、性能和未证实场景写入标题。中文标题只同步事实与顺序，不用英文字符数填充。

## Risks / Trade-offs

- [模型标题低于 120 后回退，文风可能更确定性] -> 只在证据丰富来源启用，并以真实请求验证最终输出。
- [长标题接近通用 200 字符上限] -> 保留现有标准化与 200 字符安全上限，测试固定上下界。
- [场景词从参考说明过度扩展] -> 只有明确同时出现户外、越野和骑行时生成专用别名，否则不加入该场景短语。
- [未来平台上限变化] -> 每次请求使用已解析 policy；低于 120 时自动关闭下限。

## Migration Plan

1. 增加失败测试，复现完整证据标题只有 72 个字符，并固定低上限与稀疏证据例外。
2. 修改标题提示词、真实响应接纳条件、场景证据别名和护目镜回退标题属性。
3. 运行聚焦测试、串行全量测试、公共模块同步检查、Pages 构建与 OpenSpec strict 校验。
4. 重启本地 3600 服务，对现有记录发起真实 Listing 请求并检查最终英文标题长度与页面显示。
5. 回滚时删除本次下限接纳规则与新增标题属性；无需迁移已有记录。
