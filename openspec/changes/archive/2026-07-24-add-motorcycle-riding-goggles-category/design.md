## Context

Creation Mode 使用静态四级类目表构建选择器、搜索索引和提示词策略，并通过 `findCreationIndustryTemplateMatch` 将参考分析文本映射到唯一类目。当前表中摩托装备只有头盔、骑行服、护具和骑行手套；商品名“复古摩托车骑行风镜”无法命中真实类目，在旧自动类目被正确清除后只能回落到通用电商。

“护目镜”也可能指工业个人防护用品，因此不能把该词单独作为摩托类目的直接别名。现有类目代码按层级和顺序稳定排序，新项应追加在摩托装备现有四项之后，不改动已有代码。

## Goals / Non-Goals

**Goals:**

- 为摩托车骑行护目镜提供稳定、可搜索的四级类目代码和完整路径。
- 让明确的摩托骑行风镜/护目镜文本自动命中该类目。
- 保持宽泛“护目镜”文本不自动分类，避免与工业防护眼镜混淆。
- 修正当前受影响记录的可变顶层类目，同时保留冻结生成事实。

**Non-Goals:**

- 不建立通用同义词或模糊语义分类框架。
- 不重新分类全部历史套图，也不重写已生成图片、逐图提示词或冻结计划。
- 不改变旧自动类目失效后回落到通用电商的安全行为。

## Decisions

### 追加稳定的四级类目行

新增 `C10-006-001-005`，路径为 `汽车摩托 > 摩托车用品 > 摩托装备 > 骑行护目镜`。采用现有相邻编码而不是复用“护具”或工业“防护眼镜”，因为 UI 和后续计划需要显示真实、可区分的商品类目名称。

### 使用窄范围组合别名

自动匹配仅在文本同时满足两个词组时返回新类目：一组是 `摩托车`、`摩托`、`机车`、`骑行`，另一组是 `护目镜`、`风镜`。组合规则作为新类目的显式别名判断，先于通用直接匹配运行；不把别名并入所有类目的搜索文本，以免放宽现有歧义保护。

### 搜索与自动匹配使用不同边界

用户在类目选择器中可直接搜索正式名称“骑行护目镜”、完整路径或代码；自动分析文本则额外接受“骑行风镜”等自然商品名。单独“护目镜”不自动命中，但用户仍可手工搜索并选择正式类目。

### 仅迁移记录顶层当前类目

把受影响记录的当前 `industryTemplate`、类目名称/路径和相关顶层规划摘要修正为新代码；已经冻结并用于生成的逐图 prompt 保持原样，避免伪造生成时事实。修正字段记录原值、原因和时间，便于审计。

## Risks / Trade-offs

- [“骑行风镜”可能指自行车用品] -> 必须同时存在摩托车或机车词，或者由明确商品名中的“摩托车”提供语境；仅有“骑行 + 风镜”不作为摩托类目自动匹配。
- [新增类目导致依赖固定总数的测试漂移] -> 将断言从 1577 更新为 1578，并验证代码唯一、路径和搜索结果。
- [历史冻结提示词仍含旧类目] -> 顶层显示真实当前类目，并保留旧 prompt 作为历史审计证据，不假装生成过程使用了新类目。

## Migration Plan

1. 添加类目行和自动匹配回归测试，再实现窄组合别名。
2. 同步 `lib` 到 `public/lib` 并运行同步检查。
3. 备份并原子写回当前受影响记录，仅更新允许迁移的顶层字段。
4. 验证定向测试、完整测试和 OpenSpec 后归档变更；回滚时恢复记录备份并删除新增类目行及规则。
