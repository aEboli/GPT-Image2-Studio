## Context

`confirmCreationRecordDelete()` 在 `POST /api/creation/sets/delete` 成功后已经从 `state.creation.sets`、勾选 ID、Creation 队列和当前工作集移除请求中的套图，并关闭相关灯箱。随后它仍无条件执行 `await loadCreationSets()`；该函数会进入资产加载态、请求全部 manifest、重建 `state.creation.sets` 并再次渲染记录列表和详情。

Local 与 Cloudflare 删除路由都把成功响应定义为已完整处理提交的去重 `setIds`：Local 将每个 ID 分类到 `deletedSetIds` 或 `notFoundSetIds`，Cloudflare 将当前会话 ID 作为幂等删除返回。因此成功路径不需要第二次读取才能知道哪些已提交记录应从当前浏览器视图消失。

## Goals / Non-Goals

**Goals:**

- 删除成功后不触发自动 `GET /api/creation/sets` 或资产加载态。
- 在一次最终渲染中更新总数、筛选计数、列表、详情、勾选和删除按钮状态。
- 当前详情未删除时保持不变；删除时选择当前筛选顺序中的相邻记录。
- 保留搜索、时间筛选和列表滚动上下文，支持连续整理记录。
- 保持删除失败不修改当前记录集合。

**Non-Goals:**

- 改变删除 API、存储安全、批量上限或永久删除语义。
- 增加撤销、回收站、自动后台刷新或跨窗口实时同步。
- 改变 Creation 生成、修复、Listing 或其他资产记录页。

## Decisions

### 1. 成功删除响应作为当前操作的提交确认

只有 `response.ok` 后才修改浏览器记录状态。成功响应表示提交的每个规范化 ID 已被删除或本来就不存在，前端据此移除本次不可变目标快照。请求失败、响应非 2xx 或 JSON 错误不会提前修改列表。

### 2. 不在成功路径自动调用 `loadCreationSets()`

删除后直接提交本地状态并最终渲染一次。手动“刷新”仍明确调用 `loadCreationSets()`，用于用户主动同步其他窗口、外部脚本或手工文件修改。这样把本次操作确认与全局重新同步分开。

### 3. 用删除前筛选顺序决定相邻详情

删除请求前记录当前完整筛选集合和当前详情 ID。纯函数按以下顺序解析删除后的详情：

1. 当前 ID 未删除且仍在筛选集合中时保持当前选择；
2. 当前 ID 被删除时选择它之后第一个未删除记录；
3. 没有下一条时选择之前最近的未删除记录；
4. 当前筛选没有剩余记录时返回空选择。

该规则不依赖最多 60 条的 DOM 渲染限制，并同时适用于删除当前、删除选中和删除筛选结果。

### 4. 依赖稳定列表容器保留滚动位置

记录列表只替换同一滚动容器中的子项，不替换容器本身。移除自动加载态后，浏览器会保留现有 `scrollTop` 或移动端 `scrollLeft`，仅在内容缩短到不足原偏移时自然收敛到可用范围，不增加额外滚动状态。

## Risks / Trade-offs

- [其他窗口同时修改记录] -> 当前删除只保证本次目标正确；用户可通过现有“刷新”显式同步全部记录。
- [当前记录位于列表末尾] -> 没有下一条时回退到上一条，避免跳回列表第一项。
- [筛选删除后没有匹配项] -> 保留筛选条件并展示零结果，用户可清空筛选或继续调整条件。
- [成功响应后本地状态提交异常] -> 纯函数只处理 ID 与数组，不执行副作用；最终渲染从更新后的单一状态派生。

## Migration Plan

1. 增加相邻选择和禁止成功后自动重载的失败测试。
2. 实现纯函数并同步 `public/lib`，再收紧 `confirmCreationRecordDelete()` 的成功路径。
3. 运行聚焦测试、完整测试、public-lib 同步、Pages 构建与 OpenSpec strict validation。
4. 使用隔离套图记录验证删除请求后没有列表 GET、筛选与滚动保留、相邻详情正确。
5. 回滚时恢复成功后的 `loadCreationSets()`；API 和存储无需迁移。
