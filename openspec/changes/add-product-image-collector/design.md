## Context

Creation 当前通过 `applyCreationReferenceFiles()` 把浏览器 `File` 对象写入独立参考图状态，页面级 `paste` 处理也已经能识别剪贴板中的图片文件。现有前端、Local 和 Worker 均把 Creation 参考图限制为 15 张，分析结构和测试也依赖这个边界。

浏览器扩展需要处理的商品页可能一次暴露数十张图片。系统剪贴板在 Windows 上不能可靠保存多个原生图片项，而图片 CDN 网址又可能受 CORS、重定向或热链策略影响。因此扩展与 Studio 之间使用小型版本化文本清单，图片二进制由本地服务在用户确认后逐张获取。扩展下载路径继续使用 Chrome `downloads` API，只能定位到默认下载目录下的相对子目录。

## Goals / Non-Goals

**Goals:**

- 在 Creation 中提供可发现的一键剪贴板导入入口，并复用现有参考图业务状态。
- 对 1688 当前商品详情页执行高准确率优先的商品图采集，按主图、详情图和 SKU 图分组。
- 让扩展复制大量候选图时不受多图片系统剪贴板限制，并在 Studio 中保留显式选择和上限反馈。
- 让下载的全部选中图片位于同一个按日期和商品分层的文件夹中，并使用可读的中文类别与 SKU 规格文件名。
- 限制扩展权限和本地代理网络边界，避免任意页面扫描、认证数据外流和 SSRF。
- 让扩展源码可测试、可打包，并随桌面安装包持续分发。

**Non-Goals:**

- 第一版不支持淘宝、天猫、Temu、Amazon 或任意通用网页采集。
- 不使用视觉模型猜测任意网页中的商品图，不承诺对未知 1688 页面结构静默降级。
- 不提高 Creation 参考图或上游生成请求的 15 张限制。
- 不读取浏览器 Cookie、请求头、账号资料或绕过登录和反爬限制。
- 不在本 change 中发布 Chrome Web Store 商品、配置企业强制安装或实现静默安装。
- 不建立 Native Messaging、预加载脚本、通用 Electron IPC 或固定本地端口。

## Decisions

### 1. 使用版本化文本清单，而不是复制多张图片二进制

扩展将 `GPT_IMAGE2_STUDIO_PRODUCT_IMAGES_V1` 作为第一行魔术标识，第二部分为 JSON。清单包含 `version`、`source`、`product`、`capturedAt` 和有序 `items`；每个条目只保存稳定 ID、类别、顺序、HTTPS 图片地址、建议文件名、尺寸和置信度。

Studio 按用户点击读取 `navigator.clipboard.readText()`。若文本不是受支持清单，再尝试 `navigator.clipboard.read()` 获取原生图片项，并继续调用现有文件导入函数。清单解析必须限制总字节数、条目数、字段长度、协议和类别，不能把任意剪贴板 JSON 当作网络请求。

该方案兼容只支持一个系统剪贴板项的 Windows 环境，也使来源和分组不会在复制过程中丢失。复制 Base64 图片会让几十张图片形成巨大剪贴板负载，因此不采用。

### 2. 超量清单进入批次预览，生成参考图上限保持不变

清单解析成功后，Studio 根据当前剩余槽位预选候选项。选择优先级为主图、SKU 图、详情图，在同类别中保留采集顺序；已存在或失败条目不占用最终槽位。用户可以在批次预览中修改选择，但可选数量不得超过剩余槽位。

点击“导入所选”后才逐张获取图片。结束反馈分别报告已导入、重复、失败和未选择数量。这样可接收一个完整采集批次，同时不静默丢弃 15 张以外的素材，也不扩大上游请求体和分析模式。

### 3. 本地代理只允许受支持商品来源和可信图片主机

Local 新增单图代理端点，接收规范化的清单来源和单个图片条目。它只允许 HTTPS、受支持的 1688 商品页主机以及明确的阿里图片 CDN 后缀；每次重定向都重新验证，最多跟随 3 次。响应必须是 `image/*`，单图最多 20 MiB，并使用超时和流式字节上限终止异常响应。

端点不接收 Cookie、Authorization、Referer 或调用方自定义请求头。云端运行时返回结构化不支持信息。由于允许主机是固定后缀而不是任意 DNS 名称，本地服务不会成为内网地址或任意公网 URL 代理。

### 4. 使用受限悬浮入口、Manifest V3 action 和 `activeTab` 注入采集窗

扩展声明 `activeTab`、`scripting`、`downloads` 和 `clipboardWrite`，并只在 `https://detail.1688.com/offer/*` 注册一个 `document_idle` 内容脚本。该脚本仅创建悬浮入口并发送打开消息，不查询商品 DOM、不读取图片、不发起详情请求，也不自动采集。点击入口后，后台使用消息发送方的 `sender.tab.id` 注入采集窗；点击扩展 action 时，后台直接使用点击事件携带的标签页补充注入入口和采集窗，不通过 `chrome.tabs.query()` 猜测活动页。

采集窗通过消息发送方的 `sender.tab.id` 请求采集，并同时提交自身 `location.href` 供后台预检；采集器仍使用页面真实地址二次校验。因此即使 Chrome 隐藏 Tab 的 `url` 字段，也不会在已授权商品页上提前误报不支持。采集窗打开和关闭时发送不含页面数据的 DOM 状态事件，让悬浮入口在面板存在时隐藏、关闭后恢复。

悬浮入口和采集窗分别使用 Shadow DOM 隔离 1688 页面样式。采集窗支持拖动；释放到左右边缘阈值内时自动贴边并隐藏，只保留固定宽度的展开把手。移入或点击把手后展开，离开已贴边窗口后再次收起。扩展不使用 `<all_urls>`、`tabs` 或 `sidePanel` 权限，也不扫描浏览历史；自动内容脚本的主机、路径和脚本文件必须精确匹配上述入口边界。

采集函数优先从 1688 页面内联商品状态中解析 `gallery.fields.mainImage`、`skuProps` 和 `description.fields.detailUrl`。`mainImage` 是主图权威集合，避免把 `offerImgList` 中重复追加的 SKU 图片误归为主图；SKU 按规范化图片 URL 合并，但在条目中保留所有对应规格名称；详情描述只允许无凭据请求受限的公开 `itemcdn.tmall.com/1688offer/` 端点，并从 `offer_details.content` 中按顺序读取图片。详情请求设置超时和响应大小上限，失败时仍返回已经确认的主图与 SKU 图。

页面没有这些声明数据时，采集函数才查询版本控制的 1688 商品图库、详情内容和 SKU 区域选择器，并对候选节点执行祖先排除、协议、尺寸、文件类型和 URL 去重检查。推荐、评价、头像、店铺、导航、Logo、广告、服务浮层、视频封面和占位资源均不进入默认结果。若结构化数据与已知区域都没有结果，界面显示未找到，而不是扫描整页兜底。

### 5. 下载使用日期父目录、一个商品文件夹和中文确定性文件名

扩展把选中图片依次下载到 `GPT-Image2-Studio/<YYMMDD>/<商品ID-标题>/`，日期使用浏览器本地日期，例如 2026-07-27 为 `260727`。主图和详情图按各自分组顺序命名为 `主图-1.jpg`、`详情图-1.jpg`；SKU 图命名为 `SKU-1-<规格名>.jpg`，同一图片覆盖多个规格时连接已保留的规格名并执行 Windows 非法字符清理和总长度限制。已知原扩展名继续保留。

下载使用 `conflictAction: "uniquify"`，只提交用户选中的图片，不创建或下载 `manifest.json`、数据 URL 或其他辅助文件。来源与全部 SKU 映射仍保留在用户主动执行“复制到 Studio”时生成的版本化文本清单中。

不使用 `saveAs`，避免每张图片重复弹出选择器。第一版不承诺选择默认下载目录之外的任意文件夹。

### 6. 本地端点按需生成扩展 ZIP，商店安装作为后续分发步骤

扩展源码保存在 `extensions/product-image-collector/`，共享清单协议从 `lib/` 在打包时复制到 ZIP。Local 下载端点使用已存在的 `jszip` 生产依赖按需生成并缓存 ZIP。桌面构建白名单包含扩展源码，但不包含 `artifacts/` 或已生成 ZIP。

工具菜单入口下载 ZIP，并提供明确完成反馈。Chrome 在 Windows 上仍要求用户解压并通过扩展管理页加载，或未来从 Chrome Web Store 确认安装；应用不得使用注册表、本地 CRX 或外部协议绕过该确认。商店商品创建后，可以在独立 change 中把同一入口切换为精确允许的商店 HTTPS 地址。

## Risks / Trade-offs

- [1688 更新 DOM 后采集数量下降] -> 选择器集中维护并用代表性 HTML fixture 回归；失败关闭而不是扩大到全页扫描。
- [公开详情描述端点变更或超时] -> 仅访问页面声明且主机/路径受限的无凭据端点，限制响应大小和等待时间；失败时保留主图与 SKU 图并显示部分结果提示。
- [公开 CDN 图片仍可能拒绝本地服务] -> 对每张失败项单独反馈，并保留扩展“下载全部”作为文件导入回退，不携带用户认证数据重试。
- [大量候选图使批次弹层拥挤] -> 使用分组、固定比例元数据预览块、内部滚动和响应式列数；为遵守确认前不请求远程图片的边界，Studio 弹层不直接加载 CDN 缩略图。
- [用户误以为 ZIP 已自动安装] -> 菜单文案使用“下载插件”，包内包含中文安装说明，完成反馈不声称安装成功。
- [扩展权限过宽] -> 自动内容脚本精确限制为 1688 商品详情路径且只能显示入口；采集继续使用 `activeTab`、消息发送标签页和按需脚本，下载只由明确用户动作触发。
- [持久侧边栏丢失活动页 URL 可见性] -> 不在面板中调用 `chrome.tabs.query()`；action 负责注入，悬浮窗通过 `sender.tab` 让后台采集当前授权页。
- [本地代理内存占用] -> 单图请求、20 MiB 硬上限、超时和有限并发，不返回包含多张图片的 Base64 JSON。

## Migration Plan

1. 添加纯协议/选择模块及失败测试，固定清单、上限、主机和文件名行为。
2. 增加 Creation 按钮、批次弹层和 Local 单图代理，验证原生图片粘贴与现有上传行为不变。
3. 增加 1688 扩展、页内悬浮窗、复制和下载，并用 fixture 验证非商品区域排除和分组顺序。
4. 增加扩展 ZIP 下载端点、工具菜单入口和桌面打包白名单。
5. 运行聚焦测试、public/lib 同步、全量测试、扩展构建、OpenSpec 严格校验及桌面/浏览器可视验收。
