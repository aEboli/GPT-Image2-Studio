# Design: Listing 组合规格块

## Context

尺寸和重量已经分别使用 `packageDimensions`、`packageWeight`、`productDimensions`、`productWeight` 保存。问题只存在于展示层：当前顺序先列两个尺寸，再列两个重量，无法快速核对同一对象的完整规格。

## Decisions

### Decision 1: 组合展示，不合并数据

页面渲染两个规格块。包装块包含“尺寸”和“重量”两行，产品块使用相同结构。底层草稿、历史回读和 API 响应继续保留四个字段。

### Decision 2: 尺寸永远在重量之前

页面、行级复制目标和“复制全部”均固定先输出尺寸，再输出重量。英文与中文仍可分别复制，且不会互相混入。

### Decision 3: 结构化导出保持可解析

结构化 JSON 不新增拼接字段。V2 规范化导出将包装的尺寸与重量相邻输出，再输出产品的尺寸与重量；历史 V1 导出继续保持原对象内容不变。

## Risks

- 组合块复用现有带标签行渲染，需确认字段级复制、行级复制和字符计数仍覆盖两个值。
- 浏览器静态镜像必须同步，否则本地服务可能继续展示旧的四段布局。
