# 设计：图片软显现

## 成功标准

1. 新生成的主结果图在浏览器完成解码后，以约 300ms 的柔和聚焦出现；生成中的加载壳在图片就绪前继续显示。
2. 同一 URL 的轮询或重渲染不会让已显示的主预览再次闪回到模糊状态。
3. 灯箱首次打开和在一组图片中切换时均使用同一显现机制，缩放、拖拽、适配与键盘导航保持正确。
4. 减少动态效果偏好下，图片在解码后直接显示为清晰状态。

## 决策

### 共享解码后工具

新增 `setImageRevealSource(image, source, options)`，统一写入图片地址、管理一次性 `load`/`error` 监听，并在 `HTMLImageElement.decode()` 可用时等待它完成。等待后在下一绘制帧把图片从 pending 状态切到 revealed 状态。缓存命中和普通网络加载都走同一条路径，因此不会因 `complete` 时序不同而一处跳帧、一处过渡。

工具将当前 source 记录在图片节点上。调用点可以安全地在每次 render 中调用它：source 没变时保持已显现状态；source 改变才重新进入 pending。清空预览时由 `clearImageReveal()` 清理监听、状态类和旧地址，避免已失焦的图片迟到后覆盖当前预览。

### 不干预现有几何变换

主预览的缩放和灯箱的缩放/拖拽均使用 `transform`。软显现使用 CSS 独立 `scale` 属性而不是重写 `transform`，所以不会覆盖主预览的缩放比例或灯箱的平移、适配与检查模式变换。模糊只加在实际 `img` 上，不会模糊文字、工具栏或整个卡片。

### 视觉参数和可访问性

默认由 `opacity: 0`、`blur(10px)`、`scale: 1.03` 过渡到清晰、原始比例。缓动使用接近参考视频的快速进入、柔和收尾曲线，时长控制在 280-320ms。图片容器保留既有尺寸和占位，避免布局跳动。

减少动态效果时，工具仍等待图片可用并更新可见状态，但样式关闭过渡、模糊和缩放。图片加载本身不写入新的 live region，避免批量切图时产生重复播报。

## 验证策略

- 单元测试覆盖新 source 进入 pending、解码后才 revealed、同 source 不重播、换 source 时旧监听无效、清空和错误不残留状态。
- 静态入口测试覆盖五个主生成预览和灯箱均调用共享工具，且主预览不再在写入 `src` 的同一轮直接可见。
- 样式测试覆盖轻微模糊、独立 scale、reduced motion 和灯箱不重写其现有 `transform`。
- 运行定向测试、公共模块同步校验、OpenSpec 严格校验和本地浏览器截图检查。
