## Context

颜色识别器会先选择互不重叠的可靠颜色 token，再把一个产品单位内的多个颜色合并为标签。当前字符清理会删除所有非字母和数字，因此无法区分 `off-white` 内部的词法连字符与 `brown-black` 中连接两个独立颜色的分隔连字符。

## Goals / Non-Goals

**Goals:**

- 保留同一个已识别复合颜色 token 内部、位于字母或数字之间的单个连字符。
- 删除颜色 token 边界之间的连字符以及逗号、引号、斜杠、括号等其他标点。
- 保持不同颜色以单个空格连接，并保持分组顺序和重复项。

**Non-Goals:**

- 不扩展颜色词表或改变颜色证据来源。
- 不允许任意用户文本中的连字符绕过纯颜色过滤。
- 不改变 SKU 数量、分组或生成版式。

## Decisions

### Decision 1: 只在已选颜色 token 内保留内部连字符

颜色片段仍先经过现有词表和重叠选择。对每个已选片段，仅保留位于 Unicode 字母或数字之间的连字符，并把连续连字符压缩为一个；其余字符转换为空格。因为 `off-white` 会被选为一个完整 token，所以连字符保留；`brown-black` 会被选为 `brown` 和 `black` 两个 token，再由空格连接，所以中间连字符不会保留。

### Decision 2: 提示契约显式区分内部连字符和分隔符

参考分析和最终生成提示允许 `off-white` 这类复合颜色内部连字符，同时明确不同颜色只能用空格分隔，其他标点仍禁止。准确标签继续单独成行且不使用引号或列表符号包裹。

## Risks / Trade-offs

- 输入中使用连字符拼写的其他已识别多词颜色也会保留其内部连字符；这是对“颜色名称本身的一部分”规则的一致应用。
- 未识别词仍会被删除，不能仅凭连字符格式成为可见标签。

## Migration Plan

1. 添加保留复合颜色连字符和删除分隔连字符的失败回归。
2. 修改共享归一化和提示契约，保持其他规则不变。
3. 同步浏览器镜像，运行聚焦、全量、构建和严格 OpenSpec 验证。
4. 归档变更并合并主规格。
