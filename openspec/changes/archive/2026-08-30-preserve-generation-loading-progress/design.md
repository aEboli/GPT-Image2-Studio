## Context

共享加载源目前在最后一个 `.generation-loading-shell` 停止时立即删除。套图队列按 `itemId` 复用卡片 DOM、按 `queueId::itemId` 隔离进度 key；因此从队列 A 切到 B 时，A 的加载源会在仍运行的情况下被误判为终结。其他视图的重渲染已经通过先挂载替代壳、再停止旧壳来避免短暂断开，但队列切换没有两个 key 同时挂载。

## Goals / Non-Goals

**Goals:**

- 将临时失焦的运行任务与真正结束的任务区分开。
- 让队列 A -> B -> A 恢复 A 的百分比、计时节奏和保存的心跳图标状态，且 B 仍从 `0%` 开始。
- 保留完成或失败后释放共享源的语义。

**Non-Goals:**

- 不将估算进度持久化到刷新后的浏览器会话。
- 不改变服务端任务调度、实际生成进度或现有百分比时间曲线。
- 不重构各生成模式的 UI 渲染器。

## Decisions

### 保留源是显式的，而不是零节点时永久缓存

`stopGenerationLoadingShell` 增加内部 `retainSource` 选项。只有因界面/队列切换而替换运行任务的 key 时才传入该选项；保留源即使暂时没有 DOM 壳，也继续按原节奏推进。普通停止仍立即清理 source，因此同 key 的下一次独立任务从 `0%` 开始。

备选方案是让所有零节点 source 永久存活。它会使终态任务在长会话中无界累积，并且无法区分“暂时隐藏”和“真正完成”。

### 以队列运行结束作为套图进度源的终结信号

新增按 key 前缀释放 source 的 API。套图队列任务在 `runCreationQueuedJob` 的 `finally` 中通知调用方释放 `${queueId}::` 与当前 `setId::` 下的所有源，覆盖成功、失败和自动补图后的结束路径；手动补图和历史记录补图也在各自的 `finally` 中释放同一组作用域。该清理不依赖当前是否选中该队列。

备选方案是在每个流事件中逐项释放。它能更早释放单项，但会扩大事件分支且漏掉异常终结路径的风险更高；队列 `finally` 是单一、可靠的终态边界。

### 维持现有 DOM 与图标所有权

在同一张卡上切换 key 时只从旧 source 脱离并保留它，不销毁仍会立即用于新 key 的 shell。source 保存当前心跳图标索引，重新挂载时继续使用已有的共享状态；真正停止时才销毁图标实例。

## Risks / Trade-offs

- [保留的隐藏任务仍会占用一个计时器] -> 仅对显式保留的仍运行队列生效；队列最终结束时按前缀释放，且到 `99%` 后不再调度。
- [终态回调未执行] -> source 至少在 `99%` 后停止调度；回归测试覆盖成功和失败都进入队列 `finally` 的清理边界。
- [相同 itemId 的不同队列串用进度] -> 继续使用既有 `${queueId}::${itemId}` 命名空间，并断言 B 不继承 A。

## Migration Plan

1. 增加 source 的保留与显式释放能力。
2. 将套图卡片的跨队列 key 切换标记为临时脱离，并在队列结束时释放前缀。
3. 通过 fake timer 验证恢复、独立起点和终态释放。
4. 同步 `public/lib` 浏览器镜像；若需回滚，移除保留选项及队列结束回调即可恢复旧行为。
