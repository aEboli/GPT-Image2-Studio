## Why

直连生图渠道可能使用自定义模型名称，例如 `IMAGE-2.6`，与工作台或其他渠道的模型 ID 不同。用户需要在「流式输出」下方配置可见的模型映射，以便继续选择原模型，并在请求时发送渠道接受的名称。

用户于 2026-11-05 回复“确认”批准实施。现已完成直连生图映射、配置往返、胶囊界面和出站模型替换；具体验证结果与全量回归的独立剩余问题见 `verification.md`。

## What Changes

- 在 GPT 直连配置的「流式输出」下方增加「生图模型映射」，每行使用两个可编辑胶囊输入框和右箭头：`当前模型 → 请求模型`。
- 支持添加、删除多条规则；两端均可手动填写名称或 ID，也可选择候选项。复用直连生图的「获取模型列表」，一次获取同时更新原生图模型输入框和映射候选，不根据名称自动猜配关系。
- 左侧代表现有生图模型选择，右侧代表向当前直连生图接口实际发送的模型 ID。例如 `gpt-image-2.6-sunburst → IMAGE-2.6`；如果渠道使用相反命名，也可反向填写。
- 只作用于 GPT 直连生图及其编辑请求。文本/视觉请求和其他调用通道保持现有行为。对 Responses 协议只替换生图模型字段，不替换独立文本模型。
- 保存并恢复映射，贯通浏览器私有配置、本地配置、请求载荷和已有任务快照；未匹配时保留原模型，清空映射恢复当前行为。
- 映射不改变已知模型的能力判断；明确映射到已知 ID 的自定义名称可以按该已知模型判断能力，不以包含 `2.6` 等字符串猜测未知模型能力。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `configuration-usability`：直连生图映射胶囊控件、共享模型候选及响应式布局。
- `runtime-configuration`：映射配置往返、精确单次替换、生图与文本隔离、模型能力和任务快照一致性。

## Impact

预计最小范围包括 `public/index.html`、`public/styles.css`、配置/模型选择器相关浏览器模块、`public/app.js`、共享配置与生图请求构造模块，以及对应测试和 `public/lib` 镜像。沿用现有字段与调用路径，不增加提供方框架，不改私有凭据。

## Success Criteria

1. 映射区位于指定位置，显示 `胶囊 → 胶囊`；模型列表获取后两端均可选择，未知 ID 仍可手动输入。
2. 配置保存、重新读取、JSON/FormData 请求以及队列快照均保留映射，显式空数组可删除全部映射。
3. 用本地模拟接口确认 Images 生成/编辑、Chat Completions 生图及 Responses 图像工具发送正确 ID；文本请求和其他通道不被替换。
4. 已知 2.6 模型映射为渠道别名后，原有能力与参数处理保持一致；不支持的参数仍正常校验。
5. 通过定向测试、共享模块同步检查、必要回归与 OpenSpec 严格校验；实施后确认中文编码及宽窄界面无横向溢出。
