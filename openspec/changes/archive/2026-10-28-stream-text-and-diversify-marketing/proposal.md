## Why

文本结果仍会成批出现，分析师和营销面板可读空间不足，营销图虽然文字不同但购买问题与构图重复。需要同时处理上游传输、浏览器增量显示、整套任务分工和请求触发，不能只加打字动画。

现状依据：
- `lib/prompt-agent.mjs` 的 Responses 请求已有 `stream: true`，Chat Completions 请求没有该字段且使用 JSON Accept；模型协议下的 Gemini 分支仍通过兼容网关发送非流式请求。
- 套图参考识别前后端仍以完整 JSON 交付；营销进度只提取完整顶层字段和完整任务，因此已有 SSE 时也可能一次出现大量内容。
- 两个悬浮面板共用 860px 宽度上限；营销视图每次收到进度都会重建面板内容。
- 营销规划已有文字和主体锁要求，但代码只拒绝完全相同的营销目标或提示词，没有明确的场景分工数据和语义重复诊断。
- 参考识别前端可调用四次；服务端又分别存在结构化格式回退和完整 JSON 重试。两层嵌套会放大调用量，且当前预览协调器只淘汰旧响应，没有按相同输入合并请求。
- 截图中五条日志分布在 2026-10-28 23:27:49 至 23:41:23，不能据此认定它们属于同一次操作，更不能认定系统固定并发五次。实际关联需要请求 ID 与触发原因。

## What Changes

1. 全部文本/视觉分析与文本规划调用采用流式优先的统一事件契约。覆盖 Responses、Chat Completions、现有模型协议兼容分支，以及 Listing、翻译、文章和 PPT 文本请求。图像生成协议不在此项改动内。明确提示网关缓冲或不支持流式的情况，不伪装实时输出。
2. 将上游增量一直送到浏览器：先显示安全的回答片段和正在接收的字段，再逐步更新结构化卡片；保留完整 JSON 与业务校验作为生成门槛。重试、取消和切换商品隔离旧输出。
3. 两个面板使用生图区内的大尺寸阅读浮层，默认约占可用宽度 88%、可用高度 82%，最大宽度建议 1440px；正文 14–16px、行高约 1.6，概览与逐图任务分区。移动端单列；保留互斥展开、Escape 收起和任务定位。
4. 将营销师职责明确为整套分工：商品身份与外观保持一致，场景、动作、景别、购买问题和信息形式按任务改变。明确区分允许改动的姿态/光线/环境与不可改动的产品部件、掌背面归属、标识和证据边界。白底、清单、参数图保留用途，不强行全部改成场景图。
5. 为任务增加简洁的用途/场景分工信息和重复诊断：只换背景、色调、近义标题的任务标记为重复风险；有依据的不同真实场景优先，资料不足时允许复用场景但必须改变购买问题或证据表达。诊断不擅自删图、不增加默认二次模型审查请求。
6. 正常路径无有效分析时一次完成分析与整套规划；已有有效分析时只做整套规划并复用事实 ID；有效预览提交与补图复用冻结计划。相同输入合并在途请求，结果按既有失效规则复用，单纯开关面板不触发模型。
7. 重试预算由服务端统一控制：一次逻辑文本操作最多两次上游 POST，兼容格式回退与 JSON 修复共用一次重试预算；账号/权限错误和取消不重试。识别前端不再对所有错误额外重放整套调用。
8. 展示逻辑请求 ID、用途、触发来源、实际尝试次数、重试原因与首个有效文本耗时，以定位截图中的五条调用；不记录密钥、图片 base64 或模型私密推理。

## Capabilities

### New Capabilities
- `text-model-streaming`: 文本请求的协议适配、真实增量、安全输出和统一重试预算。

### Modified Capabilities
- `creation-mode`: 大阅读面板、整套场景分工与主体适应规则、规划复用和请求可追踪性。

## Impact

- 服务端：`lib/prompt-agent.mjs`、营销规划与校验、独立文本调用模块、相关 `server.mjs` 路由。
- 浏览器：对应分析/规划入口、进度视图、计划请求协调器、`public/styles.css` 及登记的 `public/lib` 镜像。
- 验证：协议分片、提前可见性、取消、有限重试、同输入并发合并、场景分工与主体锁、桌面/窄屏布局。
- 当前阶段只提交提案、设计、增量规范和任务；等待用户确认后修改业务代码。不修改已有图片、历史记录或本次开始前的未提交实现。
