## Why

Deterministic Listing fallback copy must be at least as conservative as model output. A localized thermal-scope fallback previously treated optional reference aliases as universal facts, and a sparse generic fallback filled missing information with broad attribute groups. Both cases could publish claims not supported by the saved product record.

## What Changes

- Gate every specialized fallback phrase on the exact translated alias or structured buyer-decision evidence that supports it.
- Keep the five fallback bullets in distinct buyer-decision roles, using confirmed package quantity when it is available.
- Remove generic color, shape, dimensions, variants, and package filler when sparse input does not supply those facts.
- Resolve a trusted parent product identity before using a generic SKU subject title, so fallback copy cannot publish labels such as `1 SKU 1 SKU` when the saved parent product name is available.
- Add a localized motorcycle-goggle fallback that turns exact viewing, lens, airflow, fog, fit, option, and quantity evidence into natural buyer-facing selling points, declarative category-friction statements, and five distinct Amazon-style decision bullets.
- Gate each motorcycle-goggle detail independently, so missing aliases remove only the unsupported statement from both languages instead of triggering generic filler.
- Preserve locale-appropriate Chinese commas, semicolons, and bullet-label colons after width-insensitive forbidden-term sanitization.
- Add regression coverage for positive localized evidence, missing optional aliases, and sparse fallback data.

## Impact

- `lib/creation-listing-agent.mjs` deterministic Platform V1 fallback only.
- `test/creation-listing-agent.test.mjs` fallback regression coverage.
- No API, persistence, export schema, or historical-record migration.
