# 设计说明

## 默认值来源

lib/generation-size-options.mjs 是尺寸选项的唯一来源。普通生图路由从当前比例的选项列表取第一项具体像素尺寸；Gemini 模型协议路由固定使用 1K。浏览器和 Node 服务端都调用同一组归一化函数，避免两端对旧值的处理不同。

## 迁移边界

历史值只在表示图像分辨率的字段上迁移：size、requestedSize、effectiveSize、resolutionTier 及其对应的任务、manifest、sidecar 和缓存元数据。值等于 auto 时使用当前比例和路由决定的具体默认值；历史尺寸缺失但图片字节能推导出实测尺寸时保留实测值，否则使用路由对应的具体默认值；已有合法具体值保持不变。

文章内容类型 contentType、自动修复 autoRepair、自动折叠 autoCollapse 以及 CSS 的布局值不属于图像分辨率，不参与本迁移。

## 请求边界

所有生成入口在构造上游请求前再次归一化尺寸。GPT/Grok 请求获得具体像素尺寸，Gemini 请求获得 512、1K、2K 或 4K 中的具体档位。浏览器后台队列重试和服务端 mock 同样使用归一化后的值，因此旧任务不会在重试时重新提交 auto。

## 验证策略

- 尺寸选项测试断言所有公开选项均为具体值且历史 auto 会迁移。
- 浏览器、服务端和存储测试断言请求体、快照、manifest、sidecar 与缓存不包含分辨率 auto。
- 运行完整测试、公共模块同步检查、严格 OpenSpec 校验和差异空白检查。
