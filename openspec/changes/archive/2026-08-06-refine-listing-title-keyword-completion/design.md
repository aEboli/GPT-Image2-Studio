## Context

Platform V1 已在安全清理之后调用确定性标题补全，并从卖点、五点、痛点、描述和搜索字段收集候选。现有拆分主要依赖换行或“标点后空格”，因此连续中文正文不会稳定拆开，英文长从句也可能整句进入标题。补全必须继续使用已接受响应中的事实，不能新增模型调用或从原始输入推断新卖点。

## Goals / Non-Goals

**Goals:**

- 清理后标题低于平台目标时，从已清理的同语言字段提取标题化关键词或短语。
- 去掉五点标签、句末标点和重复标题概念，英文保持完整单词边界，中文按标点和短语长度边界处理。
- 在候选耗尽、平台硬上限或 UTF-8 字节上限处停止，不改变可用响应的完成语义。

**Non-Goals:**

- 不实现通用 NLP、词性标注或重新调用模型生成标题。
- 不把正文中的每个词都强制加入标题，不为达到长度目标编造或改写事实。
- 不修改非标题字段、历史 Listing 或模型返回结构。

## Decisions

### 1. 对已清理响应做确定性短语提取

候选仍只来自已经完成品牌、证据、阻断声明和货号清理的同语言响应。先去除五点等字段的短标签，再按换行、句号、逗号、分号、竖线和常见从句边界拆分；英文候选限制为完整单词组成的短语，中文候选限制为一段可读短语。这样不会把整段描述直接复制到标题。

备选方案是再次请求模型提取关键词，但它会增加时延、成本和失败面，并破坏“第一份可用响应不重试”的合同，因此不采用。

### 2. 以新增信息而不是候选原句判断去重

规范化标题与候选后，完全包含、完全重复或没有新增词项的候选直接跳过。候选仍保留原有词序，不从句中任意删词，以避免把否定、条件或限定语删除后改变含义。

### 3. 两层边界共同约束补全

单个候选先按标题短语边界收紧，再按剩余字符数和 UTF-8 字节数截取。英文只追加能够完整放入的单词；中文可按字符边界安全截取。达到平台建议目标后立即停止，证据丰富英文仍可使用 120 字符目标。

## Risks / Trade-offs

- [简单规则无法等同人工关键词提取] → 只做保守的标签、句子、从句和长度边界处理，保留原词序与事实限定。
- [中文没有天然空格分词] → 使用中文标点和有限短语长度，不尝试不可靠的逐词切分。
- [关键词不足导致仍然偏短] → 保留已接受标题并正常完成，不填充通用形容词。
- [短语中重新出现货号] → 每个候选和最终标题继续运行现有货号清理。

## Migration Plan

1. 添加能复现整句英文和连续中文正文被直接拼接的测试。
2. 实现标题短语提取、完整词边界截断和增强去重。
3. 运行 Listing 定向测试、共享本地/Worker 一致性测试、构建与 OpenSpec 严格验证。
4. 验证后合并规格并归档；回滚只需恢复本次函数、测试和规格，不涉及数据迁移。
