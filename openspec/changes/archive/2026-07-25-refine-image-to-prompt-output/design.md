## Context

图片转提示词与套图参考分析共用 `requestPromptAgentAnalysis`，但两者的调用目标不同。普通图片反推只需要复刻单张图片的可见画面；套图参考分析才需要平台、类目和主图/详情页/SKU 等用途判断。当前通用 `/api/prompt-agent/analyze` 处理器无条件组装套图上下文，使普通反推结果被电商用途污染。

普通反推的严格 JSON 同时要求完整 `prompt` 和主体、场景、构图、光线、色彩、镜头、备注等拆分字段。结构化字段适合审计和历史兼容，但前端又把整份 JSON保存为提示词模板，应用模板时会把完整 `prompt` 及其拆分复述一起送入主提示词框，因此用户看到并实际使用的内容都发生重复。

## Goals / Non-Goals

**Goals:**

- 普通图片反推只接收与当前图片复刻有关的指令和图片，不接收套图平台、类目或营销用途上下文。
- 让模型生成紧凑、具体、无近义堆叠的单一可生图提示词。
- 主结果、复制和模板应用都以 `json.prompt` 为唯一生图文本来源。
- 继续保存完整 JSON，并允许用户显式复制 JSON；旧记录和旧模板无需数据迁移即可使用。
- 本地服务与 Cloudflare Worker 保持一致。

**Non-Goals:**

- 不改变融图分析、套图参考分析或写真参考分析的既有结构化输出。
- 不用通用文本算法擅自删除模型输出中的词语；精炼主要通过模式专用指令约束完成。
- 不重写 `.local/prompt-agent-history.json` 或浏览器已有模板存储。
- 不改变 `/api/prompt-agent/analyze` 的成功响应结构。

## Decisions

### 1. 在路由边界隔离套图上下文

通用 Prompt Agent 处理器把 `contextPrompt` 设为空；专用 `/api/creation/reference/analyze` 路由继续组装并传入套图上下文。这样上下文归属由调用模式决定，且不需要在共享请求函数中猜测内容。

替代方案是在 `buildPromptAgentInput` 中按模式丢弃传入上下文，但这会掩盖调用方错误，也可能误伤其他模式合法的上下文，因此不采用。

### 2. 保留 JSON 契约，收紧普通反推语义

保留当前字段以兼容不同上游模型、历史记录和 JSON 复制。普通反推指令明确要求 `prompt` 只出现一次完整描述，按主体、动作/状态、环境、构图、光线/色彩、媒介/镜头、画幅的顺序组织；只保留影响像素结果的描述，禁止“精美、高级、震撼、氛围感”等无可验证作用的空泛质量词、近义词堆叠、用途建议和对字段内容的重复总结。拆分字段作为分析元数据，不得被再次拼入 `prompt`。

替代方案是删除所有拆分字段并缩小 schema，但这会破坏历史结构和下游展示兼容，变更面超过本次目标。

### 3. 将生图文本与分析 JSON 分开展示和复制

结果文本框只显示 `json.prompt`，主按钮复制提示词；另设次级“复制 JSON”按钮用于需要结构化数据的用户。历史卡片同样以单一提示词映射，并继续提供 JSON 复制。

自动保存到提示词模板的内容改为 `json.prompt`。读取模板时若内容是旧版反推 JSON，且其中有非空 `prompt`，则透明提取该字段；普通用户手写的 JSON 模板不做无条件转换，只有符合反推结果形状或反推模板 ID 时才兼容提取。

### 4. 不对历史文件做破坏性迁移

历史记录继续保存完整 JSON。旧模板在读取时做内存归一化，并在下一次正常写入模板时自然落盘为单一提示词。该策略保留回滚能力，也避免修改用户本地数据。

## Risks / Trade-offs

- [不同模型对语言约束遵循程度不同] -> 使用严格 schema 描述、明确禁止项和请求级测试共同约束；不引入可能误删关键视觉词的后处理器。
- [旧模板中的任意 JSON 被误判] -> 仅对 `prompt-agent-` 模板或包含反推分析特征字段的对象提取 `prompt`。
- [用户仍需要完整 JSON] -> 保留单独的“复制 JSON”动作和原始历史存储。
- [本地与部署版漂移] -> 对两个路由实现增加同一上下文隔离测试并运行完整 Worker 测试。

## Migration Plan

1. 先增加指令、上下文隔离、主结果与模板兼容测试并确认旧实现失败。
2. 更新共享提示词模块、本地路由、Worker 路由和前端展示。
3. 运行针对性测试、完整项目测试和 OpenSpec 严格验证。
4. 归档变更，将 `image-to-prompt` 规格合并到主规格。

回滚时可恢复代码与界面改动；历史 JSON 与模板存储格式未被批量改写，不需要反向数据迁移。

## Open Questions

- 无阻塞问题。“影响词”按用户描述和真实历史结果解释为过多且作用不明确的修饰词，并以可见画面影响作为保留边界。
