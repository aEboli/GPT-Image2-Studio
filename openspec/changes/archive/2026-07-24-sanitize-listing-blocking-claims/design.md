## Context

Platform V1 当前按“无品牌净化 -> 低风险证据词净化 -> 最小结构检查 -> 高风险声明检查”处理单次模型响应。`CLAIM_RISK_RULES` 中除 `functional-wording` 外的规则仍由最后一步作为硬失败条件；截图中的 `compatibility claim` 正是该路径。局部增加兼容性白名单会让后续认证、排名、保证等词继续重复造成同类失败，因此需要统一转换这组阻断规则。

## Goals / Non-Goals

**Goals:**

- 所有当前会产生 `content contains unsupported claim` 的 Platform V1 模式都先清理再返回，不再因关键词本身失败。
- 对 `exact-evidence` 规则保留有精确来源证据的匹配内容，只清理无证据内容。
- 直接按原多语言正则删除匹配片段，覆盖英文、中文、日文、韩文和西班牙文。
- 清理导致标题或描述为空时，使用剩余安全内容、来源商品主体或中性商品词修复最小双语主体。
- 保持一次模型请求，并让共享函数、本地服务和 Worker 使用同一行为。

**Non-Goals:**

- 不取消提示词对真实性、平台合规和高质量文案的指导。
- 不改变 V2 独立发布字段验证器、历史草稿读取或显式 mock 行为。
- 不为清理掉的兼容型号、认证、性能数字或比较结论生成替代事实。
- 不吞掉上游 HTTP、超时和 JSON 解析错误。

## Decisions

1. 复用 `CLAIM_RISK_RULES` 作为唯一模式来源。新净化器遍历与 V1 高风险检查完全相同的规则集合，并跳过本来就不参与 V1 硬失败的 `functional-wording`，避免额外删除允许的买家价值表达。
2. 对每个字段直接应用原正则，而不是先收集英文关键词再做字面替换。这样可保留正则边界、完整删除 `compatible with ...` 等多词片段，并正确处理没有英文词边界的 CJK 内容。
3. 抽取共享的旧版内容字段遍历器，统一处理标量、成对数组和四个关键词桶。低风险净化与阻断声明净化都通过该遍历器执行，空英文列表项会同步移除同索引中文项。
4. 验收顺序改为“归一化 -> 低风险净化 -> 阻断声明净化 -> 最小主体修复 -> 再净化 -> 最小结构检查 -> 声明残留断言”。最后的声明检查只作为实现不变量；使用同一规则净化后不应再产生关键词错误。
5. 最小主体修复只填 `title`、`description` 及其中文对应字段。优先使用同语言剩余公开内容，其次使用净化后的来源商品名，最后使用 `Product` / `商品`；不构造新的卖点、型号、兼容对象或性能事实。

## Risks / Trade-offs

- [删除完整兼容性或比较片段后句子可能不够自然] -> 清理相邻空格、英中标点和悬空连接词；若整个必要字段为空则使用安全主体修复。
- [宽松返回会降低部分 Listing 的信息量] -> 保留提示词规则和有精确来源证据的声明，清理只作用于原本会整单失败的内容。
- [多语言正则可能匹配较长片段] -> 直接使用已经过测试的现有规则，不扩展匹配范围，也不猜测翻译对应关系。

## Migration Plan

无需迁移历史草稿。部署后新的 Platform V1 响应会在保存前净化；回滚时移除新增净化步骤并恢复原高风险硬失败行为。
