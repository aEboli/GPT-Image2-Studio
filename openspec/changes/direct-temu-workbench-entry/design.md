# 设计：Temu 工作台直达入口

## 与 absorb-temu-listing-workbench 的关系

`absorb-temu-listing-workbench` 仍是 live change，负责把工作台、同源 iframe 覆盖层和“批量快速导出”标签并入本仓库；它当前对同一入口规定了“未勾选不打开、勾选后以 set ID 自动打开 Studio 导入”的语义。本 change 依赖其工作台承载能力，但后续覆盖该入口语义：零勾选不再是阻塞条件，已勾选记录也不再成为初始化输入。

主规范中的 `creation-mode` 当前 Requirement 名为“套图记录复用显式多选导出 Temu Excel”，因此本 change 的 `creation-mode` delta 用该名称完整替换入口行为。`temu-listing-workbench` 尚未进入主规范，故其 delta 对应覆盖 live change 中“工作台入口位于套图记录”的 Requirement。实施或归档这两个 change 时，必须先合并其共同依赖并以本 change 的入口语义为准，不能同时保留旧的自动导入场景。

## 成功标准

1. 套图记录入口显示精确文案 `temuexcel导出工作台`，且在没有勾选记录时可用。
2. 用户从该入口打开后，首先看到 Temu 工作台主界面，而不是“从 Studio 导入”对话框。
3. 无论套图记录当前勾选为零、一条还是多条，主入口都以空 set ID 集合初始化 iframe，不会改变工作台草稿或触发导入。
4. 用户切换到“批量快速导出”标签时，原有显式勾选批次仍是唯一导出目标；零勾选不发送导出请求。

## 边界与决策

本次只调整入口语义，不改变工作台的商品编辑、手动“从 Studio 导入”、草稿保存、工作簿导出或既有批量快速导出逻辑。

| 场景 | 套图记录是否需要勾选 | 初始视图 | 是否传 set ID |
| --- | --- | --- | --- |
| 点击 `temuexcel导出工作台` | 不需要 | 工作台主界面 | 空集合 |
| 已勾选后点击同一入口 | 不需要 | 工作台主界面 | 空集合 |
| 在覆盖层切换“批量快速导出” | 需要 | 既有批量导出对话框 | 仅该导出请求使用显式勾选批次 |
| 在工作台点击“从 Studio 导入” | 由工作台内用户选择 | Studio 导入对话框 | 仅由该显式导入流程处理 |

主入口保留 `#creationRecordExportTemuButton` 及既有单一点击监听归属，避免复制监听器或让标签文本、禁用状态分散到多个控制器。`syncControls` 继续负责该按钮的渲染，但按钮文案改为固定的 `temuexcel导出工作台`，禁用判据移除“有效勾选数量为零”；生成、刷新、删除、启动互斥等原有非选择安全阻塞仍然保留。

## 启动协议

当前协议将 `setIds` 放进 `temu-workbench:init`，工作台子文档只在该集合非空时调用 Studio 导入对话框。这是入口被错误地变成导入界面的直接原因。

主入口改为始终向启动器传递空集合。启动器仍用既有协议同步 `setIds`、主题和语言，但初始化消息中的 `setIds` 固定为空数组，子文档自然保持工作台主界面而不调用 `openStudioImportDialog`。这样无需改动已经验证过的工作台内部手动导入流程，也不会使旧协议的非空行为影响新的主入口。

工作台原有“从 Studio 导入”按钮继续是唯一会在本次入口流程中打开该对话框的显式用户操作。

覆盖层仍只隐藏、不卸载 iframe；因此本次不应清空工作台草稿、滚动位置或本地预览。主入口也不修改 `recordCheckedSetIds`，这样用户随后主动切换“批量快速导出”时仍可使用自己明确保留的选择。

## 批量快速导出的隔离

“批量快速导出”不是工作台初始化的一部分。用户主动点击该标签后，既有导出控制器才读取当前有效的 `recordCheckedSetIds`，并以该显式批次构建预检和导出请求。零选择时保持禁用或结构化提示，并且不向导出端点提交空批次。

这保证“打开工作台”与“导出勾选记录”各自有单一、可观察的意图：前者不受选择影响，后者不能绕过选择。

## 验证策略

- 控制器与静态测试：固定新标签、零选择仍可打开、非选择安全阻塞仍不可打开，以及只有一个入口监听。
- 启动器/控制器测试：零选择和多选择两种点击都以空 `setIds` 启动；初始化消息保持空数组，覆盖层默认选中工作台标签。
- 子文档回归测试：空 `setIds` 不会自动调用 Studio 导入；用户点击“从 Studio 导入”仍会打开原有导入对话框。
- 批量导出回归测试：切换标签后的零选择不请求导出，显式选择的 set ID 仍按现有规则进入预检与导出请求。
- 完成实现后执行相关前端/工作台测试、`npx openspec validate direct-temu-workbench-entry --strict`、`git diff --check`，并复核新增中文文本编码。
